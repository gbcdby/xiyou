# spatial-v2 高老庄客户端

对应 [ADV-001 #33](https://github.com/gbcdby/xiyou/issues/33)，复用 A1 的 [adv-protocol-v1/r2](../docs/specs/adv-protocol.md) 与已确认请求／控制恢复底座。A2 依据 [#32 正式灰盒释放](https://github.com/gbcdby/xiyou/issues/32#issuecomment-6832743262) 接入 [高老庄机器接口](../protocol/gaolao-v2.md)和[真实规则](../backend/gaolao.md)。本页说明当前实现，不代替固定候选的独立审查、整章验收或正式视觉结论。

## 入口与兼容

- 大厅的单一高老庄入口在没有 `VITE_GAOLAO_CONTENT_VERSION` 覆盖时默认创建 `gaolaozhuang-scene-v2`；显式配置值原样生效，可选择工具东侧新场景 `gaolaozhuang-tools-east-scene-v2`，也可为回归或兼容固定旧版。加入或恢复已有房间沿用其存储的内容版本，不迁移旧局；仍可明确选择行走灰盒或旧版山间通路。空间创建、加入和 Socket 认证明确携带 `spatial-v2` 能力，空间只读 HTTP 请求使用能力请求头。
- `/spatial/:sessionId` 只消费 `SnapshotV2` / `BatchV2`；`/sessions/:sessionId` 保持原 v1 驱动。房间列表能力或加入结果决定路由，新创建的旧版房间直接沿已选能力加入，不等待列表更新。
- `protocol/spatial-schema.mjs` 仍是字段唯一来源。前端使用生成类型与公开校验器，不维护第二份消息 schema，不导入服务端内容、真身、受众或知识状态。

## 状态、控制与原请求

`SpatialView` 先完整校验批次，再按完整区间原子替换投影与游标。重复、缺口、旧视图、旧连接和不匹配身份分开处理；不按事件条数猜测全局序号差。投影与渲染缓存分离，渲染不会改写世界。

`SpatialSessionClient` 为每条连接和视图维护代次。暂态订阅失败有有界延迟重连，撤权立即清空旧投影；后台补发修复漏掉的末批。控制 ACK 必须带匹配 nonce、Session 和新快照。新控制 epoch 才建立新的 `MovementCommandSource`；同 epoch 的有效来源沿用其计数器。刷新或来源丢失时不能从服务器 highWater 猜在途请求，应恢复或明确接管以取得新 epoch。

控制事务替换视图期间暂停旧视图补发，并隔离控制开始前已在途的同步结果；成功或明确拒绝后继续同步。结果未知仍保留同连接的原 nonce 供重试，心跳周期不变。真正撤权、换房、断开、更高控制 epoch 或终态仍使旧控制确认失效。

移动与停步从同一来源在发起时分配序号。未知 ACK 保存完整原始请求，查询或原样重发，不更换 ID、视图、epoch、序号或 baseSeq。动作缓存放在标签页 sessionStorage，按登录用户和 Session 隔离；缓存不是权限凭证，授权投影不持久缓存。明确失效的登录按原身份层规则清除。

客户端显示公开错误码的固定中文反馈，不把校验器路径、内部异常或调试对象直接呈给玩家。陈述、观察和物件名称来自服务器已经授权的 DTO。

## 地图、行走与操作

灰盒渲染服务器可见地图的尺寸、可走多边形、障碍及明确扣除区、锚点和出口；角色绘制以脚底位置为准。地图点击通过 SVG 实际坐标变换得到整数目标，发送目标请求，不能提交位置事实。支持查看全图、跟随角色和回到角色；方向键与 Escape 提供移动和停步入口。

本人只沿已授权完整路线中两个已确认位置之间的段插值，保留折线转角。其他角色仅在服务器给出连续可见 `motionTrail` 且端点与已有确认相接时播放；缺字段、断段、换视图、换场景或离开投影立即回退到当前确认点，不推断隐藏轨迹或未来目标。插值最多滞后 200ms，不向未来外推。

点击物件后的后续操作绑定视图、控制 epoch、命令序号、地图版本以及目标当前公开状态。必须先收到同一路线的服务端 `arrived`，且本人绘制已追到对应确认点，才另发操作。停步、换目标、控制变化、目标移动或版本改变会取消后续；操作仍由服务端重验。

出口点击拆为当前场景走到出口、确认到达后再提交目标场景入口请求。两段在同一次点击预留命令顺序，第二段仍受原计划取消条件和服务端出口前提约束；不以客户端按钮直接切换场景。

物件拿取、脚边放置、近距转交、已声明公用物领回、协作准备/就位/取消、交谈和证据分享使用当前投影提供的引用与版本。客户端不猜初始协作版本或站位，合作列表依赖服务端给出合法可见的准备数据。锁定准备只显示服务端结果。

## 章节阅读与当前授权

按 `GZ-VIS-01/v1.1` 的场景优先、独立文字和状态语义，将行囊、手记、交谈改为按需展开的阅读区。桌面阅读区占用独立侧栏，不覆盖地图上的人物；窄视口顺序排在地图下方。阅读区不遮罩或暂停世界，服务端投影继续更新。关闭时恢复当前场景操作与入口焦点；Escape 先关闭阅读区，没有阅读区时才提交一次停步。

阅读内容与操作对象始终来自当前授权投影；同名人物依不透明引用区分，交接与分享不会按姓名重定向。对象离开投影时清除收件人，换房、换授权视图或撤权时清除选择、阅读区与未发送草稿。手记区分陈述、证据、事实，并仅展示 DTO 已提供的来源说明；不从引用、字段 key 或序号猜身份。未知动作的全部查询/原样重试入口继续保留，只有确定历史取最近八条。

当前视图为每个可见人物分配唯一临时前置编号，并在地图、选中卡、可见对象列表、物主说明以及交接/分享/定向下拉框中使用相同标记。所有人物统一使用“编号 · 当前授权姓名”，合法姓名即使本身含编号格式，也不会使两个完整标签同文。编号只跟随本视图的公开引用，人物排序或暂时离开不会把编号移给另一人；视图失效即清除，不充当真实身份或跨视图追踪标识。地图换选对象或点地后清除旧收件人，阅读区明确显示地图选中者；发送前仍须选择可见收件人。历史陈述的称呼保持服务器记录，不套用当前地图编号。

### 生产章节交互

`SpatialSessionPage` 只在服务端声明 `gaolao-world-v1` 并给出授权 `chapter` 时挂载章节交互。选中卡按当前 `availableOperations` 显示有限操作；接近、停步、拿取、物权交接、证据送达仍走原空间客户端与收据通道。新操作继续保存完整原请求，未知结果原串重试，不把新版本许可或新结束轮塞入旧请求。

场景上方摘要在初始阶段使用授权目标；已有章节进展后复述当前 `chapter.progress` 字段，终态使用授权结局。刷新和打开回看都重新读取当前投影，不能重新把静态的初始救援文字当成尚待执行的事项。否定或尚无的字段保持其状态，不改写为完成；A1 仍使用原目标列表。

`GaolaoInteractionPanel` 提供联络／铜封核查、当前许可版本的随行改约、借貌／会面请求、私物处理请求、公用物实际归还、来源比较和离庄通知。地面物件没有公开物主字段，持有人也不等于物主；私物请求只选当前可见非公用物，物主、本人许可与本次用途由服务端校验。NPC 本人的破封、退让、确认安置、借貌执行和去留决定没有玩家代答按钮。

`GaolaoChapterState` 在“进展”阅读区展示当前 DTO 已授予的职责、许可用途与本次范围、随行、本人决定、公共物和结束确认轮。每个人物及用途按十进制版本取最新安排，旧记录保留在当前获准的手记和终态授权历史里。到达不等于安置，暂缓/未决不显示为拒绝；撤回不会由客户端抹去已确认进展。回应和撤回按钮只针对当前 `self.entityRef`，不能替同名人物或 NPC 签字；发出请求不乐观改写状态。`route` 缺席时不显示乔装安排，人物称呼只按当前授权对象和本视图临时标记解析。

`GaolaoSourceComparison` 保留材料原类别与来源，按当前合法观察引用选择旧账和独立见闻；同一原始来源、失效观察和失去操作资格不能构造请求。有限操作使用生成的 `GaolaoInteractionV2` / `gaolaoInteraction`，不依赖旧通用字符串分支作类型窄化。提交比较只是意图，不产生客户端事实或人物决定。

全员结束入口分别提出“结束本局招徒”与“暂告一段”；每位当前在线旅伴须明确确认同一轮。人数变化导致旧轮失效，由当前服务器投影撤下确认按钮。招徒结束后仍需实际安置、归还与分别；界面不把口头意向、到达或确认动画当成世界完成。

`SpatialRecapClient` 与 `HttpApi.spatialRecap` 在“回看”阅读区读取独立 v2 授权历史，仅在当前在线终态投影下启动。它固定终态水位，绑定账号、房间、本人引用和视图代次；换绑定取消旧请求并清空，迟到结果不能回填。分页校验同房间/水位/终态、从新到旧的事件顺序、条目去重以及末条游标推进；同一事件的多条合法记录仍可保留。暂时故障保留已读并标明未完，明确撤权清空历史及结局，反馈不显示内部异常。`GaolaoRecapPanel` 保留三类结局给出的事实与历史 `speakerName`，不以当前人物称呼重写过去。

`frontend/tests/gaolao-fixture.html` 仍只用于独立组件检查。生产入口连接真实后端；组件截图不能证明后端同意、来源比较、结局或真人体验已完成。

## 检查与边界

```sh
cd frontend
npm test
npm run build
```

真实高老庄作者浏览器入口（仓库根目录运行）：

```sh
npm run test:browser:gaolao --prefix frontend
```

该入口启动隔离 PostgreSQL、真实 HTTP / Socket.IO 和 Vue 页面。人类合成账号经可见页面发出正常客户端请求；NPC 通过受信观察、意图预留与提交入口执行明确受控策略，没有直接改写世界。它覆盖 2 人与 5 人章内交互、三种收尾与各自授权复盘、恢复和桌面／窄屏；最终 2/3/4/5 矩阵与五客户端不少于 900 秒由独立验收另行执行。脚本只定义范围，实际结果必须绑定运行时固定源码。现有 `.github/workflows/ci.yml` 在保留 A1 与未知请求恢复检查的同时执行本入口；A2 具名 JSON 与截图单独归档，不上传数据库、凭据或浏览器缓存。

A1 兼容浏览器入口（明确选择行走灰盒）：

```sh
node frontend/tests/spatial-browser-check.mjs
```

脚本实际启动隔离 PostgreSQL、权威 HTTP / Socket.IO 服务及 Vite，再运行 2/3/4/5 个独立浏览器身份；指定 Playwright 与 Chromium 的环境变量沿用本目录 README。各组检查真实页面登录、控制、点地、停止；2人与5人进一步检查拿取、转交、协作及出口，2人检查刷新、断网、场景暂停恢复和窄屏布局。所有资源由 finally 关闭。脚本存在与构建通过不等于这些运行检查已经通过，具体候选和结果由 #33 记录。

阅读区针对性入口为 `node frontend/tests/spatial-reading-browser.mjs`。该脚本使用真实 Vue/Chromium、Socket.IO 与受控公开 DTO，检查按需阅读、同名引用、失效收件人、Escape、持续投影、来源标签和撤权清除；不替代真实权威服务的权限规则或完整高老庄联调。地图脚本另外记录每次原世界目标、实际屏幕像素、逆变换及发出的世界目标，在原精确到达断言前校验坐标映射。

新增组件隔离入口为 `node frontend/tests/gaolao-components-browser.mjs`。它用真实 Vue/Chromium 渲染受控 DTO，检查本人权限、同意/随行/决定的状态区分、严格动作载荷、来源失效、历史称呼与分页反馈、三类结果显示和撤权；没有启动后端。`gaolao-actions.test.mjs` 与 `spatial-recap.test.mjs` 分别覆盖请求构造边界及读取代次/分页恢复，不能替代服务端规则验收。

首轮实际接入在两人先订阅大厅、再 HTTP 开局的顺序中发现服务端新实体引用缺失，已交 #31 修正；保留原失败，不使用前端强制重连掩盖。原 region-v1 实际浏览器回归已执行，适用源码身份与原始结果交总控。继续实跑时须固定修正后的组合候选。

真实模型、真人趣味／复玩、正式水墨素材与动画、手机真机属于后续独立范围；当前界面保持已采用的文字可读性、44px 命中区与不遮挡人物的布局。高老庄实际章内结果、同候选五人长测与独立审查以 #33 / #29 的固定证据为准。设计图、自动浏览器和真人体验各自取证。
