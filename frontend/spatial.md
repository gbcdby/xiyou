# spatial-v2 灰盒客户端

对应 [ADV-001 #33](https://github.com/gbcdby/xiyou/issues/33) 的 A1 子阶段，依据 [adv-protocol-v1/r2](../docs/specs/adv-protocol.md) 和 [#31 机器协议阶段产物](https://github.com/gbcdby/xiyou/issues/31#issuecomment-6825190128)。完整章节交互、正式素材与运行视觉继续按 #32 / #28 的释放条件接续；本页不声明 A1 或整票通过。

## 入口与兼容

- 大厅可以选择行走灰盒或旧版山间通路。空间创建、加入和 Socket 认证明确携带 `spatial-v2` 能力，空间只读 HTTP 请求使用能力请求头。
- `/spatial/:sessionId` 只消费 `SnapshotV2` / `BatchV2`；`/sessions/:sessionId` 保持原 v1 驱动。房间列表能力或加入结果决定路由，新创建的旧版房间直接沿已选能力加入，不等待列表更新。
- `protocol/spatial-schema.mjs` 仍是字段唯一来源。前端使用生成类型与公开校验器，不维护第二份消息 schema，不导入服务端内容、真身、受众或知识状态。

## 状态、控制与原请求

`SpatialView` 先完整校验批次，再按完整区间原子替换投影与游标。重复、缺口、旧视图、旧连接和不匹配身份分开处理；不按事件条数猜测全局序号差。投影与渲染缓存分离，渲染不会改写世界。

`SpatialSessionClient` 为每条连接和视图维护代次。暂态订阅失败有有界延迟重连，撤权立即清空旧投影；后台补发修复漏掉的末批。控制 ACK 必须带匹配 nonce、Session 和新快照。新控制 epoch 才建立新的 `MovementCommandSource`；同 epoch 的有效来源沿用其计数器。刷新或来源丢失时不能从服务器 highWater 猜在途请求，应恢复或明确接管以取得新 epoch。

控制事务替换视图期间暂停旧视图补发，并隔离控制开始前已在途的同步结果；成功或明确拒绝后继续同步。结果未知仍保留同连接的原 nonce 供重试，心跳周期不变。真正撤权、换房、断开、更高控制 epoch 或终态仍使旧控制确认失效。

移动与停步从同一来源在发起时分配序号。未知 ACK 保存完整原始请求，查询或原样重发，不更换 ID、视图、epoch、序号或 baseSeq。动作缓存放在标签页 sessionStorage，按登录用户和 Session 隔离；缓存不是权限凭证，授权投影不持久缓存。明确失效的登录按原身份层规则清除。

客户端显示公开错误码的固定中文反馈，不把校验器路径、内部异常或调试对象直接呈给玩家。陈述、观察和物件名称来自服务器已经授权的 DTO。

## 地图、行走与操作

灰盒渲染服务器可见地图的尺寸、可走多边形、障碍及明确扣除区、锚点和出口；角色绘制以脚底位置为准。地图点击通过 SVG 实际坐标变换得到整数目标，发送目标请求，不能提交位置事实。支持查看全图、跟随角色和回到角色；方向键与 Escape 提供移动和停步入口。

本人只沿已授权完整路线中两个已确认位置之间的段插值，保留折线转角。其他角色仅在服务器给出连续可见 `motionTrail` 且端点与已有确认相接时播放；缺字段、断段、换视图、换场景或离开投影立即回退到当前确认点，不推断隐藏轨迹或未来目标。插值最多滞后 200ms，不向未来外推。

点击物件后的后续操作绑定视图、控制 epoch、命令序号、地图版本以及目标当前公开状态。必须先收到同一路线的服务端 `arrived`，且本人绘制已追到对应确认点，才另发操作。停步、换目标、控制变化、目标移动或版本改变会取消后续；操作仍由服务端重验。

出口点击拆为当前场景走到出口、确认到达后再提交目标场景入口请求。两段在同一次点击预留命令顺序，第二段仍受原计划取消条件和服务端出口前提约束；不以客户端按钮直接切换场景。

物件拿取、脚边放置、近距转交、已声明公用物领回、协作准备/就位/取消、交谈和证据分享使用当前投影提供的引用与版本。客户端不猜初始协作版本或站位，合作列表依赖服务端给出合法可见的准备数据。锁定准备只显示服务端结果。

## 检查与边界

```sh
cd frontend
npm test
npm run build
```

真实空间浏览器入口（仓库根目录运行）：

```sh
node frontend/tests/spatial-browser-check.mjs
```

脚本实际启动隔离 PostgreSQL、权威 HTTP / Socket.IO 服务及 Vite，再运行 2/3/4/5 个独立浏览器身份；指定 Playwright 与 Chromium 的环境变量沿用本目录 README。各组检查真实页面登录、控制、点地、停止；2人与5人进一步检查拿取、转交、协作及出口，2人检查刷新、断网、场景暂停恢复和窄屏布局。所有资源由 finally 关闭。脚本存在与构建通过不等于这些运行检查已经通过，具体候选和结果由 #33 记录。

首轮实际接入在两人先订阅大厅、再 HTTP 开局的顺序中发现服务端新实体引用缺失，已交 #31 修正；保留原失败，不使用前端强制重连掩盖。原 region-v1 实际浏览器回归已执行，适用源码身份与原始结果交总控。继续实跑时须固定修正后的组合候选。

本阶段未覆盖完整高老庄、乔装/本人同意/终局、真实模型、真人趣味、正式水墨素材与动画、五人长测或手机真机。设计图、自动浏览器和真人体验各自取证。
