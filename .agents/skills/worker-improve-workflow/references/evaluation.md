# 评估与试用规则

## 评估集合

按目标风险选择必要样本，不追求无关的题量：

- **确认缺陷**：来自真实问题、事故或回滚，保存缺陷时的材料和确认依据。
- **正确改动**：已有独立依据说明其符合要求，用于发现误报与有害建议。
- **边界情境**：例如候选变化、超时未知结果、缺少权限、宿主不支持的能力。
- **留出样本**：不在调优时展示答案，用于检查方法是否只记住见过的案例。

标签应可追溯。修复过、线程已关闭或作者拒绝意见都不是充分标签；必要时对样本重新确认。新评估者只看到完成任务所需的原始材料，已知结论保存在评分侧。

## 比较单位

至少记录任务类型、harness 版本、模型版本、Skill 版本、工具能力、相关配置和环境。它们共同决定实际能力，不能只按模型品牌排名。

对照保持关键条件可比较；无法保持时记录差异。把冷启动、失败、超时、重试和总成本计入实际工作量；不要只比较最快的一次。样本少时不输出虚假的精确排序。

## 指标与反向激励

| 指标 | 必须同时检查 |
| --- | --- |
| 发现真实问题 | 误报、有害建议与实际严重度 |
| 自动通过率 | 是否删除检查、改变标签或降低验收 |
| 审查轮次减少 | 是否忽略未解决的阻断问题 |
| 人的审查时间减少 | 后续修复、恢复和被打断成本 |
| 交付速度 | 真实验收、回滚和返工 |
| 模型或工具成本下降 | 成功率、质量与补救成本 |

保留分组结果，避免总体平均掩盖高风险类别的退化。没有足够事件或样本时报告限制；阈值未设定时先形成规则提议，不在看到结果后选择有利阈值。

## 审查收敛

为 finding 保留规则或根因、位置、对象版本、证据、状态与被替代关系。后续检查优先核验修复、新增变化和受影响依赖，已报告且无新证据的问题不重复发布。

同类缺陷应检查其他实例。达到无进展阈值时，可以创建有界调查、换一种验证方法或返回设计；仍有效的阻断问题不得因轮次结束被清空。

## 试用与回退

在实施前记录：候选版本、试用范围、预算、观测窗口、接受条件、停止条件、回退机制和已有授权来源。

采用结果区分为：仅建议、隔离评估、有限试用、已启用、已回退。每次推进需要实际执行事实；没有运行接口或授权时保持在当前状态。

提高权限、降低验收、移除必要批准属于边界变化，不能夹带在提示优化里。评估通过仅提供技术依据，不提供这些授权。
