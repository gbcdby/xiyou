# 同仓本地并行

用于多个 Spec、会话或 harness 同时写入同一项目。复用现有任务系统和协调能力；小改动、只读或顺序执行不另建看板、锁服务或审批。

## 共同记录

开始、恢复或扩大范围时，查看同仓活动工作：Spec／Ticket、负责人、实际目录、分支与基线、修改范围；仅登记实际用到的共享环境和接口。记录位置须能被各工作区、会话和相关 clone 共同访问，不能把各分支里的独立副本当全局状态。

沿用既有负责人和约定。各 Spec 自行推进；重叠资源与集成顺序有明确协调者。没有原子领取时，由该协调者串行确认共享对象的分配与交接；普通文件、Issue assignee 和心跳不提供硬锁。不为此阻塞已隔离的独立工作，也不要求人逐项批准。

## 按实际冲突处理

| 对象 | 默认处理 |
| --- | --- |
| 工作目录 | 每个并行写入单元使用独立目录；Git 默认 worktree／clone 加独立分支。顺序任务可复用，只有分支不同不足以隔离未提交内容。 |
| 端口、测试库、构建与临时路径 | 仅对任务实际使用的资源核对并隔离；核实实际连接／写入位置。无法隔离的独占资源按约定轮流使用。 |
| 同名文件 | 不同目录里兼容的修改可并行；记录整合责任，不因文件重叠锁住整个 Spec。 |
| 公共接口、数据与迁移 | 约定兼容时可并行；存在真实冲突时指定一个基础任务／负责人，或明确依赖与顺序，其他工作继续。 |

缺少活动记录时，先查现有工作区、分支和已知参与者，建立所需的最小共享记录；不把目录干净当作无人工作，也不因未知是否还有别的会话而停掉全部实现。无法确认共享对象归属时，只暂缓该对象的操作。

## 集成与交接

复用合并队列；没有队列时明确一个集成负责人，按依赖整合并检查最新组合。基线或约定变化时，只重评受影响任务与证据。

失联或超时不自动释放独占资源。接管前核对旧执行者、工作区和已发生的操作；暂时无法确认时保留原现场，继续可隔离的工作。只在开始、范围／状态变化和交接时更新必要记录，不维护重复状态或频繁全仓扫描。

## 收尾与资源释放

一项工作结束只释放自己的资源使用关系；共享或活跃资源、下游仍需产物继续保留。由原负责人逐项核对，已独立释放的资源可继续清理，不等待所有 Spec 结束。Git 分支与 worktree 的内容核对和删除交给 `worker-land` 或等价能力，沿用当前清理授权与活动记录，不新增全仓扫描或锁服务。
