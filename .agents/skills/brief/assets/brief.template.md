# 项目简报模板

只取与用户问题有关的部分，不填空栏目。默认约 200–400 汉字，重要未知、阻塞和待决事项不因篇幅被省略。

**〈一句话回答现状或最重要的变化。〉**

多项可比较信息用短表，否则用少量短句；下表是占位格式，不是待报告事实。

| 事情 | 现在怎样／有什么影响 |
| --- | --- |
| 〈事项〉 | 〈实际结果及短依据链接〉 |

- **卡在哪里（有才写）**：问题与影响；Agent 能继续处理的卡点不要求人拍板。
- **需要你决定（有才写）**：问题、建议及主要代价、影响或等待后果；所有实质决定保留短索引。
- **下一步（问到才写）**：已记录安排，或明确标为建议；不写成已经启动。

问设计变化时，改用“原来／现在／影响”表或一张小图，解释职责、依赖和取舍。标清计划与已实现部分；缺少之前确认的设计时说明无法判断累计变化，图后不逐项复述。

关键结论旁给短依据链接。记录观察时间、实际版本、来源时效和检查范围；影响判断的旧资料、版本差异和未知在正文直说，其余细节按需展开。

普通简报不附 JSON、状态码或完整字段表；接收方确需机器记录时使用 [交接约定](../references/result-contract.md)。
