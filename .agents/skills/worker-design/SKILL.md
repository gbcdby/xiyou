# 行为与系统设计

形成足以指导实现和验证的方案，解决会影响后续工作的真实不确定性。可跨项目、跨语言独立使用，不依赖其他 Skill 或协作宿主。

## 1. 固定对象与范围

- 读取目标、项目约定、现有架构与源码、验收条件、已有决定，确定本次设计终点；不重复确认已明确的要求和授权。
- 记录实际对象版本，区分当前实现、拟议方案和之前已接受的设计；保留决定的依据、适用条件与替代关系。
- 确认共享 Spec 的权威位置和有效修订。无现成 Spec 时按项目约定形成设计记录；小改动可以使用紧凑契约，不强制长文档、多个方案或新 Issue。
- 在授权和预算内查资料、测量或做隔离原型。原型注明用途和限制，不能直接冒充生产实现或运行验证。

## 2. 设计行为与结构

从用户或调用者入口说明输入、成功、失败和结果未知时的行为；为关键验收条件保留稳定编号。

| 设计面 | 必须解决的相关问题 |
| --- | --- |
| 行为 | 主路径、异常、取消、恢复与兼容承诺 |
| 状态 | 谁记录、谁能写；请求、接受与实际效果何时成立 |
| 并发与重试 | 冲突的决定者、重复操作身份、超时后未知结果 |
| 模块与接口 | 谁判断、执行、保存和观察；输入输出、错误与调用方承诺 |
| 演进 | 依赖变更、兼容迁移、恢复或补偿，何时移除旧路径 |

只展开与本次问题相关的设计面。区分业务约定、环境假设、实现义务和可自由选择的机制；稳定承诺放在清楚的接口上，不无依据指定数据库、锁或队列。

存在实质取舍时比较少量方案的收益、代价、失败方式与证据。可调查的问题先查事实；确需人的产品取舍时给出具体推荐及影响，不以多数模型赞同替代依据。

## 3. 建立验证路径

- 对关键验收条件写明检查对象、输入与环境、可观察输出和失败判据，核实所需工具是否真实可用。
- 对核心不确定性选择最小实验；结果绑定实际对象与环境，未运行的内容明确标注。
- 并发交错、幂等、乱序、资源竞争、取消与恢复值得建模时，给 `worker-tla` 或合适的验证者提供性质、假设和状态边界。没有该技能仍可交付同等输入，不假称运行 TLC。
- 分开记录模型结论、源码对应与实际行为证据。设计或模型通过不表示业务实现已通过，也不授予合并或发布权限。

## 4. 形成持续共享的 Spec

Spec 保留目标与设计概览、共同约束、整体验收，以及 Ticket 目录和依赖图的入口。设计阶段写清设计语义；具体拆票交给 `worker-plan-tickets` 或调用者，总控负责运行时调度。

- 使用 [设计模板](assets/design.template.md) 的必要部分，复用项目权威记录；详细任务与依赖已在其他权威位置维护时只引用，不复制一套状态。
- 交接 `spec_ref` 的位置与有效修订、稳定验收编号、约束、实施自由度、验证路径、未决事项和返回设计的条件。没有实际平台接口时交付草案，不伪造写入或接受记录。
- 按 [可读视图与语义](references/visual-semantics.md) 展示职责、变化和影响。图是设计记录的阅读视图；标清计划、模型检查与实际实现，不省略会改变判断的条件或反例。
- 核对相对上次观察和已接受设计的变化；没有接受基线时说明限制，不自动把当前方案标成已接受。

## 5. 交回设计结果

默认用简短文字给出设计记录、决定依据、实施义务、验证状态与缺口。结束本职责，后续工作由原调用者沿用有效授权推进；不自动接管拆票、实现或交付。

- `COMPLETE`：约定范围的设计与实施义务已明确；未运行检查仍需显式保留。
- `INCONCLUSIVE`：现有依据不足以确定关键方案；`BLOCKED`：缺少必要决定或访问。完成不依赖该缺口的部分，再交回具体影响。
- 检查仅有计划时标 `NOT_RUN`；有范围和真实证据的检查才可报告 `PASS`，保留原工具状态。

后续若改变调用语义、原子性、状态归属、外部效果、环境假设或兼容承诺，标出受影响的 Spec、Tickets 与证据，重新评估相关部分。只改图形样式不改变设计验证状态。

仅接收方需要时输出 `work-result/v1`：`schema_version/work_id/skill/outcome/subject/evidence/unresolved/changed_assumptions/next_action`。`subject` 含 `kind` 和真实修订身份 `id`；证据含 `id/locator/scope/status/producer/subject_id`。`next_action` 与 `evidence.scope` 为非空文本，`evidence/unresolved/changed_assumptions` 为数组。静态观察用 `OBSERVED`，历史实测保留对象和日期；跨对象材料标 `relation: background`，不伪装当前对象已通过。原工具报告可由交接层包装，无须改其格式。
