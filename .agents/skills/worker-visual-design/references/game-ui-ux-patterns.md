# 12 个通用游戏 UI/UX 模式（条件化应用，不是固定布局）

材料基于 20 个游戏的官方图文研究；每条模式包含适用情境、推荐动作、失效边界和验证任务。它们是跨案例的设计**假设工具**，没有将观察次数解释成普遍有效的统计结论。可从 [完整案例研究库](game-case-library.md) 找到对应 GAME ID 和原始来源。

## 模式索引

GP01 注意力；GP02 表现与阅读；GP03 固定语法；GP04 动作种类；GP05 因果反馈；GP06 上下文与返回；GP07 比较；GP08 缺口路径；GP09 有界辅助；GP10 等效操作；GP11 探索与说明；GP12 压力节奏。

使用方式：写下任务与失败代价 → 选择一个主要模式 → 找一条反例 → 约定可观察的成功／失败信号 → 再做设计。不要求同时采纳 12 条。

### GP01 让注意力对应当前任务

把当前任务必须看到的信息放到同一可扫读关系中；背景故事、角色表现和持续状态可以并存，但不必同等显著。比较《纪念碑谷 2》的空间路径、《Spiritfarer》的建造侧栏和《Terra Nil》的阶段／成本：三者的必要信息不同，不能从“精美”推导出统一的少按钮布局。

- **适用**：玩家常问“现在该做什么”“这次操作影响哪里”。
- **动作**：列出此次决策需要的事实、输入、成本与结果，把每项安排到明确区域；降低与当前任务无关的装饰竞争。
- **边界**：战斗中的危险与关键持续状态不能为单一焦点被藏掉；场景截图没有 HUD 也可能只是宣传方式。
- **检查**：不给控件提示，只给任务，让玩家指出当前对象、可以做的动作和所需条件；记录漏读与误解，不用主观“很干净”代替证据。

来源：[ustwo](https://ustwo.com/work/monument-valley/)、[Spiritfarer](https://thunderlotusgames.com/games/spiritfarer/)、[Terra Nil](https://store.steampowered.com/app/1593030/Terra_Nil/)。

### GP02 把表现层与精确阅读分开处理

允许纹理、插画、世界内装置承担气氛，让名称、数值、条件与操作提示拥有稳定承托。《Dordogne》的手绘纸条、《stitch.》的数字轮廓、《Persona 5 Royal》的规整对话正文展示了不同做法。

- **适用**：背景精美但文字吃力，或世界内信息会随镜头变小、变斜、被遮挡。
- **动作**：先保证正文、必要边界与选中态可读，再把材质加到不破坏它们的位置；必要时提供平面读数或辅助模式。
- **边界**：不规定所有项目都用纸张、半透明卡片、统一低饱和或固定色数；高对比、科幻、像素也可采用同一原则。
- **检查**：在实际背景、缩放、文字长度与观看距离下核对；世界内显示另测遮挡和角度。宣传截图不能证明触控尺寸或对比度达标。

来源：[Dordogne](https://www.focus-entmt.com/en/games/dordogne)、[stitch. 访谈](https://developer.apple.com/news/?id=mc4d1ufa)、[Persona 5 Royal](https://www.playstation.com/en-us/games/persona-5-royal/)。

### GP03 固定语法，放开内容与主题

优先统一组件边界、字级、对齐、间距、状态含义和输入结果；允许场景、人物、色域与题材变化。《GRIS》《Alto’s Odyssey》的配色变化和《Hades》不同场景中的稳定状态区提供了不同尺度的例子。

- **适用**：系列资产一换角色就散，或为求统一而把整套作品染成一色。
- **动作**：把固定项与可变项逐项写清；功能色与角色身份色分开，换主题时重新检查实际对比。
- **边界**：探索布局阶段允许比较多种结构；用户定稿或同一实际流程才需要稳定位置。不能借“一致性”冻结尚未决定的布局。
- **检查**：跨两个相差明显的场景／主题检查相同动作是否仍能被找到、相同状态是否仍同义。

来源：[GRIS](https://nomada.studio/gris-game/)、[Alto 官方媒体包](https://altosodyssey.com/press/)、[Hades](https://www.supergiantgames.com/games/hades/)。

### GP04 减少动作种类，保留选择深度

让少量容易理解的动作作用在清楚对象上。《Prune》的修枝、《Unpacking》的取物摆放、《Townscaper》的选色放块说明：输入简单与结果丰富并不冲突。

- **适用**：初始学习成本高，或多个手势没有清楚区别。
- **动作**：为每个核心动词规定对象、合法条件和可见结果；对高频任务复用动作语法，把难度留在有意义的决策上。
- **边界**：少动作不等于所有操作一步完成；有成本的提交需要知情确认。精确数值也不能被迫用难控的空间手势输入。
- **检查**：新玩家能否从一次示例迁移到同类对象；重复操作是否出现手势混淆、误提交或不必要步骤。

来源：[Prune 支持](https://prunegame.com/support)、[Unpacking](https://www.unpackinggame.com/)、[Townscaper](https://rawfury.com/games/townscaper/)。

### GP05 让反馈有对象、有因果、有凭据

把即时按下反馈、处理中、系统确认、最终结果分别设计；让结果出现在玩家操作的对象或受影响的信息附近。《Spiritfarer》的材料／场景预览和侧边获取回执、《Hades》的目标附近战斗信息可提供位置关系参考。

- **适用**：玩家不知道点击是否生效、资源到了哪里或为什么变化。
- **动作**：写出触发对象 → 接收反馈 → 真实处理状态 → 受影响对象 → 可回查结果；异步业务以真实确认驱动完成效果。
- **边界**：单机即时结果不能证明网络交易可乐观记账。演出不是业务成功凭据，失败重试也必须有真实能力支持。
- **检查**：看见／没看见动画、减少动效、离开后返回时，是否仍能说明结果；模拟未知结果时不能假报成功。

来源：[Spiritfarer](https://thunderlotusgames.com/games/spiritfarer/)、[Hades 历史更新](https://www.supergiantgames.com/blog/get-pumped-for-the-beefy-update/)。异步确认与恢复是设计转译，另依 UX 工作流核实业务。

### GP06 按上下文展开，明确模式与返回

把当前决策的选项放在当前上下文，使用可识别的模式标题、当前选择和退出动作。《Dordogne》的工具取景、《Spiritfarer》的建造模式、《Dorfromantik》的模式选择都可研究；不要只学面板外形。

- **适用**：首页功能过密，或玩家展开后不知道自己在哪里。
- **动作**：区分展开／收起、导航、切换模式、提交；保留触发入口、当前状态、返回路径和未完成输入。
- **边界**：渐进展开不能藏掉必须同时比较的事实；减少可见项也不应让高频任务反复钻层级。是否暂停、是否模态由产品任务决定。
- **检查**：进入 → 改变选择 → 返回 → 再进入，当前对象和草稿是否按约定保留；关闭是否被误解成提交或撤销。

来源：[Dordogne](https://www.focus-entmt.com/en/games/dordogne)、[Spiritfarer](https://thunderlotusgames.com/games/spiritfarer/)、[Dorfromantik](https://www.toukana.com/dorfromantik/presskit)。

### GP07 用稳定字段支持比较与确认

为同类候选提供相同字段和顺序，区别当前、选中、已拥有、已占用、锁定和不可用。《炉石传说》的牌组列表与《原神》4.5 养成页可作为信息排列参考；把它们转译为比较方法，不复制属性系统。

- **适用**：装备、技能、卡组、建造或其他需要选择的候选集合。
- **动作**：按真实数据展示名称、用途、条件、成本和变化；选择预览与最终生效分开，增减含义不能只靠红绿。
- **边界**：数值更高不必然更适合；不同属性、规则版本或条件下不能伪造统一分数。
- **检查**：给两个有取舍的候选，让玩家说出会获得、失去和花费什么；取消预览不应意外更改实际配置。

来源：[炉石开发者说明](https://news.blizzard.com/en-gb/article/22938500/developer-insights-smart-deck-builder)、[原神 4.5 开发者说明](https://blog.playstation.com/2024/03/05/20230306-genshinimpact/)。

### GP08 把目标、缺口和解决路径连起来

不要止于“条件不足”。在有真实能力和信息时，连接当前目标、缺少的条件、来源入口、解决后的回归位置。《原神》4.5 养成指引把材料短缺与来源导航放在同一上下文，《Terra Nil》按阶段组织任务。

- **适用**：成长、制作、配置、任务或解锁路径复杂。
- **动作**：清楚区分缺资源、等级锁定、时间未到、数据未知；只对有效来源给入口，并保留返回上下文。
- **边界**：没有来源数据时说明缺口，不能编造来源、奖励、时间或跳转；不足不应默认导向付费。
- **检查**：从缺口到解决再返回，玩家是否仍知道原目标和所选对象；不可获取或过期时入口是否诚实。

来源：[原神 4.5](https://blog.playstation.com/2024/03/05/20230306-genshinimpact/)、[Terra Nil](https://store.steampowered.com/app/1593030/Terra_Nil/)。

### GP09 提供有边界的辅助，保留玩家决定

推荐依据应可解释，尊重已选项、真实拥有资源、锁定项与占用关系。《炉石传说》2019 智能组牌保留指定卡、只用已有收藏；《原神》4.5 的常用武器区交代了数据依据。两者不构成“热门即最优”的证明。

- **适用**：选项多，玩家需要起点而非自动代理全部选择。
- **动作**：先展示推荐理由、适用条件和差异，再让玩家确认；允许不接受推荐。
- **边界**：无数据、无适配模型时不生成“最佳”结论；不静默扣费、购买、替换或覆盖用户锁定。
- **检查**：已有偏好、资源不足、候选被占用时，推荐能否解释限制；拒绝推荐后流程仍可完成。

来源同 GP07。辅助只是一种候选模式，产品没有授权时不自动新增“一键配装”。

### GP10 为同一目标提供等效操作和读取方式

把能否看清、能否触达、能否完成动作作为设计输入。《Unpacking》的输入替代、《Sky》的单双手讨论、《stitch.》的数字与左手设置说明，不同使用者可能需要不同路径。

- **适用**：拖动、长按、多键、精细点击、纹理文字或手指遮挡影响完成。
- **动作**：提供适合当前设备的替代输入、可调读取和减少动态选项；关键状态同时有可读信息，不只依赖颜色或声音。
- **边界**：可访问性不是删掉全部挑战，也不是只增加一个开关；需要与实际核心任务、平台能力和业务约束共同设计。
- **检查**：分别用适用的单手、非拖拽、放大文字、减少动态和辅助技术路径完成同一目标。未实际运行就标为待验证。

来源：[Unpacking](https://www.unpackinggame.com/)、[Sky 2020 访谈](https://developer.apple.com/news/?id=zm47it7t)、[stitch. 访谈](https://developer.apple.com/news/?id=mc4d1ufa)。

### GP11 区分探索乐趣与操作障碍

《TUNIC》有意让说明书也成为谜题；《原神》养成指引和《Dorfromantik》教程帮助玩家快速理解。先判断“发现未知”是否属于玩法，再决定揭示时机。

- **适用**：新手帮助过重，或为了世界观而让日常操作难以理解。
- **动作**：把必须知道的操作、代价和后果提前讲清；把可探索的世界秘密保留给内容层。帮助应可回查，必要时定位到当前问题。
- **边界**：权限、真实费用、失败原因、提交状态、退出与恢复不能写成谜语；也不必提前泄露探索游戏的全部答案。
- **检查**：玩家卡住时能否找到恰当帮助；帮助后能否返回原任务；用故意保密解释哪些信息仍必须可见。

来源：[TUNIC 主创文章](https://blog.playstation.com/?p=370009)、[原神 4.5](https://blog.playstation.com/2024/03/05/20230306-genshinimpact/)、[Dorfromantik](https://www.toukana.com/dorfromantik/presskit)。

### GP12 按任务调节压力、节奏和信息密度

《Alto’s Odyssey》的 Zen Mode、《Dorfromantik》的不同模式、《Unpacking》的无时间惩罚说明，舒适感也来自任务规则和交互成本。强战斗反馈在《Hades》中有作用，不是所有首页的目标。

- **适用**：作品视觉柔和但交互持续催促，或所有状态都使用相同强度演出。
- **动作**：区分安静浏览、需要决策、真实紧急三类情境；去掉没有业务必要的打断与重复奖励演出，保留真实时效信息。
- **边界**：不能通过隐藏真实截止、危险、失败代价来制造安静；也不把低压力设为竞技或高难动作游戏的通用要求。
- **检查**：并发通知、减少动态、长期重复操作时，玩家是否能继续当前目标并理解真实紧急程度；当前没有测试就不报告留存或焦虑改善。

来源：[Alto 媒体包](https://altosodyssey.com/press/)、[Dorfromantik](https://www.toukana.com/dorfromantik/presskit)、[Unpacking](https://www.unpackinggame.com/)。

## 证据核对

- 历史游戏版本和不同平台不得合并为当前唯一事实。
- 开发者对机制的陈述、截图可见关系、设计师推导、实际玩家表现分开记录。
- 官方图片很多没有完整 HUD；不能仅凭“无字画面”推断实际界面应删除说明。
- 涉及精确数值、费用与异步结果的处理，必须以目标产品真实能力决定；游戏案例不足以作为后端规则依据。
