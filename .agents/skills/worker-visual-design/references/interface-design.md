# 从项目规范到界面设计

将当前任务转成界面与组件规格。共享 Spec 决定业务目标与能力；参考提供候选方法，已确认设计提供适用约束。整体画风任务只处理跨资产关系，不展开本流程全部内容。

## 1. 读取合同与复用入口

定位有效 Spec、相关规范、页面合同、公共组件、token 和实际实现，确认：

- **目标与范围**：谁在何种情境下完成什么，本轮解决什么、保留什么、尚未决定什么。
- **平台与输入**：目标是 Web、原生 App、游戏引擎或其他平台；查实际技术栈、输入方式、屏幕、路由和运行入口。
- **既有决定**：画风、字体、图标、材质、容器、导航、反馈、动效与可访问性要求。
- **现状与目标**：代码说明已实现能力，已接受合同说明目标；两者不同时记录差异与迁移范围，不默认为代码推翻设计。

### 设计语言复用优先

同一产品／平台中，按用途和语义选择：直接复用已采用组件与 token → 使用既有变体 → 必要扩展或新设计。已有确认图但无实现时沿用其适用视觉规格；历史废案、未采纳候选和偶然代码样式不作为默认。

现有方案无法容纳真实内容、平台／无障碍需求，或用户要求更改时，说明复用失败原因与新增范围。尺寸按固定值、最小值、伸缩范围和平台单位处理，不让一张图的像素锁死长文案、大字号或命中区。

沿用组件索引；缺少入口且确需后续复用时，最小条目记录：名称与用途、适用平台／页面、规范或确认图及来源、组件／变体／token／素材入口、当前状态和必要例外。不要全量盘点或抄录整套 token。

本次方案说明“复用哪些、扩展哪些、为什么”。局部确认只在其范围内成为默认；重用已确认设计不需要再次索取确认。

### 整页重构时的功能与视觉边界

局部调色持续无效时，结合 [实验自由度](evaluation-lab.md#先区分诊断与方向探索)复核构图和信息层级：

- 分开列出必须保留的业务能力／状态、已确认视觉约束、本轮可重组关系。旧图可仅作功能资料，风格图可仅借鉴画法；重构授权不自动增加机制或删除能力。
- 用户后来限定的入口、读数或导航关系成为布局锚点。改风格同时检查背景、文字、图标、控件和交界。
- 按当前任务组织首屏；次级信息可组合、展开或下沉，不让每项功能都同等醒目。按项目选择分区、叠加或连续场景，不预设卡片数量、比例或按钮数量。
- 被移出首屏的能力需说明新入口、必要通知、状态与返回路径，保留时效事项和错误；“查看条件”与未就绪操作分别表达。
- 给文字与数字稳定色域，统一同类控件语言，联合分配艺术焦点与功能强调。安静不能依靠缩小文字、削弱必要对比或取消反馈。

### 出图前核实真实能力

涉及既有功能、地图、动态内容或条件显示时，在页面记录中保留相关输入：

| 依据 | 需要核实 |
|---|---|
| 数据 | 公开输入／DTO、来源路径与版本、可用和缺失字段；假数据与拟新增能力标明 |
| 行为与布局 | 显隐、展开／收起、固定锚点、允许遮挡范围；内容增长的换行／滚动／伸缩规则 |
| 既有能力 | 镜头、朝向、缩放、手势、组件与状态恢复的复用入口，本轮保留与改变的内容 |

先查合同与代码，需要样例时优先现有公开边界的脱敏数据。静态图不能暗示尚不存在的能力；状态变化需比较锚点与保留布局，不能只画展开态。影响产品行为、状态归属或接口的缺口交给 `worker-design` 协同明确。

## 2. 把参考转成有边界的决定

先查看现有参考；有缺口时使用实际可用的搜索或 `huaban-ui-ref` 等能力，并遵守其调用限制。每个采用点说明来源、可见观察、借鉴部位与不适用部分。长图、拼图检查影响判断的实际细节。

配色说明主调、固有色、亮色、结构深色与阅读色的职责和面积关系。“温和、简洁”不能自动翻译为全局降饱和、加白或暖色滤镜；结合细节密度与对比判断。纹理与线条数量不等于材质品质。

长期入库按任务授权执行；资料收录和风格采纳分别记录，已有授权不重复问人。有取舍时只查相关 [案例](game-case-library.md)、[模式](game-ui-ux-patterns.md)或[决策](ui-ux-decision-playbook.md)，不为凑结果引入陌生画风或行业假设。

## 3. 形成可实现的规格

在既有 Spec／界面文档中写本次相关部分：跨页共性进入公共规范，具体页面进入页面合同，画风总纲不承载整份页面规格。

| 方面 | 需要明确的决定 |
|---|---|
| 信息架构 | 用户目标、主次信息、关键读数、动作、按需展开内容与阅读顺序 |
| 布局与适配 | 对齐、间距、密度、滚动／固定区、安全区、键盘、窄屏与长文案 |
| 字体与颜色 | 字级职责、数字排版、语义 token、阅读承托、复杂背景与状态区分 |
| 组件与图标 | 公共组件、变体、尺寸与识别；矢量／位图按用途与资产语言选择 |
| 操作与导航 | 点按／拖动／长按、返回／关闭、焦点／上下文、手势冲突、代价与恢复 |
| 状态与反馈 | 默认、选中、不可用、处理中、空态、失败、未知结果、成功，按适用范围选择 |
| 表单与差错 | 标签、输入格式、校验时机、错误位置、重试、重复提交与草稿恢复 |
| 动效 | 目的、触发、状态同步、时序、中断与减少动态；演出不能冒充业务成功 |
| 可访问性 | 字号缩放、命中区、辅助技术标签与顺序、键盘、非颜色编码、可读性 |
| 素材与性能 | 素材用途／尺寸／透明度／预算、占位、防布局跳动、长列表、动画和解码 |

只细化影响本次设计和验收的决定，不凭清单新增产品未支持的主题、方向或设备。数值注明平台单位与来源，CSS px、iOS pt、Android dp 和图片像素分别使用；需要平台细则时查当前官方资料并记录适用性。

## 4. 选择图片或隔离原型

根据当前不确定性选择草图、图片、组件样本或可运行设计原型，不强制每项任务先出图或凑三版。若用户要求先选图，遵守该停点；已有确认或直接做代码原型的授权直接承接。

图片简报带上复用组件、已确认视觉依据、目标比例与主要状态；明确完整首屏、滚动长页还是比较板。生成后检查真实尺寸与内容，预览等比处理，不用裁功能、拉伸图片或把比较板当单屏掩盖偏差。生成文字、示例数字和偶然图标不自动进入功能合同。

`prototype`、图片与 Rive 能力只在实际可用、适用且允许调用时使用；不可用时交付可执行简报与规格，说明相关未验证项。需要原型时采用目标平台的实际技术栈、假数据和隔离状态；探索原型不冒充生产实现或平台验收。

已有确认图且需要据图落实时，给 `worker-ui-fidelity` 交接原图与版本、确认范围、布局／字体／素材合同、允许差异和相关状态；按技能名称调用，不依赖安装目录。无需重新确认已有决定。

## 5. 自查与交接

按 [界面核对](interface-validation.md)自查本次规格和实际产物；必要时运行最小原型以消除设计不确定性。区分静态视觉、原型、设备交互和用户任务证据，保留未测范围。

输出 Spec／页面修订、依据、复用入口、状态与素材合同、设计取舍、自查证据及后续检查条件。在授权内按 [项目学习](project-learning.md)更新确认决定及替代关系；只读请求交回建议。

生产实现／TDD 交给 `worker-implement`，据图实现与视觉对照交给 `worker-ui-fidelity`，独立验证／审查交给对应 worker 或指定执行者。后续若必须偏离已确认视觉关系，应标明原因和范围，实质改变方向时返回设计；本技能不继续调度整条交付链。
