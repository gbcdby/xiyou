# 游戏 UI／UX 通用决策手册 · 从原则到可执行动作

**用途**：在风格探索、信息量变化、复杂操作或用户测试出现问题时，选择合适的设计方法。不是通用页面模板，也不预置任何产品功能。

## 0. 先区分四层问题

| 层级 | 应回答的问题 | 不应混淆的内容 |
|---|---|---|
| 视觉气质 | 这个世界怎样表现形体、色光、笔触、材料与情绪？ | 用户能否成功完成任务 |
| 信息架构 | 当前目标需要哪几类信息？关系与优先级为何？ | 元素的皮肤颜色与材质 |
| 操作语义 | 是查看、选择、展开、导航、预览、承诺还是撤销？ | 箭头或底板画得是否精致 |
| 可靠性与可访问 | 成功何时成立？变化／失败／输入限制下还能用吗？ | 只凭静态截图宣称可用 |

把每条反馈归类再改，避免为了修复阅读而全局降低饱和度，或为了增加气质而在全部控件上叠装饰。

## 1. 设计问题 → 方法选择（条件化）

| 玩家／评审的现象 | 优先选用 | 最小动作 | 排除式反例 | 验证手段 |
|---|---|---|---|---|
| 第一眼找不到主体或下一步 | GP01 + GP02 | 标明焦点、行动条件、阅读面 | 不是所有环境都应取消信息 | 任务找入口，记录漏读与误点 |
| 图片漂亮但正文困难 | GP02 + GP10 | 在构图期预留可调的稳定信息层 | 不是对全图加不透明卡片 | 实际尺寸、明暗最差背景、增字测试 |
| 换色或换人物像另一个产品 | GP03 | 固定字体/图标/状态语法，开放人物与色域 | 不是套统一滤镜 | 2 种明显不同视觉主题交叉复查 |
| 操作太复杂、手势混淆 | GP04 + GP10 | 减少独特手势，保留等效输入 | 有成本的决定仍需确认 | 首次与重复任务、替代输入测试 |
| 点击后不知道结果去哪了 | GP05 | 将过程、已确认结果、回查位置连在一起 | 演出≠服务器确认 | 失败、断网、重入、无动效检查 |
| 功能过密，展开后迷失 | GP06 | 区分导航／展开／提交，保留上下文 | 不任意隐藏必须比较的事实 | 开关、进入、返回、继续任务 |
| 候选太多难以取舍 | GP07 + GP09 | 相同字段比较、解释推荐限制 | 不擅自提供“最佳” | 两个有取舍候选的决策任务 |
| 条件不足却不知怎么办 | GP08 + GP11 | 真实缺口、可用来源和回路 | 不虚构收益／入口 | 从缺口到下一步再返回 |
| 叙事留白与必要说明冲突 | GP11 | 把世界未知与交互未知分开 | 成本、退出等不能做谜题 | 故意不给提示时的理解检查 |
| 视觉很治愈，但过程很吵 | GP12 + GP05 | 按任务压力分级反馈 | 不能隐藏真实紧迫性 | 重复任务与并发打断走查 |

模式定义与边界见 [12 个模式](game-ui-ux-patterns.md)；来源证据见 [20 案例库](game-case-library.md)。

## 2. 八项可复用设计问答

1. **角色**：这个元素是情绪性、信息性、交互性，还是同时兼具？谁优先？
2. **显著性**：哪一个状态必须立即发现？哪些可以次级呈现？
3. **结构**：玩家要比较还是顺序阅读？当前焦点和返回关系是什么？
4. **动作**：同一符号在不同位置是否同义？可见状态是否映射真实能力？
5. **内容增长**：长文案、更多位数、不同语言和高字级会挤压什么？
6. **差错**：操作失败、结果不明、任务打断或离开后会怎样？
7. **身体情境**：手指遮挡、左右手、触控与辅助技术是否能完成同一目标？
8. **验证**：哪条证据可以证伪设计选择？已测／未测如何标注？

## 3. “自然融合但可读”的冲突处理

当漂亮的场景与文字互相争夺注意力，按从少干预到多干预的顺序试验：

1. **构图挪密度**：将树枝／石纹／亮斑移出预留文字区。
2. **降低背景局部对比**：只淡化信息下方的小范围肌理，不降低全图色彩。
3. **局部色面承托**：使用与环境同材质、同光色的轻盈表面；没有必要不添加大面积矩形框。
4. **增强前景**：选择合适字重、文字色、符号轮廓；保留文字和含义不透明。
5. **可配置辅助**：对不可避免的动态或复杂背景提供更强承托／高对比选项。

第 1–5 步都应以实际图像（尤其颜色反差最差的位置）验证。背景透明、发光或动态会改变真实对比；不能仅用“风格统一”宣布可读。

## 4. 任务状态与美术状态分离

- 视觉是同一套画法，但**可点击、选中、不可用、进行中、失败、确认结果、结果未知**不可共用无意义灰态。
- 颜色不是唯一状态通道；文字／形状／位置／线型至少再有一种有效区别。
- 装饰动画仅标识反馈，不得冒充实际账目或业务结果。减少动效也能获知结果。
- 世界内信息、贴近对象的指标可以提升氛围，但不应牺牲可读、焦点或退出能力。

## 5. 平台与标准：引用前判断适用性

- [WCAG 2.2 · 文本最低对比](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)：一般文本 4.5:1、大文本 3:1，适用于相应 Web 范围；不要把这些阈值当作所有游戏或硬件的自动“认证”。
- [WCAG 2.2 · 非文本对比](https://www.w3.org/WAI/WCAG22/understanding/non-text-contrast.html)：关键控件边界／状态线索与相邻色建议按 3:1 核验，尤其小图标不宜只有细淡线。
- [Android · 触控目标](https://support.google.com/accessibility/android/answer/7101858?hl=en&ref_type=adv)：至少 48 dp 的建议。**dp≠图片像素**。
- [Apple HIG · Accessibility](https://developer.apple.com/design/human-interface-guidelines/accessibility)：iPhone 触控目标指导值 44×44 pt。**pt≠dp**。
- [Xbox Accessibility Guidelines 102 · Contrast](https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/102)：游戏内环境复杂时检查最不利底色；可调承托是可行解决方法之一。XAG 是实践指南，不是法律合规认证。

**测试分层**：项目字色对比计算 → 实际背景静图 → 真实设备与字体缩放 → 交互原型（输入与状态）→ 玩家任务观察。上一步通过，不能取代下一步。

## 6. 用“决策记录”沉淀而不是堆规范

```text
问题：谁在何种状态下，不能完成什么？
证据：来源 ID／截图／用户反馈，观察和推导分开
候选：A、B、（不修改）的比较理由
采用：选哪一条语法，什么内容可以变化
不适用：在哪些输入、设备、任务和特殊状态下失效
验证：目标、样本或测试状态、通过/失败证据
结论：已采用 / 待原型 / 待设备 / 待用户测试
```

需要的案例由问题决定，不要求每个项目都做 20 个。效果图只支持视觉推断，不支持网络交易、任务完成率或触控达标的肯定断言。
