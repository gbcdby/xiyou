# 设计资料的落点与分工

先定位项目已有共享 Spec、设计体系、页面合同、组件和素材索引。把新结论写入其权威位置，并从已有入口链接；不因使用本技能搬迁文档、复制任务板或另建平行规格库。小任务可只补充现有合同的一节。

| 内容 | 维护位置与边界 |
|---|---|
| 目标、产品行为、共同约束、验收 | 共享 Spec；视觉设计引用它，不另写一套业务定义 |
| 跨资产画风、色光、材质和排除项 | 美术总纲或项目相应章节 |
| 跨页组件、字体、状态与导航共性 | 现有设计体系／公共组件合同 |
| 页面布局、内容、操作和局部例外 | 对应页面合同，保留有效修订 |
| 精确 token 与真实能力 | 项目指定的代码或配置真源；确认目标尚未实现时分别标明 |
| 参考、决定理由、验证与替代关系 | 现有素材／设计记录；链接合同，不复写全部规则 |

## 可选模板与资料 CLI

没有合适记录位置、且任务确实需要持续管理美术参考时，可采用 `docs/design-direction/`；它只是 CLI 的默认目录，不是使用本技能的前置条件。已有其他资料目录时用 `--docs-dir` 指定兼容位置；不为运行工具改造共享 Spec 的结构。

`assets/project-template/` 提供可选的方向简报、总纲、人物／环境／色彩／界面视觉／动效／一致性提示，以及参考 manifest 和索引。`init` 会一次补建这套模板及参考目录，只补缺、不覆盖；只需要一条规则时直接编辑已有文档，不运行 init。项目无需涉及的专题可以不采用。

`assets/learning-template/` 提供事实、偏好、决定的简表；按需取用相关部分，既有索引只合并必要入口。验证模板在 `assets/validation-template/`，可填入已有页面、Spec 或原型记录，不要求另建日志文件。

原图、浏览总览、manifest、逐图观察有不同职责：保留可定位原图，manifest 管编号与哈希，观察记录采纳范围及证据。生成候选与原参考分别标注；项目参考保留在项目资料内，不写入通用技能。

只做整体画风时不创建页面合同；进入具体界面任务后按 [界面设计](interface-design.md)细化。反馈与复用按 [项目学习](project-learning.md)处理，CLI 用法见 [维护与工具](iteration.md)。
