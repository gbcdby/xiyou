# 风格与 UI/UX 迭代实验室（通用可复现）

## 什么才叫“已验证”

| 层级 | 证据与可声称的结论 | 不可声称 |
|---|---|---|
| 文件级 | ZIP 有效、来源哈希一致、引用正确、色板格式有效 | 风格好看、交互好用 |
| 色值级 | 指定的前景／背景对比达到计算阈值 | 图片叠加后的对比一定合格 |
| 静态视觉 | 缩略／常规／局部下能看见哪些优点与缺点 | 触控、加载、业务结果、用户完成率 |
| 可点击原型 | 指定版本下能否找到入口、完成操作、返回 | 全平台和所有设备都通过 |
| 实机与辅助操作 | 特定设备／字体／输入方式的观察结果 | 未覆盖人群与未知设置 |
| 用户任务研究 | 有任务、样本、条件与观察记录的结论 | 无控制条件的普遍因果提升 |

## 按问题选择视觉实验

按本次不确定性选相关样本，不要求五类全部执行。

1. **主体焦点**：同场景更换人物体型、衣色和饰物；验证身份鲜明与线墨一致性是否同时成立。
2. **场景换气氛**：同主体置于暖光／冷光环境；观察局部固有色与远近层次是否自然。
3. **图标同族**：同类功能语义做一组约束：视角、轮廓权重、简化层次、材质、状态；缩小观察识别。
4. **艺术信息共存**：一幅高复杂背景上预留两种阅读承托，不改变文字内容；检查最不利背景和信息可读性。
5. **内容弹性**：用长文本、高位数、增字、字体放大、多设备纵横比做压力测试；不以缩小到不可读为解决方法。

## 先区分诊断与方向探索

- **诊断局部成因**：围绕待验证的主要变量比较，尽量保持其他条件一致。生成工具若同时改变人物、构图或文字，记录漂移，不能继续声称严格单变量。
- **探索整体方向**：用户希望重新设计或已授权重构时，允许构图、信息层级、人物与控件关系共同变化。先列业务能力和真实状态等共同要求，再明确自由度；比较各方案的整体效果与取舍，不把效果归因于单一颜色。
- **多方向的差异要对应问题**：整页问题应比较空间组织、阅读顺序、艺术与信息的关系等实质差异；单纯配色探索才可保持布局只换设色。不默认每次都要三版，也不为凑差异改动无关业务。
- **参考图按用途输入**：分别标明风格参考、功能资料和必须保留的视觉基准。旧图反复诱发已排除的布局时，可改用业务清单、文字构图与风格参考出图；已确认且仍适用的约束继续保留。

为每轮保存条件、版本、样本文件、可见缺陷、修改以及复检结果。局部迭代持续未改善时，复核问题假设与允许改变的范围，不把同一种调色反复加重当作进展。

## 多尺度人工审核

- **整体缩略（如 10%）**：主次与阅读顺序是否清楚，艺术与 UI 强调是否互相争抢？主要色面是否有序？系列气质是否成立？
- **模拟实际阅读**：文字是否在平静底面？图标是否识别？入口是否与背景融合而非消失？
- **局部放大（如 200%）**：脸手连接、衣层结构、图标轮廓和材质细节是否准确？
- **最差背景**：透明叠色、亮斑、暗纹、山石／树枝紧贴文字时是否破坏对比？
- **跨场景／主题（适用时）**：相同符号和状态是否跨不同色域同义？不新增产品未支持的主题。

记录建议使用 `[项目 / 参考 ID / 输出 ID / 测试变量 / 检查尺度 / 有证据的观察 / 修正动作 / 复测结果 / 未测范围]`，可直接复制 [实验记录模板](../assets/validation-template/visual-experiment.md)。

## 静态图像检查器能做和不能做的事

脚本可读取文件尺寸、明度分布、简单色彩分布，但无法自动判定“精致”“仙气”“酷”或是否是符合规则的用户交互。色彩比例是诊断性统计值，不应变成强制阈值；对部分图片的检查也不等于全套产物通过。

## 完成门槛

- **资料型交付**：检查本次改动的引用与文件完整性；采用捆绑工具的数据格式时可运行相应脚本。没有新图时说明未进行新图验证。
- **风格规范自测**：用能覆盖本次主要不确定性的代表样本检查，记录反例与适用范围；跨资产规则需要相应资产样本，单张图只支持该图范围。
- **可交互 UX 宣称**：必须另有可点击原型／实机或任务测试，不得从“界面看起来有条理”直接推断。
- **审美选择**：评审者可给偏好反馈，但没有样本的喜爱程度不能伪造为“多数玩家选择”。
