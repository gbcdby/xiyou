# 项目认知、偏好与设计复用

在任务中读取、更新可复用的设计知识。沿用共享 Spec、规范和页面合同的唯一维护位置；本方法不建立后台学习任务，也不要求新增目录或逐轮日志。

## 开始任务

1. 从现有设计入口读取相关事实、有效偏好、规范与组件，不加载所有历史。
2. 核实可能过时的平台、预算、组件和实现，以位置与修订说明现状。
3. 分清已确认且适用、仅局部适用、待验证和冲突。用户当前明确指令优先；未说明全局变更的反馈保留原范围。

## 把反馈变成有边界的记录

| 反馈 | 可以记录 | 不能推出 |
|---|---|---|
| “这个背包太空，物品再紧凑些” | 当前背包需要提高信息密度 | 整个产品永远高密度 |
| “全项目不要这种厚重底板” | 此项目排除该材质语言及受影响规则 | 用户所有项目都排除底板 |
| “就用 B，保留 A 的标题” | 本轮采用的组合及范围 | B 的全部行为和布局都获认可 |
| “这批画风和布局考量没问题” | 本批方向与设计考量获认可 | 某张图、精确坐标、入口迁移或实现授权均已确定 |
| 多次选相似方案但未说明原因 | 有依据的偏好假设 | 已确认永久偏好 |
| 用户没回复、图片已下载 | 没有新增偏好依据 | 默认采纳或长期入库授权 |
| 设备误触、长文案遮挡 | 指定条件下的可用性问题 | 所有人都不喜欢该视觉风格 |

只保存用户明确表达的对象与上下文，不虚构原因；仅在当前决定依赖未知原因或范围时澄清。agent 提案、授权内的设计选择、用户确认和实测结果分别注明来源，不能用“已采用”伪装成用户已确认。

## 最小记录

在已有合同或决定条目中保留：内容、适用范围、来源与日期、当前状态、落地／复用入口和替代关系。重要长期条目可用稳定 ID；不要求小改动新建编号体系。

- **事实**：项目目标、场景、平台、约束与真源。链接 token 和组件，不复制整套数值。
- **偏好**：明确评价与排除项，使用者／角色已知时记录；推断标待验证。多人偏好保留各自范围和当前项目决定，不机械平均。
- **决定**：问题、相关候选、选择理由、决定者、验证和替代对象。图片采纳与运行验证分开；无新结论不添条目。

需要表格时取用 `assets/learning-template/`，需要研究记录时取用 `assets/validation-template/` 的相关部分。只记录任务相关内容，不保存无关聊天或敏感资料。

## 回写唯一真源

仅在本次写入授权内更新；明确的只读分析／审查请求只交回建议。已有授权内记录确认决定无需再问“是否允许记住”。

| 确认对象 | 更新位置 |
|---|---|
| 全局画风、材质、色彩关系 | 美术总纲／相应规范，保留范围与排除项 |
| 精确颜色、字级、时序 | 对应 token 合同与实现入口；未接入的值标“确认目标／待实现” |
| 跨页组件与变体 | 公共组件合同及复用索引，链接素材、采用原型或实现 |
| 页面布局、交互和局部动效 | 对应页面合同，不改写权威业务机制 |
| 偏好、理由和替代关系 | 现有决定／偏好记录，链接上述落点 |

当前页面保留一份有效合同，合并仍有效的行为、字体、数值、素材和例外，不逐轮堆叠“覆盖上文”。旧决定标明替代关系，历史使用项目现有记录；压缩历史不能删掉仍有效的约束。待审草案与已合入实现分别标状态。

## 交付前核对

- 新结论能从既有入口找到，范围与来源清楚，未把局部确认扩大为全局默认。
- 当前规范和复用入口一致，旧规则有替代指向；写入没有覆盖并行任务的决定。
- 新样式说明复用现有组件／变体的方式，尚无实现时指向已确认视觉规格。
- 采纳、设计自查、平台运行和真人任务各自有真实状态；没有证据的内容保持待验证。

交付说明沉淀了什么、适用哪里和剩余问题。后续任务涉及旧条目时复核来源与适用性，不定期重写全部文档。
