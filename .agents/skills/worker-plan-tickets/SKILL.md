# 把规格拆成可执行任务

保留共享 Spec 的设计含义，把具体工作交给能独立执行和检查的 Tickets。只完成本次规划职责，按已有授权保存到项目使用的记录位置。

## 1. 固定输入与权威记录

- 读取 Spec 的有效修订、目标、共同约束、验收条件、已确认决定和现有 Tickets；沿用稳定编号。
- Spec 保存设计概览、共同约束、整体验收与 Ticket 目录。Ticket 保存本任务的输入、范围、产物和验收，引用 Spec，不复制整份设计。
- 确认 Spec、任务状态、依赖和证据各自的权威来源。记录 `spec_ref` 的位置与真实修订；缺少版本机制时使用实际内容摘要或可重建快照，不编造修订号。
- 复用已有工作规则、决定和授权。不能从资料确认的设计冲突交回设计负责人；继续规划不受影响部分，不替产品作选择或为每张票增加人工确认。
- 小任务可直接使用现有 Ticket 或紧凑工作单；不强制补造大 Spec、固定层级或新看板。没有其他 Skill、协作房间或特定语言工具仍可完成规划。

## 2. 按交付结果拆分

每张 Ticket 应有明确结果、必要输入、限定范围和可检查的完成条件。优先形成贯通行为的最小切片；仅在有独立负责人、前置产物或验收价值时继续拆票，不把每个实现步骤变成独立任务。

| 逻辑字段 | 需要记录 |
| --- | --- |
| `ticket_ref`、`spec_ref` | 稳定任务标识、所属 Spec 及有效修订 |
| `acceptance_ids` | 本票覆盖的需求或验收编号 |
| `scope` | 允许修改的边界、相关共享资源和明确不含的内容 |
| `depends_on` | 前置任务、所需产物及解除阻塞的条件 |
| `deliverables` | 代码、接口、迁移、文档、检查结果等实际产物 |
| `completion_condition` | 本票完成所需检查与交付终点 |

字段可映射为现有 Issue 正文、关系或其他记录，不要求特定 JSON。已知负责人沿用；未分派时记录所需能力，不虚构接单或独占权。

按风险纳入集成验收、兼容与迁移、必要文档和运行检查。每项整体验收应能追到负责的 Tickets；跨模块性质需要集成检查，不能仅靠多个局部任务完成来代替。

## 3. 建立依赖与并行边界

1. 每条硬依赖写清原因、需要的产物及其版本条件，例如“接口约定已固定并可验证”。编号顺序和父子关系不自动形成依赖。
2. 区分前置产物可用、本票交付完成、整体 Spec 验收。阶段产物可按约定释放依赖，不自动关票；需要合并后才能使用的产物明确写明。
3. 检查缺失引用、自依赖和循环；发现循环先查共同产物或切分错误。调整切分不得改变设计承诺，未解除的循环不得标为可执行。
4. 对照同仓其他活动工作，检查目录、接口、迁移和实际使用的环境。独立目录中的兼容修改可并行；真实冲突才指定共同基础任务、负责人或串行条件，不因同文件重叠阻塞整个 Spec。
5. 保留一处依赖记录，Spec 图和各 Ticket 视图引用它。不要分别维护几套会互相矛盾的图和清单。

可以列出按当前资料判断的起始候选与阻塞原因；这只是规划快照。总控在实际分派前重新核对依赖、所有权、权限和当前状态。

## 4. 保存与修订

- 只使用实际可用且获授权的接口。GitHub 可用父子 Issue 和 blocking 关系；工具不支持时使用明确引用与 `blocked_by` 等项目字段。
- 协作服务的原生任务管理须核实已可用并由项目选定；只有通信能力时，引用外部权威记录。遵守项目既定分工，不自动双写两份正文或状态。
- 无写入能力或仅要求草案时，返回可交接的任务计划；临时编号标为草案，不伪造平台 Issue、写入成功或领取状态。
- 改已有任务前重读当前记录，保留他人的有效内容。Spec 变化时列出受影响的 Tickets、依赖及证据；沿用稳定 ID，保留替代关系，不通过改写旧证据伪装仍然有效。
- 完成规划不领取任务、不启动实现、不把他人的任务改成完成，也不关闭 Spec、合并 PR 或发布。后续工作交回总控或调用者。

## 5. 核对与交接

用 [任务计划模板](assets/plan.template.md) 的必要部分，或等价紧凑文本交回：

- 有效 Spec 与任务记录位置，已实际保存的内容或尚未写入的草案；
- 验收覆盖、依赖和释放条件、并行冲突、集成验收安排；
- 未决设计、缺失输入、受影响范围和建议下一步。

`COMPLETE` 表示约定范围的规划和检查已完成，明确标注的待决条件仍可阻塞部分任务；不表示所有任务已就绪或 Spec 已交付。无法形成一致任务图时返回 `INCONCLUSIVE`；缺必要输入或访问时返回 `BLOCKED` 并保留已完成部分。仅计划的运行检查标为 `NOT_RUN`。

仅接收方需要机器记录时，按 [任务计划模板](assets/plan.template.md) 的交接约定提供。
