# 设计与验证契约

## 任务

- 项目 / 功能：
- 模式：design / check / align
- 用户需求及已确认规则的来源：
- 设计边界及适配记录：
- 现有源码内容标识（无代码写 NOT_ASSESSED；有代码须含相关未提交和新增文件）：

## 调用方与设计决策

- 真实调用场景和可观察结果：
- 接口输入、输出、错误及未知结果：
- 状态所有权、生命周期、提交与外部效果边界：
- 关键结构选择及理由（无实质权衡时不强制多方案）：
- 方案是否依赖尚未确认的条件：
- 验证工具选择及未覆盖的代码级问题：

## 需求到性质

| 需求 ID | 必须满足的业务保证 | 性质名 | 类型 | 启用配置 | 未覆盖项与接收方 |
|---|---|---|---|---|---|
| R1 | 填入实际保证 | 填入实际性质 | safety / liveness / reachability | 填入配置 | 无或待处理义务 |

`TypeOK` 单独检查，不能替代业务性质。无代码时不要伪造实现位置或测试结果。

## 模型边界

- 状态、参与者与动作：
- 可交错 / 可故障的步骤：
- 原子性义务与已核实依据（拟议要求与真实机制分开）：
- 持久化、提交、确认与外部效果：
- 并发、重试、重复、丢失、乱序、故障与恢复：
- 活性依赖的调度、公平性和环境条件：
- 有限规模、抽象方式与排除行为：
- 合法终止与死锁的区分：
- 关键路径可达证据：
- 关键性质敏感性证据 / 未完成项：
- 未确认条件及其影响：

## 基线与变更

- 需求 / 设计 / 模型 / 配置内容标识：
- 新增、删除或修改的性质：
- 假设、规模、检查选项变化及理由：
- 业务保证变化及决策依据：
- 旧证据失效范围：

## 检查计划

记录实际配置、预算和待解决风险。有限配置只支持其明确范围；计划不等于实际结果。
