# 设计与形式化验证交接

## 接收方先读

- 目标功能和用户需求来源：
- 交接文档版本 / 内容标识：
- 关联契约、项目适配记录和设计决策：
- 当前模型结果：PASS_WITHIN_SCOPE / COUNTEREXAMPLE / INCONCLUSIVE / TOOL_ERROR / NOT_RUN
- 实现对应状态：NOT_ASSESSED / PARTIAL / GAPS_FOUND / ASSESSED_WITHIN_SCOPE
- 阻塞问题与尚待决策项：

本材料可交给任意实现者。材料完整不代表模型通过，更不代表业务实现已经完成。

## 必须保持的业务保证

| 需求 ID | 业务性质（自然语言） | 模型性质 / 证据 | 依赖的环境条件 |
|---|---|---|---|
| R1 | 精确业务保证 | 性质名与实际结果 | 已核实 / 拟议 / 未知 |

## 实现语义义务

| 义务 ID | 必须满足的语义 | 关联需求 / 模型动作 | 实现方需提供的依据 | 不满足时的影响 |
|---|---|---|---|---|
| O1 | 原子性 / 身份 / 持久化 / 顺序等具体要求 | 稳定关联项 | 实际机制与针对性证据 | 影响哪些保证 |

## 可自由选择与须返回讨论的事项

- 可自由选择的语言、框架、模块、存储或机制，以及选择成立的条件：
- 接口 / 状态所有权 / 错误语义已确定的部分：
- 尚未决策或待确认部分：
- 不可无说明改变的业务保证、环境假设或检查范围：

## 模型与可复现证据

- 模型 / 配置 / manifest 路径及摘要：
- 工具版本、摘要与实际运行命令：
- 完整结果、原始日志和反例位置：
- 有限规模、启用性质、故障与公平性条件：
- 可达性与敏感性检查证据 / 缺口：
- 有源码时的评估内容标识（含相关未提交与新增文件）：

## 实现方的回归场景

| 场景 ID / 需求 | 初始条件和输入 | 关键交错 / 故障顺序 | 应观察的业务结果 | 所需控制能力 / 证据来源 |
|---|---|---|---|---|
| C1 / R1 | 具体条件 | 可重复的步骤 | 独立于实现算法的断言 | 能力和原始反例 |

这里是测试规格；实际编写、执行与通用代码审查由接收方安排。未提供真实测试证据时保持 NOT_RUN。

## 返回验证的条件

- 状态转移、参与者、并发度、原子性或持久化边界变化：
- 消息、重试、取消、崩溃恢复或外部效果语义变化：
- 关键需求 / 环境条件 / 运行语义变化：
- 实现方无法满足某项义务或发现新交错：

接收方返回：实际修改内容标识、覆盖文件与符号、义务到机制的映射、已运行测试证据、语义变化及未解决问题。由用户选择是否进入 align，不自动调用后续 skill。

## 未覆盖事项

逐项说明尚未检查的性质、代码级问题、无法执行的配置和证据缺口，不用模型通过覆盖这些状态。
