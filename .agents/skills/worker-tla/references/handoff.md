# 设计与验证成果交接

将设计、性质和实际模型检查证据交给实现方，使接收方无需猜测隐藏假设即可开始工作。默认完成中立交接文档后停止。
接收方可以是开发者、另一 Agent 或外部实现工具；本技能不安装、探测、调用或编排接收方工作流。

## 工作模式与停止位置

| 模式 | 工作范围 | 交付与停止位置 |
|---|---|---|
| `design` | 理解需求与系统，设计接口和状态边界，建立模型、性质及检查配置 | 交付设计、可执行模型、实际证据或未运行原因及交接说明 |
| `check` | 核对已有模型与性质，运行检查，分析反例并在授权范围内修正模型 | 交付检查结论、范围变化、原始证据及尚未解决的问题 |
| `align` | 仅在用户明确请求时，只读核对指定源码与模型语义的对应 | 交付具体对应依据与缺口；把实现修复事项交给实现方 |

各模式均不进入业务代码实现、真实代码测试编写、通用代码审查或应用操作验证。
可以读取相关现有源码、测试和设计资料来了解系统，但不能把阅读记录说成运行过测试或完成了 `align`。
用户未请求 `align` 时，将实现对应标为 `NOT_ASSESSED`；设计和模型检查可以独立交付。
接收方自行选择其开发与审查流程，本技能不为交接附加工具安装、工单操作或提交发布步骤。

## 交接记录与必要输入

沿用现有记录，用 [handoff](../assets/handoff.template.md) 作为接收方入口；已有等效文件时复用它，不重复维护同一事实。
详细依据连接 [contract](../assets/contract.template.md)、[project-profile](../assets/project-profile.template.json) 和 [report](../assets/report.template.md)；仅在 `align` 时填写 [implementation-map](../assets/implementation-map.template.md)。

| 内容 | 必须让接收方知道什么 | 记录位置 |
|---|---|---|
| 任务与模式 | 目标、范围、排除项、design/check/align、原始需求来源 | contract |
| 项目事实 | 语言、运行时、并发与持久化机制中已查证的事实、依据及未知项 | project-profile |
| 调用契约 | 谁调用、输入输出、失败结果、取消与重试规则、兼容性要求 | contract |
| 状态边界 | 状态及所有者、允许转移、提交与副作用边界、可被打断的位置 | contract |
| 业务性质 | 稳定需求 ID、自然语言保证、公式名称、类型、实际启用配置 | contract |
| 模型边界 | 参与者与有限规模、抽象方式、故障范围、公平性、排除行为 | contract |
| 实现义务 | 实现必须保留的语义、依据、可选机制及尚无实现的项 | handoff；align 再补 implementation-map |
| 实际证据 | 工具版本、输入标识、配置、状态、完整日志、反例与未运行原因 | report |
| 交接缺口 | 未决定事项、未验证项、接收方需验证的事实、返回建模条件 | handoff，连接 report 原始结果 |

没有源码或测试也可以交接：使用清楚的调用示例和业务事件描述，源码位置填 `NOT_ASSESSED`，测试结果填 `NOT_RUN`。
已有测试只作为带版本的输入材料；未实际运行时不能作为本次通过证据。
交接字段是文档内容，不是新增 runner 参数；保留 runner 的原始输出。

## 说明业务性质与环境假设

业务性质描述系统应当保证什么；环境假设描述保证成立依赖哪些条件，分栏记录，禁止相互替代。

| 类别 | 应写的内容 | 避免的混淆 |
|---|---|---|
| 安全性 | 任何允许的执行都不应出现的错误，如一次业务操作产生重复效果 | 不能用“消息从不重复”偷偷排除需要防范的风险 |
| 活性 | 在明确条件下最终应发生的结果，如请求最终完成或得到终止结果 | 不能省略调度、公平性、恢复和可用性条件 |
| 类型与可达性 | 状态域正确、关键业务与故障路径确实可达 | `TypeOK` 或不可达的错误分支不能代替业务保证 |
| 环境假设 | 真实依赖应满足的顺序、持久化、失败、重试与原子性条件 | 不能把没有查证的条件写成系统已提供的能力 |

为每项假设注明已核实、设计要求或未知，以及支持它的资料；未知不自动视为成立。
性质变更必须联系需求变化；记录前后差异，不能通过删性质、删故障或缩小范围隐藏问题。
不适合 TLA+ 的数值、内存、解析或渲染要求列为替代验证需求，交给接收方选择对应工具；不得宣称本技能已经验证。

## 区分语义义务与实现选择

先描述接收方必须保留的行为，再说明可自由选择的机制；除非契约已有要求，不指定实现语言、框架或库。

| 语义义务示例 | 可以由实现方选择的机制 | 仍需接收方核实的条件 |
|---|---|---|
| 去重判断与业务效果在失败、重试和并发下保持一致 | 数据库事务、受约束的持久化状态机或其他协议 | 真实故障边界与外部副作用是否仍满足模型 |
| 旧异步结果不能覆盖契约规定的新结果 | 世代标识、版本检查或其他等价机制 | 检查与提交之间是否存在未建模的交错 |
| 资源所有权转移满足唯一性及释放规则 | 锁、消息所有权或原子操作等适合项目的机制 | 作用域、内存可见性、异常和取消路径 |

这些是条件性的候选机制，不表示它们对任意模型都等价；实现方须说明所选机制如何满足相关义务。
模型的原子动作不自动对应一段原子代码；明确哪些拆分需要进一步建模，哪些需要实现方提供真实原子性依据。
把整数范围、内存模型、时钟、序列化、异常和部分副作用等差异列为接收方义务；只展开本任务相关风险。
没有专门语义与 refinement 工作时，交接对应表属于工程说明，不构成源代码形式化证明。

## 交付有限检查证据

为每次检查提供模型／配置与必要依赖快照、内容摘要、工具版本、实际命令、完成状态和原始日志位置。
逐项列出启用性质、参与者规模、故障范围与公平性；“所有检查通过”必须能展开为这些具体项目。

- `PASS_WITHIN_SCOPE`：指定有限模型、配置与性质的检查完成且未发现违反；不推广到任意规模或真实实现。
- `COUNTEREXAMPLE`：存在反例或死锁；交付解释与原始轨迹，不能只给结论摘要。
- `INCONCLUSIVE`：超时、中断或资源不足；保留实际检查进度，不能解释为通过。
- `TOOL_ERROR`：工具、语法、配置或支持范围问题；说明当前无法判断什么。
- `NOT_RUN`：尚未实际执行；交付可运行材料和缺少的条件，不伪造日志。

不适用、未运行与未评估分别记录；真实实现没有经过检查时，模型通过后仍保留 `NOT_ASSESSED`。
如果交付中有旧证据，注明其对应版本及是否适用于当前内容；文件名称相同不是版本一致的依据。

## 描述反例与回归场景

交付可供实现方转写测试的场景说明，本技能不编写或运行真实代码回归测试。

1. 列明参与者、初态、输入、关键事件顺序、故障或取消发生点，以及首次违反的性质。
2. 解释为什么场景属于需求允许的行为；若来自错误抽象或错误性质，说明修正依据。
3. 描述需要控制的顺序或观察点及期望业务结果，区分模型状态与真实可观察现象。
4. 标明修复前后的模型运行结果；真实实现尚未复现时明确写 `NOT_RUN`。
5. 无法直接映射为代码场景时解释差距，指出实现方需补充的控制、观测或环境能力。

保留旧反例及修正后的证据联系；不能靠修改目标保证把同一问题重新描述为成功。

## 只读核对源码与模型

只有用户明确请求 `align` 才执行本节；核对语义对应，不修改业务代码，不进入通用代码审查。

1. 明确源码范围和模型版本；读取相关机制与依赖事实，记录无法获得的资料。
2. 有 Git 时记录相关基线、HEAD，并保存本次范围的 staged、unstaged、untracked 内容及摘要；不能只用 HEAD 标识实际源码。
3. 无 Git 时保存当前相关文件清单、内容快照与摘要；需要比较且缺少旧快照时注明限制，不伪造历史。不要把敏感配置复制到证据目录，只记录必要语义与来源。
4. 将性质、状态和动作连接到实际符号及机制依据，核对原子性、持久化、交错、故障与语言语义。
5. 记录“对应依据明确”“存在缺口”“尚未评估”的具体项目；仅发现某个锁、事务或库名称不足以支持对应。
6. 核对期间源码变化时，使受影响结论失效并重新确定快照；保留未提交与新增内容，不能通过自动提交改变用户工作区。
7. 把缺口交给实现方，说明需补充的机制、事实或回到模型处理的问题；交付后停止。

没有完整对应依据时保留部分核对或缺口状态；不因完成只读阅读而声称代码已测试、已修复或已证明。

## 明确返回建模的条件

要求接收方在以下相关变化发生时返回设计与模型验证，而不是直接沿用旧通过记录：

- 业务保证、验收规则、接口错误语义、取消或重试含义发生变化。
- 原子步骤被拆分，提交点、持久化范围、状态所有权或外部副作用边界发生变化。
- 新增参与者、消息路径、故障／恢复行为，或改变顺序、重复、丢失与调度假设。
- 所选机制无法满足模型假设，或真实执行出现模型未包含的反例。
- 运行时、部署、依赖或数据库语义改变了相关并发、可见性、持久化与隔离条件。

纯代码移动先由接收方确认语义是否保持，再决定是否更新引用；本技能仅在被请求继续核对时推进对应记录。
区分引用同步、模型漂移、实际业务缺陷和阻塞；只有实际核对、无未解决对应缺口且必要检查完成后才推进有效基线。失败或阻塞时仍记录本次评估目标，不用更新摘要替代验证。

## 交接完成检查

确认接收方能从交接材料理解目标、调用方式、性质、假设、实现义务与选择空间，并找到全部原始证据。
逐项保留未验证内容、阻塞原因和返回建模条件；模型检查与实现状态分别表述。
交付后把成果交回调用者，不在本 Skill 内启动接收方的实现、测试或审查流程；若外层还有已授权工作，由外层任务继续。
