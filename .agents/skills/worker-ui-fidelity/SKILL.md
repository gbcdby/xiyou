# 按确认基准还原与验收

先读项目指令、现有设计合同、验收范围和有效决定；采用已确认设计，不把单页图扩成全项目规范。选定本次模式：

| 用户目标 | 工作边界 |
|---|---|
| 检查、比较、验收 | 读取材料、运行取证并保存比较结果；不修改产品代码、素材或设计基准 |
| 照图实现、修正偏差 | 在指定范围实现；有 `worker-implement` 时复用其共享约束、工作区、TDD 和候选规则；否则沿用项目约定，可测试行为先测后实现，外观变化用实际截图核对 |

实现后的视觉检查标为 `self_check`；作为视觉证据提供者，不替代 `worker-review` 的双轴独立审查，不接管全 Spec 调度、PR 或发布。设计冲突只把受影响问题交给 `worker-visual-design` 或指定设计负责人；已有确认、裁决和免图授权直接沿用。`prototype` 等工具仅在实际可用且有益时接入，向其传入本次基准与合同。

## 1. 固定依据，按影响选范围

实际打开确认原图及相关局部，分清页面基准、画风参考和上一版运行图；组合方案标明各区域来源。用确认出处、附件／文件版本或必要摘要固定图像身份。没有确认图时，继续不依赖它的工作；无图动效直接按[运动合同](references/motion-validation.md)验证，不能把该结论称为按图还原通过。

- **单处、低风险改动**：在现有记录中写清基准、候选与环境、受影响检查项、证据及结论即可，可用[短记录模板](assets/fidelity-record.md)。检查相关布局回归，不强制建立 JSON 计划、逐属性空表或新文件树。
- **多状态、跨平台、公共组件或复杂交接**：按[验收清单](references/acceptance-checklist.md)展开受影响区域、属性与状态。需要机器检查覆盖时，使用[独立计划与证据包](references/evidence-bundle.md)，先固定计划，再填结果；八类属性的适用性检查留在该完整计划模式。

在实现或判断前明确目标、来源及允许偏差：区分精确规格、图片量测和视觉近似。没有数值时写对齐、比例、换行等可观察要求，不设通用还原率。基准、范围和容差在本轮保持不变；不能换成实现截图、删检查项或放宽阈值消除失败。有效设计修订另记来源与替代关系，只重评受影响部分。

## 2. 还原约束与真实运行

沿用已有组件、token、字体和素材，核对实际文件、变体、裁切、缩放与叠放方式。影响主体观感的资产缺口列为未通过／待验证；替代品须有采用依据。保持文字、控件、命中区和状态真实可用，不能把整页截图加透明热点当作交互实现。

先校准主要结构、比例和素材，再处理文字、间距与细节。文字依附插画时，把原图局部、裁切缩放、可见区／安全区和文字锚点放在同一坐标映射中，并说明空间不足的退路；不要逐机型凑位置。检查模式仅报告这些偏差及建议。

在实际目标平台运行：Web 用浏览器，原生应用用相应运行环境／模拟器／设备；不能用另一平台的外壳替代。沿用项目账号、数据隔离、设备占用和验证约定。只覆盖产品支持且受影响的组合；适配按实际宽高比、字号与生命周期选代表，分开报告平台结果。字号变更在重新进入／重建后的稳定帧复验，不只看热更新。

## 3. 捕获、阅图与修正

每轮遵循同一闭环，证据写入项目约定位置并保留旧轮次：

1. **复现状态**：记录能重现的入口、动作、平台／视口、像素倍率、字号及适用的主题、语言、安全区；保持内容、选择、展开和滚动位置一致，等待字体、图片与异步内容就绪。
2. **保存原始证据**：捕获前后核对页面独有标识与实际加载版本，排除上一页、白帧、旧图和过渡帧。保留未经编辑的截图、捕获时间、候选／素材身份和复现动作；脏工作树不能只用 HEAD 代表。后续源码或素材改变时重拍受影响状态；未改变部分可按实际关联依据复用，保留原捕获身份。
3. **实际打开对照图**：按[工具说明](references/comparison.md)生成并排图与 50% 叠图，差异图仅用于定位。依次看整体缩略、实际阅读尺寸和相关局部，局部检查后回看全图。记录可观察差异，再按合同判断；文件存在、脚本成功或数值差异小都不是视觉通过。
4. **处理偏差**：说明区域／属性、观察事实、影响、目标和结论。实现模式修正后复验受影响项及关联布局；公共组件、字体、token、素材变化追查相关消费者。检查模式交回证据与建议，不自行修产品。

只作有依据的系统栏／共同区域裁切和等比倍率转换，并保留原图及全图检查。禁止自动平移组件、拉伸画面或裁掉错误区域以降低差异；其他屏幕比例另验适配。工具与人均不能把展示合图的独立缩放当作像素对齐。

连续动效读取[动态验证](references/motion-validation.md)，用连续片段检查中间帧、起停、反向、层级和生命周期，静态截图不能替代。两轮针对同一偏差无改善时先查基准映射、字体／素材、约束与状态；没有进展或缺环境时交出具体阻塞，不因耗时结束而判通过。

## 4. 交付结论与证据

优先展示一张“确认图左、当前实现右”的合图，注明页面／状态／候选和剩余差异；多状态补总览及必要局部。没有本轮真实运行图时直接说明缺口，不用历史演示替代。

用短表分别报告 **静态视觉、交互、连续动效** 的“通过／未通过／待验证／不适用”；性能仅在任务涉及且有相应测量时给结论。每项写明已检查范围与证据，未测平台、状态或屏外区域不在通过结论内。视觉通过要求适用基准状态已捕获并阅图、关键检查通过、阻断偏差已解决；例外保留接受出处与影响，未知结果不能归入可接受偏差。

交接原图、当前原始截图／录屏、并排／叠图、候选身份、复现方法和未解决项；有上一版时用于查回归，不替换原参考。按现有交接契约返回实现自查或视觉检查结果，构建／功能测试证据另列。设计决定交回现有规范负责人；证据按项目保留规则保存，文件不可访问时明确不可复验，哈希不代表已阅图。
