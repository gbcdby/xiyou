# 按任务实现变更

完成分派的一张或明确限定的一组 Tickets，交出可检查的候选。单独调用时也可按明确目标与验收条件工作，不要求安装其他技能。

## 1. 核对输入与当前状态

- 读取项目指令、当前目标、验收与已有决定；沿用 `work_id`，没有时创建本地标识。
- 有 Ticket 时读取其 `ticket_ref`、有效 `spec_ref`、`acceptance_ids`、`scope`、`depends_on`、`deliverables` 和 `completion_condition`。共同约束以共享 Spec 为准，不靠聊天摘录替代。
- 核对前置产物及其版本确已满足释放条件、当前负责人和写入范围。过期分派、依赖缺口或归属冲突交回协调者；不自行解除阻塞、接管其他票或重排任务图。
- 检查实际工作树、目标文件与调用方，保护用户已有改动。记录基线、设计修订、已知失败和环境限制；不强制 Git。
- 目标清楚、影响局部且低风险的小改动可用紧凑目标与验收条件，不先制造完整 Spec 或票据。项目要求共享任务记录的大功能，缺本批 Spec／Ticket 或有效依赖时交回负责人补齐，不将聊天分工当成已建票。已有授权内的实现选择自行判断；缺口只阻塞受影响部分。

## 2. 选择实际可用的方法

读取 [执行规则](references/execution-rules.md)，发现项目工具链、现有验证入口和依赖约定。优先复用已有能力；按授权补齐必要依赖，不能为获得绿灯绕过限制或扩大全局配置。

使用外部实现或 TDD 技能前核对调用限制、适用版本与前置条件；不通过读取正文绕过人工专用入口，也不补造已确认的测试边界。采用本技能自己的方法时如实记录，不假称调用外部技能。

同一可写工作区保持一个负责人。并行写入使用独立目录；Git 默认独立 worktree／clone 与分支，不能只换分支共用目录。顺序任务可复用，纯只读助手无需另建工作区。

## 3. 小步测试与实现

新增或改变的可测试业务行为默认采用 TDD；文档、文案和低风险样式使用相应检查，不为形式新增测试。

1. 选一项可观察行为并关联验收；先编写、补充或复用对应测试，实际运行并确认失败来自目标行为或公开接口，排除无关环境错误。
2. 只做使该测试通过的最小实现，再运行确认。测试原本已通过时核对覆盖，记录现有能力，不为造红灯破坏实现。
3. 一项行为完成红—绿循环后再进入下一项，保存候选、命令和实际结果。必要小重构在相关测试通过后进行，改后复跑；不强制每轮重构。
4. 测试通过稳定接口验证行为，期望来自需求或独立已知结果，不复算实现、不绑定私有细节。公共 API、异步、数据形状和生命周期变化检查相关消费者；不删有效断言、跳过失败或改需求来制造通过。
5. 出现既有失败先确认是否由本次引入，保留依据；达到工作预算或不再取得进展时，交回具体阻塞和候选，不能把耗尽预算当作完成。

发现共同接口、状态归属、验收或依赖需要改变时，记录事实、影响和建议，交回总控或设计负责人。不要悄悄改 Spec 让实现通过；有效设计修订到达后，只重评受影响工作与证据。

## 4. 固定候选并交接

- 汇总实际改动，包括 staged、unstaged、untracked 和删除。用真实提交、内容摘要或可重建快照标识候选；脏工作树不能只用 HEAD 代表。
- 核对检查证据仍对应当前候选；后续修改使检查失效时重查相关范围。工作树持续被他人改动、无法固定候选时返回 `INCONCLUSIVE`。
- 用 [实现结果模板](assets/implementation-result.md) 或等价短文本返回：Spec／Ticket 引用、候选、验收对应、自查证据、未覆盖项和建议下一步。
- `COMPLETE` 仅表示本次实现和必需自查已完成。必需检查失败用 `FAIL`，证据不足用 `INCONCLUSIVE`，缺必要输入或能力用 `BLOCKED`；尚未执行的工作用 `NOT_RUN`。
- 作者自查不替代独立验证或审查；后续检查可以明确留待相应角色执行。实现完成不自动更新整体交付状态、关闭 Ticket、合并或发布，交回总控或调用者按既有授权继续。

只有接收方需要结构化结果时输出 `work-result/v1`：`schema_version/work_id/skill/outcome/subject/evidence/unresolved/changed_assumptions/next_action`。`subject` 含 `kind` 和真实修订身份 `id`，按需加基线、设计和环境；证据含 `id/locator/scope/status/producer/subject_id`。`next_action` 与 `evidence.scope` 为非空文本，`evidence/unresolved/changed_assumptions` 为数组。静态核对用 `OBSERVED`，旧实测保留原对象和日期；跨版本材料标 `relation: background`。保留原报告，不把计划、历史或静态依据写成当前实测通过。
