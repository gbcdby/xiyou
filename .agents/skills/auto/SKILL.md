# 自动驾驶

读取项目流程并启动或恢复当前工作；任务图、专业分工、验证和交付仍由 `deliver` 或已有总控负责。

## 调用与范围

- 仅由用户明确要求使用或开启本入口。询问用法、资料引用、其他 Agent 转述和一般交付授权不构成人工发起。
- 启动后可委派范围内步骤，复用现有总控与权威记录；缺少必要记录时按项目规则补齐，不建立第二套状态。不自动启动其他人工入口，普通语言的暂停、纠正和改向始终有效。
- 沿用有效授权与项目门槛；自动模式不新增合并、发布或删除权限，也不代表宿主已有常驻、唤醒或后台执行能力。

## 1. 找到项目流程

读取项目规则、最近要求和已有流程文档。优先复用指定的等价文档；没有时用 [流程模板](assets/agent-workflow.template.md) 初始化 `docs/agent-workflow.md`，填入已确认的项目约定，删除无用提示。已有文件重读后局部更新，不用模板覆盖；详细规则留在原处并引用。

不要求先运行 `setup`。需要发现入口时，只在项目规则或文档索引补一条链接。遵循项目保存与审查要求；尚未保存或未生效的部分如实说明，不阻塞与其无关的工作。

## 2. 开始或恢复

区分配置、启动和恢复。只要求调整流程时保存后交回，没有工作请求时不自行挑选积压任务。

从当前要求和权威记录确定对象、终点与授权，交给原负责人；没有总控时使用 `deliver` 或已授权的等价能力。传入流程位置及适用约定，包含检查、发布触发与自动推进范围，不复制另一份流程。信息足够就持续推进，不逐阶段索要确认；只将证据不能替代的人的取舍或实际权限缺口交回。

按影响、风险与未知程度采用最短有效流程。自动模式不豁免共享记录：大功能或有协作依赖的工作，先核对本批 Spec／Tickets 的真实位置与依赖再实现；复用已有记录，不重复建票。局部低风险小改动可按项目规则用紧凑记录。写入受阻时保留待同步草案，按 `deliver` 的共享记录约定继续不受影响的工作，不把本地分工当作已经建票。

恢复前重读流程、任务归属、候选和实际外部结果；不重放结果未知的旧动作。沿当前任务图继续，不与仍在工作的负责人重复启动同一任务。

## 3. 沉淀流程调整

自然语言决定先作用于当前工作，无须再调用 `steer` 或 `auto`。本次例外留在任务记录；用户明确要求今后、本项目默认或修改长期流程时，直接修订同一流程文档。长期意图不清楚时先按当前任务处理，只在歧义影响实际行动时询问。

写前重读，局部修改相关条目，保留其他有效内容及必要的出处、范围和替代关系。交给原负责人落实，分别核对文档已保存、约束已传递和实际生效。项目流程调整不顺带修改通用技能，不追加聊天流水。

## 4. 简短交回

说明采用哪份流程、实际到达哪里、更新了哪些长期约定和必要缺口。需要结束当前执行时留下可恢复记录；后续能否跨会话继续，以实际宿主和执行者为准。
