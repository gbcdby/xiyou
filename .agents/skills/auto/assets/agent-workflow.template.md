# 项目 Agent 工作流程

本文件保存跨任务的工作约定。具体目标、进度和证据留在任务记录；本次明确要求按其范围优先。初始化时填入已知入口，删除不适用的提示，不覆盖已有等价文档。

## 资料与终点

- 项目规则、架构与正式文档：〈已有入口〉。
- Spec、Tickets、依赖与负责人：〈唯一权威来源〉。
- 长期项目知识：〈已有 CONTEXT.md 或等价入口及维护规则〉。
- 默认终点：沿用当前任务或 Spec 的约定；项目已有默认时在这里引用。

## 默认怎样推进

1. 按影响、风险与未知程度选择最短有效流程。目标清楚、影响局部且低风险的小改动直接实现、针对性检查，再走项目要求的最小独立审查和交付流程；可用现有任务或 PR 紧凑记录，不强制新建 Spec／Ticket。
2. 原因不明先做最小调查；接口、权限、迁移或关键状态变化补相关设计和验证，值得建模时再使用 TLA。未知消除后缩短流程，不按行数判定风险，不让用户反复选档。
3. 大功能或有共同约束、依赖交接的工作，先在选定权威来源创建或复用 Spec 与本批 Tickets，回读链接、验收和依赖后再分派。可以逐步设计、逐批拆票；Spec 保留概览和任务目录，聊天分工不代替共享记录，auto 也不豁免。
4. 按实际依赖、归属和写入范围推进，安全独立的工作可并行。同一 Agent 可实现并自查；可测试行为遵循 TDD，文档等使用相应检查。复用仍适用的证据，不因换技能重复检查。
5. 保留项目 CI 与独立需求、标准审查门槛；项目允许时，局部低风险小任务默认一位独立审查者分开完成两轴。再按目标推进 PR、合并或发布，阶段完成不冒充整体交付。
6. 到达目标后回写任务、依赖与 Spec 目录，沉淀可复用事实，并按既有授权清理已释放资源。

由 `deliver` 或现有总控组织，专业方法沿用当前技能和项目规则；不建立第二套任务状态。

记录写入受阻时说明具体失败及原因，保留待同步草案。继续调查、设计、有界准备或已有记录仍适用的独立任务；依赖缺失记录的新实现与分派等待补齐，不静默改用本地任务板，不绕过实际审批。恢复先核对已发生工作与真实记录，只补缺口。

## 检查与发布

只保留适用条目；已有配置写引用，不复制命令或流水线全文。

| 项目约定 | 入口与有效规则 |
| --- | --- |
| 本地检查／CI | 配置或命令入口、触发范围、必需结果及适用候选 |
| 产物与发布 | 来源／构建入口、版本或摘要、交付位置、发布触发方式 |
| 自动推进范围 | 已有授权覆盖的操作与环境，以及实际停点 |
| 发布后检查与恢复 | 适用验收、结果查询及恢复入口 |

没有远程 CI 或发布需求时，注明实际检查与交付方式，不为填表搭建服务。

## 何时需要人

- 已有有效决定和授权继续适用，不逐阶段重复确认；自动模式和本文件不增加合并、发布、删除等权限。
- 能从记录、源码或实际检查查明的事自行查明。只有尚未委托、证据不能替代的人的取舍，或真实权限缺口需要交回；先完成可以自主推进的部分。
- 已有预算、停点与无进展处理约定继续适用；缺口只阻塞受影响工作，不因一次失败扩大成全局暂停。
- 想主动参与大功能前期方向时，可调用 `challenge`，分批讨论关键取舍并保存到共享记录；这不是自动流程的必经阶段，Agent 不自行启动人工入口。

## 汇报、暂停与恢复

- 用简短白话先说结果、影响和必要决定；适合比较或解释关系时用小表、图。详细证据保留链接，不要求人逐条阅读 Agent 对话。
- 自然语言暂停、纠正和改向直接有效。记录已完成效果、在途或未知结果及接续点；恢复先查当前事实，避免重复动作。
- 是否能跨会话、后台运行或唤醒，由真实宿主能力决定；没有执行者时保留交接，不宣称正在持续运行。

## 知识与资源收尾

- 长期知识只保存难以重新发现、后续会用到的项目事实，注明范围、日期和来源；已有正式归属就引用，无新事实不写。
- 清理只涉及本次已释放的临时分支、专属 worktree 和可丢弃材料。按已有授权执行并回读，保留脏目录、未交付内容、共享或活跃资源和仍被依赖的产物；无授权时交回具体清单。

## 后续调整

本次例外留在任务记录；用户明确要求长期生效时，重读后直接修订本文件相关条目，保留必要出处与适用范围。文档保存和工作实际生效分别确认，不累积聊天或运行日志。
