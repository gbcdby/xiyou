# 分支与工作树清理

只处理本次归属明确、用途已结束的临时／topic 分支和专属 worktree，不删除仓库、主线、共用集成分支或正式记录。沿用覆盖本地分支、远端引用或工作区回收的有效授权；合并或关票本身不授予删除权限，创建时已约定用后回收的资源无需重复确认。

## 1. 核对可释放对象

- 取得实际仓库、remote、完整 ref、当前 tip、worktree 路径和使用关系。一项 Spec 完成只释放自己的使用关系；共享、活跃、归属不明或仍被下游使用的对象保留，只处理其余独立资源。
- 核对已合并 PR 的原始候选、目标结果与当前分支内容。普通合并可用提交包含关系；squash／rebase 结合原候选与结果的对应证据，不能只靠祖先关系或 merged 标记。候选之后新增、未推送或未交付的唯一内容没有持久去向或明确弃用决定时保留。
- worktree 检查暂存、未暂存、相关未跟踪内容及目录内需保留的产物，包含被忽略的唯一证据。脏目录保持原状；必要资料先保存到不会随清理消失的位置，单有 SHA 不等于保存了内容。

## 2. 执行与回读

临近操作重读该对象的 ref、版本和归属，变化后只重评该项。使用现有工具的版本条件和项目协调机制；不以 reset、clean 或强制移除制造可清理条件，也不为了清理推送所有本地历史。

在保留的工作目录执行清理，先释放符合条件的 worktree，再处理不再被工作树使用的本地分支；远端分支按其独立状态与授权处理。工具拒绝时核对原因，未证明内容已完整交付或可弃用前不绕过保护。

回读 worktree 登记与目录、本地 ref 和远端 ref，分别记录实际结果，并更新本次使用关系。响应丢失先查询，不盲目重复；远端已由平台删除时按实际缺失记录，本地仍另行核对。

没有授权或暂不能清理时，在既有交付记录列明实际仓库／ref／路径、当前版本、拟执行动作、保留原因与接续条件。清理待办不改变已发生的合并、验收或任务完成事实；不新建清理看板或无期限后台任务。
