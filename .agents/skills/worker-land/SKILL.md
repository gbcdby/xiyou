# 推进 PR 与合并

先确定终点是 draft、pr_ready 还是 merged。保留仓库既有规则和用户已授予的权限，把审查、验证、授权与平台事实分别核对。

## 1. 固定候选与规则

- 读取仓库规则、相关 Spec/Tickets、PR约定、交付终点和实际候选。核对前置产物与合并顺序；只包括本次范围的修改。
- 读取实际仓库平台能力：PR CRUD、检查、审查、队列、合并方式、保护规则及结果查询。没有权限读取某项时记录未知，不能假定无保护。
- 识别已有 PR，优先更新同一逻辑工作；重试创建前按分支/工作ID查重。不要把分支名当不可变内容身份。
- 根据已有用户请求和项目约定确定可执行动作。创建PR、合并、关票、对外评论、删除分支各自有适用授权，不能互相替代。
- 检查推送、tag、合并会触发的自动发布／部署，把实际效果纳入授权与停点判断。既有授权覆盖就继续；有缺口则先完成其余准备，交回具体动作和影响，不能先触发再称只是合并。
- 使用 [候选检查表](references/candidate-and-evidence.md) 固定集成对象、证据与当前授权。

## 2. 准备可审查变更

1. 归纳问题、改变的行为、范围、验证、剩余限制和撤回方式。使用 [PR正文模板](assets/pr-body.template.md)，保持项目语言与格式。
2. 检查 WIP，包括暂存、未暂存与相关未跟踪内容。只审 committed HEAD 的上游组件不足以证明 WIP 已审。
3. 可在有协作价值时创建 draft。草稿允许证据缺口，但必须明确缺口；ready 必须满足约定条件。
4. 需要提交/推送时，先检查实际待提交内容和目标，保留用户改动。使用分支与隔离工作区，不为了通过而重写他人历史。
5. 使用多行结构化参数或正文文件保持原始换行。创建后回读实际 PR 及 head/base，记录其身份。

## 3. 处理反馈与集成

- 将发现按稳定 finding ID、根因、范围、证据、候选版本记录。阻断问题必须修复或按项目规则有依据地处置；不能删除意见来制造通过。
- 实现者修复，独立审查者复核。审查者亲自修改后，修改部分需要另一次独立判断。
- 后续轮次检查新增 diff、受影响依赖和未解决发现；不要无限重报同一问题，也不要漏掉新的影响。
- CI失败先区分实现、测试、环境与临时基础设施故障。不得通过删检查、改门槛或修改已确认契约直接刷绿。
- base 或相关接口变化、解决冲突、rebase、squash、merge 后都要重新评估证据覆盖。按项目要求验证真实组合候选。
- 跨PR依赖不仅是同文件冲突，也包括接口、数据格式、状态语义和迁移顺序。
- 多个 Spec 复用同一 merge queue；没有队列时明确一个集成负责人，按依赖顺序整合。每次合并前重读目标分支并核对实际组合候选；只协调集成，不阻塞独立实现，不强制无关全量重跑。

## 4. 合并门槛

同时确认：
- 当前候选与审查、验证证据相符；
- 适用于当前候选的必需检查确已执行并通过，无未解决阻断；
- 所需人工/系统批准对当前范围仍有效；
- 目标分支、合并方式、依赖顺序正确；
- 当前请求或已有规则授权执行这次合并。

遵守所用第三方能力的调用限制，沿用有效授权。缺少最终授权时，先完成已授权准备，再提交具体 PR、证据、影响与待批准动作。

## 5. 执行与回读

- 发起获授权的合并后，读取平台的真实 merged 状态、目标分支和结果提交。设置auto-merge、进入队列或命令成功仅记录对应事实。
- 合并响应丢失时先查询PR和目标分支，再决定是否重试；不要重复创建或盲目重放副作用。
- 完成仓库规定的合并后检查。若实际已经合并但检查失败，报告“已合并，验证失败/恢复中”，不能改称未合并。
- 需要回退时按已有恢复授权执行；否则准备具体方案。代码revert不自动恢复已迁移数据。
- 合并授权不自动包含关票、删除分支、发布或部署；已授权的后续目标按职责继续。

## 6. 清理本次 Git 资源

交付或资源释放点到达后，按 [分支与工作树清理](references/cleanup.md) 核对实际对象、内容去向和剩余使用者，沿用有效清理授权执行并回读。单独调用也可完成本职责；无授权或条件未满足时，只交回具体待清理与保留项，不重复申请已有许可。

## 结果与交接

默认简短报告实际状态、证据和剩余动作。需要机器记录时按 [结果约定](references/result-contract.md) 返回 work-result/v1；对象绑定真实 PR、候选、基线或集成结果。

有关联任务时，交接 Ticket、合并提交与检查证据、剩余交付条件和接续负责人，交给 `deliver` 或既有任务生命周期负责人。单独调用且没有另设负责人时，当前 Agent 在已有任务管理授权内按 `deliver` 的任务收尾步骤继续；该技能不可用时，等价执行完成条件核对、任务与依赖更新及回读确认。仅获合并授权或缺少写入能力时，明确待更新任务与缺口，不虚构交接已被接收；无关联任务时省略。

清理另报已删除的本地／远端引用、worktree 和具体保留项；保留项注明实际路径或 ref、当前版本、原因与解除条件。

最终明确实际状态：draft、ready、queued、merge_requested、merged 或 merged_with_failed_checks。用户目标未达到时说明剩余动作及解除条件，不把PR链接当完整交付。
