# 接入项目工作流

保存跨任务有用的最小项目适配。日常工作无需先运行本入口。

## 调用与范围

- 仅由用户主动选择，自动路由、子任务或引用资料不构成人工发起。
- 只负责已安装技能的项目适配；安装、更新或卸载走目标环境的正式管理流程。
- 保留现有设置，按本次授权局部修改。不沿用其他项目的工具链、标签或交付规则，不收集凭据、不擅增连接、权限或全局配置。

## 1. 查明已有约定

读取项目规则、目录布局、文档归属、tracker、本地检查、CI 配置及发布入口；核对实际安装的技能和工具 schema，以当前清单为准，不依赖固定数量。

区分可核对事实、已接受决定和尚待选择的设置。已有适配只记录新增、变化和失效项；冲突先查范围与时效，不直接覆盖。文件中定义了命令或能力，不代表已运行、已授权或已实现。

## 2. 确定共享记录来源

沿用有效项目约定；没有决定时根据现有工具给最小可行方案：

| 接入方式 | 保存 Spec 与 Tickets 的位置 |
| --- | --- |
| 已有 tracker 或共享文档 | 沿用现有记录、父子与依赖关系 |
| 协作服务只负责通信 | 消息引用外部权威记录 |
| 协作服务提供原生任务管理 | 核实能力并按项目选择使用；不把愿景当现有接口 |

每类事实只指定一个权威来源，其他视图引用它，不维护两套状态。Spec 保存设计概览、共同约束、整体验收和 Ticket 目录／依赖图；Ticket 保存可执行目标、输入、依赖产物、范围与验收。依赖关系维护一次，进度按实际证据更新。

同时识别项目长期上下文和流程文档，优先复用已有入口。项目事实、架构、流程与任务状态各归其位，只引用已有权威内容；确有可复用知识但无合适入口时，再建立简短项目文档。

记录总控、Spec/Ticket 引用方式、有效修订和结果回传位置。代码、PR 与部署事实分别以实际仓库、托管平台和目标环境为准。没有 tracker 时可用项目已有共享文档；简单任务不强制新建 Spec 或票。

## 3. 接入检查与发布

核对已有命令、流水线和发布机制，引用配置入口、触发范围、必需结果及适用候选；记录产物来源、交付位置、自动触发方式、现有授权覆盖与实际停点，以及适用的验收／恢复入口。已有配置只留引用，项目流程文档补未编码的选择，不复制流水线或日志。

仅在当前目标需要时安排缺失配置：交给 `worker-implement` 实现、`worker-verify` 核验，本入口不代写流水线。不要求项目具备 Git、远程 CI、容器或云发布；本地检查与交付可以是完整终点。

## 4. 只补必要缺口

能从项目查明的事实自行查明，已有决定直接复用。只有不可推断且影响接入的选择才问用户，给推荐、影响和可调整范围；不要发通用配置问卷。

缺少可选房间或技能时用现有能力继续。真正缺少目标所需能力才构成阻塞，不猜合并权限、发布环境或宿主保证。涉及发现路径、调用和限制时读取 [宿主适配](references/harnesses.md)。

## 5. 保存并核验

优先局部更新项目已有适配，必要时用 [适配模板](assets/project-adapter.template.md)。详细规则留在原处，适配只保存入口和链接；`AGENTS.md` 不重复列技能、通用流程或一次任务日志。

首次接入本套件时，取用已安装 `auto` 的 `assets/agent-workflow.template.md`，按已有约定生成 `docs/agent-workflow.md`；已有等价文档则复用。模板资源不触发 auto，也不启动交付。缺少模板时可按现有规则形成等价短文，不因此阻塞接入。流程正文留在该文档，项目规则或索引只补必要链接。

项目尚无上下文维护约定时，补最小规则：非平凡任务先读相关部分；形成跨任务有用的事实时按范围更新并保留日期、来源与验证边界；写前查重、局部纠正过时内容，无新事实不写。独立 worker 同样遵守，无需每次运行 setup。

写入前重读、查重并保留有效内容；重复调用只更新实际差异。按项目要求完成 PR 和独立审查。

核对引用、配置语法、发现路径及与修改有关的最小检查。分开记录静态发现、真实执行、官方说明与未验证部分。人工入口的发现、显式调用及禁止自动调用必须在目标宿主分别核验，配置存在不算运行通过。

## 6. 交回结果

短报复用了什么、改了什么、哪些检查真实完成及仍影响下一项工作的缺口；无必要变更就报告已复核，不制造新文件。setup 不新增后续合并或发布授权。

接收方需要结构化结果时读取 [机器交接](references/result-contract.md)。
