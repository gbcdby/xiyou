# 验证真实行为

对明确候选和范围给出证据支持的结论。按风险选择充分检查，保持执行记录与结论之间的对应关系。

## 1. 固定问题与对象

- 读取项目指令、当前验收、设计假设、历史失败和待验证候选；Ticket 验证关联同一有效 Spec 与验收编号，整体集成另按 Spec 的验收范围判断。
- 沿用 work_id，确定本次必须回答的问题；若输入只是“测一下”，从变更和验收中推导合理范围并说明。
- 记录 subject.kind、真实 subject.id；按需补 base_id、contract_id、environment_id、worktree_digest。
- 工作树验证须包含 staged、unstaged、untracked 和删除；不能只用 HEAD 标识未提交内容。
- 核对检查期间候选是否稳定；共享工作树发生变化时重新固定对象，不能把旧结果归到新内容。
- 说明执行者与作者的关系。自己实现后执行的是作者检查，不改名为独立验证。

## 2. 建立最小验证矩阵

- 从验收条件、变更边界、故障模式和项目门禁选择必需项，不按工具数量堆砌检查。
- 读取实际构建配置、清单、已有测试与 CI；发现正确语言、运行时、工作目录和命令。流水线结果核对事件、配置、候选与适用必需任务，不仅看总状态。
- 阅读 [证据规则](references/evidence-rules.md)，选择静态核对、运行检查、集成或真实宿主实验等适当层次。
- 为每项记录预期来源、输入、方法、环境前提和完成判据，提前标明必需与可延后范围。
- 文档或低风险可逆修改可用事实、链接、语法或渲染核查；不要为其新建逐字镜像测试。
- 模型检查只读取或执行明确的模型验证任务；本技能不替形式化设计环节建立未经说明的模型假设。

## 3. 确认可执行环境

- 记录实际运行时、依赖或锁文件、必要服务、配置以及工具版本；只收集与结论有关的安全信息。
- 环境未知就标未知，不推测安装状态，不收集完整环境变量或凭据。
- 优先已有工具；在已有授权和项目约定内补齐必要的项目依赖或局部工具。升级依赖、购买配额或改变全局配置须符合实际任务范围；已有授权内的项目测试夹具按约定启动并清理。
- 沿用任务已有授权；遇到实际副作用所需权限缺口时完成其余验证，再返回具体阻塞。
- 采用项目的超时与重试预算；没有约定时设置合理有限预算，避免无限重跑。

## 4. 执行并保存原始证据

1. 运行最小直接检查，再按影响范围补必要回归和集成检查。
2. 保存准确命令、工作目录、输入、时间、退出码、原始状态与日志位置。
3. 运行前后核对候选与关键环境身份；有变化则明确该次证据实际对应的对象。
4. 出错时先区分环境未就绪、工具失败、测试自身问题和已复现的产品违约。
5. 只按已知暂态原因或明确策略重试；保存所有尝试，不选取最后一次绿灯覆盖前面的失败。
6. 达到必要覆盖或预算后停止；只为具体剩余风险追加检查。

不要修改业务代码、跳过断言或改写验收来让验证通过；把修正交回实现职责。
需要临时复现文件时遵循项目临时输出约定，保留复现入口，不污染正式交付内容。

## 5. 保留证据边界

- 源码阅读：evidence.kind=source_inspection、status=OBSERVED；只能支持静态关系。
- 运行检查：保留工具原始状态、退出码与版本，再给出对应范围的 PASS 或 FAIL。
- 历史材料：status=HISTORICAL，另存 raw_status、原日期和原 subject_id；不能冒充本轮执行。
- TLC 等模型检查：保留模型、配置、性质、边界和原始状态；不把有限模型结果改写成源码证明。
- SDK 集成：只证明实际 SDK 路径；不推出真实 harness 的唤醒、中断、上下文注入或模型行为。
- 真实宿主：记录实际 harness / 版本 / 模型身份与状态前提；不可见的信息写 unknown。
- 候选、基线、契约或环境改变时重新判断证据适用性；集成门禁绑定实际集成候选。

## 6. 判定并返回

使用 [验证结果模板](assets/verification-result.md)，或返回含同等字段的紧凑结果。
默认简短说明结论、关键证据与缺口；接收方需要机器记录时按模板交接。
原始状态如 OBSERVED 或 completed 本身不表达验收结论；需要时另填 assessment=PASS/FAIL/INCONCLUSIVE/NOT_RUN，限定在实际完成的检查范围，保留原状态和退出码。

| Outcome | 使用条件 |
| --- | --- |
| PASS | 声明范围内所有必需检查完成且满足判据；候选和环境对应明确。 |
| FAIL | 至少一项检查已确认违反当前契约；保留具体反例与影响范围。 |
| INCONCLUSIVE | 已尝试验证，但环境、观测或证据不足，不能确定结果。 |
| BLOCKED | 开始所必需的输入、能力或权限缺失。 |
| NOT_RUN | 本次验证尚未执行。 |

必需项未运行或不确定时不能整体 PASS；不能静默缩小范围来获得通过。
已有产品失败时保持 FAIL，并同时列环境阻塞；纯环境错误不能直接判定产品 FAIL。
若仅部分范围得到结论，分别列出；不要用均分或“多数通过”掩盖缺口。
摘要优先说明结论、证据范围、最大未决项和下一步，原始日志以位置引用提供。
