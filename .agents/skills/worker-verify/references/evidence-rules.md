# 验证范围与证据规则

## 证据层次

先选择能够回答当前问题的最低充分层次；不要为了“完整”无条件运行所有层次。

| kind | 可支持的结论 | 不能据此推出的结论 |
| --- | --- | --- |
| source_inspection | 固定源码、文档或配置之间的静态关系 | 真实运行、时序行为或部署成功 |
| execution | 该候选、环境、输入和检查覆盖的行为 | 未覆盖输入、所有生产环境或不存在其他缺陷 |
| model_check | 指定模型、配置、性质与有限状态范围的结果 | 源码符合模型、无限规模性质或部署正确 |
| sdk_integration | 实际 SDK 客户端路径与服务交互 | 某真实宿主会自动拉取、唤醒或中断模型 |
| real_host | 已记录版本的真实宿主在实际实验中的观察 | 其他宿主版本、未执行状态或未测试模型 |
| historical | 原日期与原候选上的既有报告 | 当前候选本轮已经运行 |

形式化证据记录模型及配置摘要、性质、边界、工具版本、完整/中断状态、反例或日志位置。保留 TLC 原始输出；“未发现错误”不能写成源码证明。模型与实现的对应核验需要独立证据。

真实宿主实验记录 harness、版本、模型实际标识（可见时）、服务版本、状态前提、动作和可观察结果。连接存活、通知发送、消息被读取、进入上下文、触发新 turn、打断执行分别观察，不能互相代替。模型标识不可见时写 unknown，不猜测。

## 执行前的检查表

| 字段 | 最低内容 |
| --- | --- |
| subject | 候选或产物真实身份，必要的 base_id、contract_id、worktree_digest |
| environment | 实际运行时、依赖或锁文件、必要配置、服务与宿主版本；不收集秘密 |
| acceptance | 本次必需回答的问题、预期值来源、必须覆盖与可延后的范围 |
| commands | 来自本项目的准确工作目录、命令、输入、退出判据、必要清理 |
| budget | 有限运行时间、最多重试次数、资源上限；采用项目既定规则 |
| provenance | 谁执行，何时执行，原始日志和产物保存位置 |

无法隔离共享工作树时，至少在运行前后确认内容一致；有并发变化则不把该运行归给最终候选。只记录实际计算的摘要。读不到锁文件或版本时标未知，不自动编造 environment_id。

## 状态判定

| 观察 | 检查结论 | 整体处理 |
| --- | --- | --- |
| 验收判据满足且证据完整 | PASS | 仍检查其他必需项及候选是否改变 |
| 已复现违反契约的行为 | FAIL | 保留最小复现；即使还有环境阻塞也不得藏掉已确认失败 |
| 工具未启动、检查未尝试 | NOT_RUN | 原因与下一步必须明确 |
| 连接拒绝、配额耗尽、依赖缺失、工具崩溃 | INCONCLUSIVE | 定位环境原因；不能单独当作产品失败 |
| 超时、输出截断、偶发失败无法归因 | INCONCLUSIVE | 保存所有尝试；不要以一次偶然成功抹去失败 |
| 必需输入或权限缺失而无法开始 | BLOCKED | 写明缺少什么；不扩大授权 |

Outcome 是检查者对明确范围的结论，evidence.status 是原始观测。执行证据保留工具原状态及 exit_code；静态核查用 status=OBSERVED、kind=source_inspection；历史报告用 status=HISTORICAL 并另存 raw_status、原日期和原 subject_id。

不要把 NOT_RUN、skip、timeout、unknown 或 “没有报错文本”转换为 PASS。历史材料只作背景，不能满足要求本轮执行的门禁。

## CI 结果

绑定实际配置、触发事件、候选、运行与任务结果，核对必需检查是否适用于本次变更并确实执行。总状态绿色不能覆盖必需项的跳过、未触发、取消，或因允许失败而未阻断的失败；按已有规则确实不适用的任务注明依据，不一律判失败。

配置解析、本地命令和远端流水线分别报告。没有远端运行记录时只对已完成范围下结论；发布任务成功也不能替代渠道或目标环境的实际验收。

## 候选和环境变化

- 从 feature head 换成集成候选、基线更新、解决冲突、变更契约或切换环境时，先重新绑定 subject。
- 通过影响分析确认哪些旧证据仍适用，并保留它原来的 subject_id；不能仅改标签复用。
- 必需集成门禁必须针对实际候选重跑；检查新增调用方、测试、适配器和配置是否仍兼容。
- 代码摘要相同也不能替代环境判断；迁移、启动参数、服务版本或外部协议改变会影响结论。

## 命令执行与失败分诊

只运行已发现且获授权的命令；安全地引用参数，避免通过日志、环境转储或命令展开泄露秘密。缺少工具时优先选择现有等价能力；在已有授权和项目约定内补齐必要的项目依赖或局部工具。升级依赖、购买配额、修改全局配置或扩大服务范围须符合实际任务授权；已有授权内的测试夹具按约定启动、隔离并清理。

发生失败后依次确认：命令是否启动 → 环境是否具备前提 → 断言实际观察是什么 → 预期是否来自当前契约 → 候选是否一致。基线对照有助归因但不是硬性前提；无法运行基线时保留不确定性。

只有已知暂态原因或项目明确的重试策略才重试。记录所有运行，不挑选有利样本。达到约定预算后停止扩大范围，返回失败或不确定结论与最小下一步。

只在预定临时目录保存日志或最小复现；不默默修改业务代码、依赖和持久化数据来让检查通过。若验证需要实际外部副作用，沿用已有任务授权；缺少必要授权时完成可执行的部分并列出具体阻塞。
