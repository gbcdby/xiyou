# 恢复与证据

## 动作边界

| 情况 | 应做什么 |
|---|---|
| 构建或前置检查失败，尚未发布 | 保留失败证据，修复或交回，不报告已上线 |
| 发布API超时，外部结果未知 | 查询指定版本/操作/渠道事实，再决定重试 |
| 产物已发布，部署尚未发生 | 保留published事实，不报告deployed |
| 部署发生，验收失败 | 报告实际版本和失败范围，按授权恢复或准备方案 |
| 代码回退完成，数据仍未恢复 | 分别报告，不能把代码健康当整体恢复 |
| 环境无法访问 | 记录BLOCKED/NOT_RUN，提供可核查的剩余动作 |

## 最小恢复计划

记录触发条件、可执行动作、实际授权、目标版本、数据前提、谁负责、如何确认恢复、哪些结果不可撤销。不要假设有备份、feature flag或回滚API；逐项核实。
