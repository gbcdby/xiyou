## 已有产品与技术边界

- 《西游记》多人合作叙事：唐僧与孙悟空跨关持续存在；每局最多五位真人，玩家逐关扮演当地配角。
- 六关当前确定的是机制类型，具体原著篇章和情节尚未选定。第一机制关优先“信任与证据 + 纠纷解决”。
- 协作依赖信息、权限与能力的差异；NPC 可以怀疑、拒绝和改变计划。世界事实、NPC 信念与角色陈述必须分开。
- 前端采用 Vue 3 与 TypeScript；后端语言尚未锁定。采用服务端权威状态与顺序事件，模型通过 Model Gateway 接入。
- 关卡以配置复用机制，按阶段扩展。下一步无需预先完成六关剧情或全部六类能力。

详细依据见[总设计](../初步设计文档.md)与[工程约定](engineering.md)。

## 开发路线

以下承接总设计的 M0–M6，表示推进顺序，不构成工期承诺。

| 阶段 | 交付目标 | 验收重点 |
| --- | --- | --- |
| M0 协议原型 | Session 状态机、事件契约、所有权、控制权及最小 TLA+ 模型 | 并发与重试语义明确，TLC 证据可复核 |
| M1 无 AI 房间 | 2–5 人进入、场景与物品同步、掉线恢复、事件日志 | 五人连续操作 15 分钟，无世界状态分叉 |
| M2 单 AI | Observation → Belief → Goal → Decision → Tool → Action 闭环 | 语言不能直接改世界，行动依据可追踪 |
| M3 双核心 AI | 唐僧与悟空的不同感知、分歧及主动交流 | 玩家行动能够影响两者后续计划 |
| M4 第一机制关 | 信任与证据、纠纷解决 | 一局形成完整协作闭环与可观察结果 |
| M5 第二机制关 | 多人协调、道具交接、承诺 | 检验共同机制能否复用 |
| M6 六关与跨关 | 选关、角色轮换、核心 NPC 状态、跨关记忆与复盘 | 前两关成立后再扩展其余内容 |

各阶段的实际验收由有效 Spec 与任务记录细化；此表不维护重复的任务状态。
