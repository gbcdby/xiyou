# 项目 Agent 工作流程

本文件保存跨任务的工作约定；具体目标、候选、证据和进度留在 GitHub Issue / PR 与有效 Spec。用户当前决定优先于旧文档，自然语言暂停、纠正和改向直接生效。

## 资料与终点

- 项目规则与入口：[AGENTS.md](../../AGENTS.md)、[工程约定](../engineering.md)、[设计资料](../design-direction/README.md)。
- 当前基线与路线：[项目现状](../project-status.md)；产品总依据：[初步设计文档](../../初步设计文档.md)。
- Spec、Tickets、依赖与负责人：[Spec 索引](README.md)、[GitHub Issues](https://github.com/gbcdby/xiyou/issues)、[GitHub 记录约定](agents/issue-tracker.md)。Spec 汇总 Issue 与 Ticket 是唯一活动任务图；聊天分工不算建票。
- 长期知识：产品决定回写总设计或对应 Spec，工程边界回写工程约定，流程变更回写本文件，视觉决定回写设计资料；无新事实不新增总结文件。
- 默认终点：沿用当前用户要求与关联 Ticket/Spec；目前首章体验版入口为 [#66](https://github.com/gbcdby/xiyou/issues/66)，整体验收入口为 [#29](https://github.com/gbcdby/xiyou/issues/29)。后续章节按用户 2026-11-13 决定暂缓。

## 默认怎样推进

1. 先固定有效 Spec 修订、Ticket、候选提交/完整工作树、当前归属和真实外部结果；恢复时不重放结果未知的动作，不与仍在工作的负责人重复启动同一任务。
2. 按影响、风险与未知程度选择最短有效流程：目标明确且低风险的小改动直接实现、针对性检查并走最小独立审查；原因不明先做最小调查；公共接口、权限、迁移或关键状态变化补设计和验证，值得建模时再用 TLA。
3. 大功能或存在共同约束、依赖交接的工作，先在 GitHub 与 `docs/specs/` 中核对或建立 Spec 和本批 Tickets，回读链接、验收与依赖后再分派；逐步设计、逐批拆票，auto 不豁免共享记录。
4. 按实际依赖、归属和写入范围推进；无法安全并行的共享对象由明确协调者串行交接。同一 Agent 可实现并自查，但作者自查不替代独立需求/标准两轴审查。复用仍适用的证据，不因换技能重复检查。
5. PR 按实际证据从 Draft 推进到 Ready 和授权内合并；创建 PR、CI 排队或自动合并设置不等于合并。合并、部署、运行验收和任务关闭分别记录。
6. 达到目标后回写关联 Ticket、依赖与 Spec 目录，确认状态实际生效，并按既有授权清理已释放资源。

由 `deliver` 或现有总控统筹，专业方法由对应 worker 承担，不建立第二套任务状态。写入受阻时保留待同步草案与失败原因；可隔离的调查、设计和已有记录仍适用的任务继续，不绕过实际审批。

## 何时需要人

- 已有有效决定和授权继续适用，不逐阶段重复确认；auto 和本文件不增加合并、发布、删除等权限。
- 能从记录、源码或实际检查查明的事自行查明。只有尚未委托的人的取舍、证据不能替代的体验输入，或真实权限缺口才交回；先完成可自主推进的部分。
- 首章剩余的真实模型配置与费用额度、真人 2 人/5 人复玩、手机真机及视觉素材专项发布属于外部输入；未具备时记 NOT_RUN / BLOCKED，不用模拟或自动浏览器替代。
- 已有预算、停点与无进展处理继续适用；缺口只阻塞受影响工作，不因一次失败扩大成全局暂停。

## 汇报、暂停与恢复

- 用简短白话先说结果、影响和必要决定；详细证据留在 Issue/PR/工作流链接。自然语言暂停、纠正和改向记录出处、范围与恢复条件后直接生效。
- 恢复先查当前事实与在途外部结果，避免重复动作；是否能跨会话后台运行由真实宿主决定，没有执行者时保留可恢复交接，不宣称持续运行。

## 知识与资源收尾

- 长期事实注明日期、范围和来源，归入已有正式文档；临时产物只写 `.agent-output/<agent-or-task>/`。
- 清理只涉及本次已释放的临时分支、专属 worktree 和可丢弃材料，按既有授权执行并回读；保留脏目录、未交付内容、共享或活跃资源及仍被依赖的产物。
- 本次例外留在任务记录；用户明确要求长期生效时重读后局部修订本文件，保留出处与适用范围。
