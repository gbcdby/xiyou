# UI 融合与共通 UX 视觉原则（不包含页面合同）

## 愿景

**界面作为同一片水墨世界里的清楚信息存在，而不是贴在背景上的另一套厚重皮肤。** 不以去掉所有承托面为目标：当真正需要阅读和触达时，局部稳定的材质、文字和动作反馈比纯装饰性“融入”更重要。

## 场景融合的五步法

1. **先规划阅读空域**：在云、天光、浅水面、绢面等本来安静的视觉区域安放信息，使场景纹理从附近自然退开。
2. **让材料与光色一脉相承**：图标、边缘、文字托面与背景使用同类墨线、局部色层和光线；不把风景先画满再硬叠大框。
3. **用对齐与间距组织信息**：一级、二级、辅助信息通过位置和字重关系区别，而非全部使用相同装饰盒。
4. **给互动元素明确可供性**：需要点按的位置仍有足够可识别的轮廓、语义、状态和命中区域；静态纯装饰不能与动作控件混淆。
5. **保留可访问的增强路径**：在光影复杂或透明叠色时，允许局部增强文字底、边缘或对比，不把“没有框”置于阅读之上。

画面内可运用失边和透明笔触，**文字轮廓、关键符号、点击热区和焦点指示不可一起消失**。纹理放在内容外缘；高频细线、植物枝叶和亮斑不穿过主要文字。

## 图标视觉系统

- 每组图标统一语义层级、视角与体量、线宽与转折、抽象程度、彩度和轮廓方式。
- 独立场景 icon、动作 icon、状态标识可有不同复杂度，但不能使某一类完全依赖文案才能认出轮廓。
- 图标底色不要求处处有独立块状底板；需要增强对比时从周围小范围环境笔触、文字颜色和轮廓着手。
- 自然材质用在图标的形体，不拿复杂纹样侵占短文字；在缩小后的真实显示尺寸检查识别。

## 通用 UX 约束

| 设计对象 | 通用设计动作 | 需要另行验证的事实 |
|---|---|---|
| 信息焦点 | 玩家目标、所需事实与下一步动作有清楚的阅读主次 | 真实玩家是否找得到 |
| 状态含义 | 可点、选中、处理中、失败、未知结果不同义 | 后端是否具有相应确认机制 |
| 反馈 | 让反馈发生在相关对象／结果附近，动效与状态相符 | 任务完成、失败及减少动效时的理解 |
| 输入与阅读 | 文字尺寸、设备距离、单／双手和触控目标分别设计 | 真机热区、焦点、放大字号、辅助技术 |
| 环境动效 | 让动态体现呼吸、风、水或材质，不移动关键文字 | 减少动态和并发场景是否仍可用 |
| 主题变化 | 统一状态与组件语法，允许人物、季节、色域不同 | 异色背景和长内容是否仍可读 |

下述方法继承自通用案例的[视觉迁移摘要](../references/research/design-transfer.md)，当前来源入口与证据范围在该文中列明。本项目只采用符合“清逸、明亮、精致水墨”的视觉方法，不复制任何游戏的具体功能或界面排布，也不将历史案例研究视为本项目已完成的视觉验证。

## 案例触发的设计判断（只保留大方向）

- 《GRIS》提示颜色可以随氛围大幅变化而画面语言仍一致；本项目以线墨和空间共性维持风格，而非单一颜色滤镜。
- 《Dordogne》提示材质丰富时仍可使用稳定的工具阅读底面；本项目将云光与绢面预先纳入构图。
- 《Sky》开发者访谈提示触控遮挡与输入情境的差异；这里吸收“真实使用环境先行”，不把它当成某个页面必须的布局。
- 《stitch.》开发者讨论数字和操作辅助；本项目保留必要文字与状态的增强手段，避免以弱对比冒充柔和。
- 《Persona 5 Royal》示意大胆风格与稳定正文结构并存；本项目借用“表现外缘更自由，阅读内部更规整”，不复制红黑配色。

这些结论是视觉转译方向，**不是对具体产品交互已通过的证明**。真实可访问性规范属于平台实现时另行确认。
