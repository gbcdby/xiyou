## 3. 必要资源与生产合同

### 3.1 选用的分层

每个场景以一个明确版本的静态资源组原子启用；动态门扇另按当前授权变体加载。名称仅为角色示例，最终文件须在静态 catalog 中逐条登记；本设计没有生成或发布这些文件。

| 层 | 必须包含 | 必须排除 / 保留 |
| --- | --- | --- |
| 静态建筑底层 | 原有远景、屋顶主体、院落、静态桌凳/架子/台阶；经局部修复的室内切口底衬 | 清掉旧门扇的所有烘焙像素及已移交前景层的重复像素；不烘焙角色、私物、可移动工具或物品专用光斑 |
| 室内地面层 | 三处既定地面和通道、背墙/侧墙的低调剖面关系；后宅包含侧廊 | 不扩大地板到障碍区冒充可走，不新增家具障碍、窗洞或出口。客房/茶棚保持固定敞开门洞 |
| 后宅门扇层 | 对应同一门框的 closed / open 两张透明图；只画可变化的门扇/既有封闭外观 | 不再次画整套门框、台阶、屋顶；不含“解封但关闭”第三帧或补播动画；不含门撑/固定绳组 |
| 入口前景碎片 | 本轮所需的房间前沿、门框/门柱、茶棚入口檐柱；局部透明底 | 底层必须移除同一碎片原像素。不得用整栋建筑或整幅画作为可淡化碎片 |
| 中性门遮片 | 单独的纸雾/斜纹等明确非写实遮片，遮住门扇状态区；配独立“?”提示。必须有不依赖图片加载的原生 SVG 中性占位 | 不能长得像关闭木板，也不能保留可读为敞开的门洞；不创建 target、操作或碰撞 |

固定空剖面保留屋顶、墙体材料和建筑外轮廓，在约定室内局部降低/切去遮挡立面；不是将整个建筑抹成方格。只显示静态结构不会增加房内动态对象的可见资格。地面材质保持既有白昼水墨淡彩、稳定冷暖与低频纹理；不为了照顾某一件私物在 C07 绘制专属亮斑、摆件轮廓或“空置位置”。

本轮必要前景只覆盖三处入口与室内前沿。原图树冠、竹叶、全场低墙和花丛的其他拆层义务仍按 GZ-VIS-01 保留；未拆的部分不能宣称已支持局部淡化。本候选不以三处局部设计关闭全章前景验收。

完整空室内地面允许在离线装配时合入静态底层，此时登记 `floors=[]`，运行时只画一次底层；这不是缺地面。该底层仍须包含正确地面与必要前景下的干净底衬，并与 replaceMask、全部必要前景一起通过原子加载。分离地面时则每一份 `floors` 都是该组必需资源。

### 3.2 映射与导出

**静态层推荐沿用原图像素网格：1586×992，映射到 1600×1000。** 所有静态导出共享左上原点，pivot=(0,0)，xWorld=xPixel×1600/1586，yWorld=yPixel×1000/992。沿用现有背景的两个轴映射，不能把近似比例改成另一套相机。透明层使用同一画框；不得各自裁紧后丢失位置。

允许为传输裁窗，但 manifest 必须保存实际 `pixelSize`、`sourceCrop`、`worldRect` 和源/导出 SHA-256。若从原网格裁出 [x,y,w,h]，worldRect 精确为 [x×1600/1586,y×1000/992,w×1600/1586,h×1000/992]。渲染只使用登记的变换，不从 PNG 非透明边界、名称或对象位置猜测。

| 候选制作窗，世界坐标 | 用途与约束 |
| --- | --- |
| 后宅 [1070,150,350,280] | 包含房内立面、侧廊、原门/台阶的局部修复；窗口不是授权整块重画的 mask |
| 客房 [500,150,280,260] | 包含客房墙面切口与 C11 通道；不移动旁边工具架、花圃或 C17 |
| 茶棚 [490,130,170,290] | 仅补后间、既有入口与必要柱边；保留两组桌凳、柱脚与原阶沿位置 |

制作窗是候选导出/检查边界，**不是地形、碰撞或裁切动态对象的边界**。生产者须另交精确 replaceMask 与 foreground alpha：只修复室内/通道原来被墙面或远景占据的区域，以及必须分离的门扇/前沿旧像素；窗内其他像素亦应保留。旧门打开时散在门洞两侧的叶片也须完整清除。源图+局部修复层在离线装配时形成新的静态底层，运行时只能画一次该底层，不能再把完整旧图画到其后造成露缝或重复。

后宅门继续使用已采纳物件资源合同：target 根点 (1250,425)，`offset=(0,-60)`，图像对齐点 (1250,365)。closed/open 必须同画框、同 pivot、同 scale；定义每张 native 像素 (u,v) 的世界位置为：

```text
target.position + (0,-60) + ((u,v) - pivot) × scale
```

门框归静态结构/前景，变化叶片归物件目录；两者不得同时持有同一可见像素。门扇实际 native 尺寸、pivot 和 scale 由制作实测登记，校准后闭合叶片与现有 70 单位门道和既有门框吻合；不得为对齐素材改变交互点或台阶。生产者若不能在现有窗口内保持这些关系，应返回局部设计，不擅自扩地形。客房和茶棚没有动态门 target，绝不为它们增造 closed/open 变体。

每个可发布资源组最少记录：`contentVersion/mapVersion/sceneId`、组版本、底图与各层明确文件、native 尺寸/映射、SHA-256、replaceMask、foreground 的 `depthY`/局部 bounds、门槽与 timber-door 目录兼容版本。缺值记待制作，不能填虚构 hash 或将候选文件自动复制进 public。首批只匹配 gaolaozhuang-scene-v2 / gaolao-layout-v1.1；east-tools 内容虽当前几何相同，未单独登记并启用前完整保留原 sceneArtwork / 原 fallback，不套用本合同新门槽或 sealed-door 显示过滤。

### 3.3 imagegen 制作输入

后续制作使用已有两张原图作编辑目标，技术导图仅作几何约束，不能把编号、色块、路径或物品占位符画进最终图。先生产后宅的静态修复、空地面和所需前沿，完成与原图及几何的对照，再按同合同生产另两处；门扇另行单件制作。此顺序不授权重试此前被阻断的门撑/固定绳组合。

输入包须带原图 hash、上述窗口/多边形/固定点、沿用画风规则、不得变化的架/台阶/柱脚清单、应删除的旧叶片像素范围。输出要保留原始请求、工具实际返回身份、源文件、技术裁窗/装配映射、每个导出 hash 和遮罩。艺术生成/编辑由 imagegen 完成；程序只作技术定位、裁窗、装配和检查，不能用几何示意替代正式水墨美术。

## 4. 运行时显示规则

### 4.1 静态层与动态对象

1. 只从**当前已接受 snapshot / projection.replace** 读取 scene 与对象；复用 SpatialView 对顺序、viewId 与版本的处理。先以已释放目录的精确 contentVersion/mapVersion/sceneId 与启用条件确定是否进入本合同；未匹配时沿用原显示。匹配后，完整静态图层组加载和校验成功才显示新静态美术，失败按 §4.4 降级；门扇不决定静态组是否可用。
2. 静态空室内始终画，不依赖门态、某人是否同意、私物是否存在、chapter.progress、历史观察或全局障碍变化。无需客户端生成视野多边形。
3. 地面物件、人物和目标仍只遍历当前授权数组，held 不在地面画；不因静态房间“可见”扩展动态对象。图层不能生成自有 entity 或缓存旧位置。
4. 裁切分开处理：背景/底衬仅按场景与制作 mask；地面材质按对应已核 area 关系；动态实体不以房间 polygon 硬切头顶或整张 sprite，只沿用场景视口与授权数组；前景按自身 alpha 遮挡。
5. 任何图层图像均 pointer-events:none。目标操作与选择仍使用原 entityRef 和权威根点，不能让视觉门点 (1250,365) 替代 C01。

### 4.2 后宅门槽的当前显示

本节门图选取只在当前已登记静态组完整就绪后运行；静态组未就绪或加载/校验失败时，新门槽只能显示原生中性占位，不能提前显示已加载或缓存的 closed/open 图。该资源占位不改变目标卡已有的授权 open 事实，不能把资源失败写成世界门态“未知/未见”。场景中只有一个固定门槽。可用当前 scene、`visualKey=timber-door` 和已公开 target.position=C01 做一致性检查；**不得解析 opaque ref、按汉字名称找门、用位置单独猜类型或将同 key 当作唯一实体身份**。若零项或多项匹配，门槽保持中性，所有已授权 target 仍保留各自的原占位与列表操作，不强行合并。门图有且只有一个绘制责任方，不能在场景层与普通物件层重复画。此门槽接管的 timber-door 在普通物件 pass 中只保留原选择占位/命中；匹配失败或多项匹配时也不得从该 pass 再画一份门贴图。

| 当前输入 | 门槽显示 |
| --- | --- |
| 唯一已授权目标，key/版本匹配；open 为唯一 boolean false；本次 closed 图已可用 | 仅 closed 图 |
| 同上，open=true；本次 open 图已可用 | 仅 open 图 |
| 目标不在当前投影、缺 key、open 缺失/重复/非 boolean、匹配不唯一 | 中性遮片；不沿用上次门态 |
| 字段有效，但对应资源加载中、失败或批次不兼容 | 中性遮片 + 既有图像失败/占位机制；合法详情仍能显示当前授权 fields |
| 无新物件能力的旧 DTO | 静态空剖面可显示；门保持中性，授权 target 走现有通用占位 |

中性是**显示未知或资源不可呈现**，不是第三种世界门态。独立“?”/简短状态文字不烘焙进图像，不能用锁、封条或黑洞暗示已关/已开。静态层必须擦除旧门态，否则遮片失败也会泄露烘焙的开放外观。

禁止从 sealed-door 是否在 scene.obstacles、exit.open、全局目标表、readyCount、support.locked、chapter.progress、动作成功文案或旧缓存推断当前门图。当前 PublicScene 的全局障碍筛选是既有投影事实，本设计不声称修复该 DTO 可推断性；本次新增显示不得将它转成门态像素或文案。

本轮只切换两张静态门图，不加解封过渡。初次进入、重连或门重新可见时直接显示当前已授权状态；不补播不可见历史。门态、view/session/scene/内容版本或目标引用变化时立即撤掉旧帧，未就绪阶段使用中性遮片；迟到 load/error 不能把旧状态带回。图像字节缓存可复用，当前显示资格与状态不可缓存复活。沿用现有资源取消机制，并将回调校验绑定当前实例、变体/资源请求代次。

### 4.4 降级与同位对象

启用范围先于加载结果：未登记、空正式 catalog、未启用或未知 scope 时，完整保留原 sceneArtwork / 原 fallback；不创建新门槽，也不执行本合同的 sealed-door 特殊显示过滤。只有已释放且精确 contentVersion/mapVersion/sceneId 登记并启用的组，才进入以下规则。

已进入该组后，静态资源未完整加载、mask/尺寸或资产元数据校验失败时，静态整组退回现有几何地图与原对象占位，不能出现“新地面+旧开门”或“移走前景但底衬缺洞”的混搭。此登记 scope 内的图形降级继续使用公开静态 areas，并排除该门槽登记的动态 sealed-door 障碍图形；静态组未完整就绪期间，门槽强制使用原生中性占位，即使某张 closed/open 门图已经加载也不绘制。只有静态组成功后才运行 §4.2 的当前授权门图选择，不能用障碍是否存在恢复门态。门扇单独失败时保留已就绪的静态组，使用原生中性遮片及原对象操作；资源占位不改目标卡的授权 open 事实，也不声称世界门态未知。导航仍使用原权威规则，服务端投影不改。

登记与合法绘制数据须分开：门槽字段本身缺失/非法也属于组校验失败，不能把坏字段继续交模板或排序。该精确院落 scope 的安全降级固定使用 §2 已确认的 C01=(1250,425)、depthY=395 与门区 [1210,1290]×[350,395] 作为原生中性几何；这些常量不取决于 obstacles 是否存在。合法组仍使用其已验证的视觉边界。庄外组无门，不借用院落门槽；未登记/未知/禁用 scope 不建立此降级描述。

其他未登记或未知场景仍遵循原有 sceneArtwork / 安全 fallback，不把同名障碍或该组的门槽规则推广过去；不得推测资源地址。失败不禁用移动、对象列表、查看或物品操作。保留现有重试入口，重试不请求新的游戏动作。

包裹与书信仍在同一点画两实例；两条独立 DOM 标签和“附近的人与物”列表足以分别选择与操作，标签拥挤时保留现有遗漏计数/列表入口。选中环与详情对应选中的 entityRef，不因两张图叠成一个轮廓就合并、偏移或自动拿取。当前无需新增同位 UI；独立验证若证明现有入口失效，才返回这个局部交互问题。
