# xiyou 项目工作流

本文件把仓库内的技能包接到 xiyou 的工作记录。它不替代技能的专业方法；任务开始时读取所用技能的当前 `SKILL.md`。

## 权威记录

- 用户当前明确决定是工作的范围与授权依据。2026-11-11 起，后续平台统一为 **GitHub**。
- [总设计](../../初步设计文档.md)保存产品与总体技术边界；[有效 Spec](../specs/README.md)保存细化行为、共同约束与整体验收。
- [GitHub Issues](https://github.com/gbcdby/xiyou/issues)保存任务范围、依赖、归属与完成状态；[PR](https://github.com/gbcdby/xiyou/pulls)保存候选、审查和集成事实。
- [项目现状](../project-status.md)是带日期的基线与路线入口，不复制活动任务清单。
- [工程约定](../engineering.md)、[设计资料](../design-direction/README.md)分别承载工程与视觉规范。

Spec 与任务可以分处文件和 Issue，但要互相引用同一有效修订。不得同时维护互相独立的 GitHub/Gitee 状态。

## 按任务选择最短路径

| 当前工作 | 使用能力 | 本职责的产物 |
| --- | --- | --- |
| 事实、原因或范围不清 | `worker-investigate` | 有来源的结论、剩余未知、下一步 |
| 行为、协议或架构待明确 | `worker-design` | 共享 Spec 与可观察验收 |
| 视觉方向与组件规格 | `worker-visual-design` | 当前视觉基准及其适用范围 |
| 大功能或多项交付的拆分 | `worker-plan-tickets` | 真实可读取的 Tickets、依赖与验收覆盖 |
| 所有权、交接、重连等关键状态协议 | `worker-tla` | 模型、负对照、检查结果与实现义务 |
| 已明确的代码、配置或文档修改 | `worker-implement` | 候选与作者自查 |
| 按既定视觉基准实现或对照 | `worker-ui-fidelity` | 界面与真实平台证据 |
| 执行运行或验收检查 | `worker-verify` | 对应候选的真实检查结果 |
| 独立核对需求与标准 | `worker-review` | 分轴结论、问题与复审结果 |
| 创建 PR、处理反馈与授权内合并 | `worker-land` | 实际 PR／合并状态 |
| 已有发布、部署目标 | `worker-release` | 指定环境的发布与验收事实 |
| 跨 Ticket、跨阶段持续推进 | `deliver` | 依赖调度与整体验收 |
| 交接消息或解释已有进度 | `collaborate` / `brief` | 有依据的交接或简报 |

技能位于 [.agents/skills](../../.agents/skills/)。`auto`、`challenge`、`steer`、`setup`、`guide` 仅由用户主动调用；普通任务不用先调用这些入口。自然语言的目标调整与停止要求直接生效。

简单、明确且易回退的修改可以直接实现、针对性检查与审查，用现有 Issue 或 PR 记录紧凑范围，不强制新建大 Spec。多阶段或多人依赖的功能先保存共享 Spec 和真实 Tickets，才进入实现分派。开启 `auto` 不会跳过这些记录或验收。

## 一项工作的闭环

1. 固定对象：相关设计修订、代码提交或完整候选、真实环境与当前归属。
2. 查阅任务与依赖；已有决定直接复用，未知只影响相关部分。
3. 产出与检查按任务风险安排。产品实现使用针对性行为测试；文档核对事实、来源、链接与结构。
4. 独立审查按 `worker-review` 的需求轴、标准轴和独立性要求执行；作者自查不替代独立审查。
5. `worker-land` 推进到本次约定终点。草稿、就绪、已合并、已部署分别记录，不因创建 PR 就写成任务已交付。
6. 达到关联 Ticket 完成条件后，在有效授权内回写结果与证据，更新依赖并读回确认；父 Spec 按整体验收判断完成。

合并与部署沿用本次任务或本项目已有的有效授权，不从其他项目或一次阅读中推定。没有部署目标时不自行新增发布环节。分支、独立工作区和临时材料按实际归属与仍在使用的情况收尾。

## 长期上下文如何积累

- 产品决定回写总设计或对应 Spec；实现边界回写工程约定；流程变更回写本目录；视觉决定回写设计资料。
- 调研结论保存到所属资料目录并附来源、日期和适用范围；任务进度与本轮检查结果保留在关联 Issue/PR。
- 已有正式记录只加必要引用。没有新事实时不新增总结文件；文档缺失不作为简单任务必须初始化一整套系统的理由。
