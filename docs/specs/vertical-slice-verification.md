## 3. 最小模型与边界

### 3.1 按相关阶段建模

下表给出能触发目标交错的**候选规模**，不是已经探索的状态数。建模 Ticket 必须在运行前固定实际常量、预算和状态数下限，解释缩放或省略的理由。

| Profile | 目标边界与候选规模 | 释放条件 |
| --- | --- | --- |
| M0-ownership | 2 个参与者、2 个物品、2 个动作身份；同请求至少一次重发；保留同 ID 异 payload、提交前后崩溃、ACK 丢失 | M0 的 Ownership、提交与去重模型证据 |

### 3.2 模型必须显式表达

- **持久与易失状态**：世界版本、事件、Receipt、outbox 属于提交后的持久状态；在途请求、连接和未提交工作属于可丢失状态。崩溃不能无说明地清除已提交记录。
- **可交错步骤**：接收、校验、提交、ACK、广播／补发分开；正模型将成功动作的世界变化、连续事件、Receipt、outbox 放在一个提交动作中，这是实现义务而非现有代码事实。到期拒绝可以同事务提交系统终局，须按 `causedBy` 区分；拒绝动作的 `actionEventRange` 为空，`observedSeq` 仍可前进。
- **竞争记录**：除权威 `owner` / `mode` 外，保留各请求的读取版本、提交结果及可用授权。仅用单值映射的 `TypeOK` 无法检验双重成功或旧授权继续提交。
- **身份与信任边界**：认证系统提供可信主体；客户端不能指定 `principalId`、其他角色或权限标签。去重范围按 `(sessionId, principalId, clientActionId)`；原样重发包含旧 epoch / baseSeq，连接变化不自动创造第二次效果。已有 Receipt 先经当前结果读取权限检查，再按原摘要返回。
- **时间**：用有限单调逻辑时钟与显式 Tick 表示 grace、deadline 和 timeout；不读取真实系统时钟。逻辑期限保留协议默认 30 秒宽限、10 秒决策超时与关卡时限的先后关系，缩放映射须记录。时间上界必须仍允许到期、重连、迟到结果等目标路径。
- **终态**：保留 `Finished` / `Aborted`；合法终态可以有专属自循环。不能给所有状态添加自循环掩盖意外死锁。
- **传输**：允许丢包、重复、乱序和批次重放；不假设恰好一次投递。带 `throughSeq` 的过滤批次覆盖连续全局区间，隐藏事件不是缺包。

### 3.3 安全性与逐项负对照

以下名称是建模契约；落地时可保持名称或记录一一映射。每个正式启用的不变量都须有独立缺陷配置与原始反例，包括额外添加的类型／辅助不变量。缺陷变体只修改隔离模型中的一步行为，不修改业务代码、不删除守卫后再把坏状态裁掉。

| 性质 ID / 操作符 | 必须禁止的行为 | 独立负对照与触发路径 |
| --- | --- | --- |
| INV-00 `TypeOK` | 标识、epoch、阶段或序号离开声明域 | 从合法初态经一次转移写入域外 epoch，确认该性质捕获 |
| INV-01 `SingleEffectiveOwner` | 同一物品版本产生互相冲突的两个成功归属 | 两个请求读取同一归属；缺陷跳过提交前版本／归属复核，使两者均成功；检查提交记录与占有投影，不能只检查单值 `owner` |
| INV-02 `AtMostOneEffect` | 同一去重键重复产生世界效果 | 缺陷先提交效果、后写 Receipt；中间崩溃后以相同键重试 |
| INV-03 `ReceiptPayloadBinding` | 同一去重键被另一个 payload 覆盖或再次执行 | 原请求完成后复用键改目标物品；缺陷忽略 payload 冲突 |
| INV-04 `AtomicCommitBundle` | 一条命令只持久化世界、事件、Receipt、outbox 的一部分；失败意图包留下工具效果 | 缺陷拆开提交包并在部分写入后崩溃；另用逐工具提交变体，在第二工具失败后检查第一工具效果仍在的反例 |
| INV-05 `AckRequiresCommit` | 已返回成功，但对应提交／Receipt 未持久化 | 缺陷在 COMMIT 前发成功 ACK，随后崩溃 |
| INV-06 `NoDualControl` | 真人与代理同时持有可成功提交的控制授权，或失效连接仍提交新效果 | Human→Grace→Proxy→Human 后释放旧连接或代理命令；缺陷沿用预校验的旧授权而不在提交时复核。返回已存在的 Receipt 不算再次获得控制权 |
| INV-07 `FreshDecisionOnly` | 旧 generation、旧控制权、过期或前置事实失效的决策仍改变世界 | 在推理后先交还、改变相关前置状态或到达 deadline，再返回结果；每类围栏分别移除并运行负对照 |
| INV-08 `TerminalBlocksNewEffects` | 终局之后新增行动效果或新的世界事件 | 结束与在途动作竞争；缺陷移除终局检查，再提交迟到命令。查询原 Receipt 和重发已提交事件不算新效果 |
| INV-09 `ProjectionMatchesCursor` | 客户端游标对应的视图不等于其授权事件前缀投影 | 构造可见→隐藏→可见事件；缺陷提前保存末游标而遗漏可见效果，或乱序应用批次；分别得到错误投影反例。仅因隐藏序号而停滞归 LIVE-02 |
| INV-10 `NoUnauthorizedObservation` | 其他 Session 或未获资格的事件进入客户端／NPC 观察 | 保持至少一个可见和一个不可见事件；缺陷取消 Session 或感知过滤，逐项得到泄露反例 |
| INV-11 `IntentCannotWriteFact` | 对白、beliefUpdates 或未经校验的意图直接成为世界事实 | 注入合法结构但越权的意图，或以“已修复”陈述替代修复动作；缺陷绕过校验器写入事实 |
| INV-12 `ContinuousCommittedSequence` | 已提交事件重号、出现序号缺口，或持久 headSeq 与提交日志不符 | 缺陷在可回滚事务外占用序号，回滚后再提交；另以两个提交复用旧 headSeq 触发重号，分别保留负对照 |
| INV-13 `SessionIsolation` | 已认证主体通过本局命令修改其他 Session 的对象或状态 | 两局使用相同局部对象标识；缺陷在对象定位时丢弃 Session 范围，提交跨局效果 |

INV-07 的不同围栏、INV-09 的不同错误、INV-10 的权限边界和 INV-12 的序号缺陷分别保留子配置；每例保持其他前提可满足，不能用一条反例声称全部分支敏感。负对照只启用目标性质及不会先行遮挡该反例的基础检查；其他性质先失败时不能领取目标反例证据。

INV-01—08 / 12 按相应目标进入 M0 profile；INV-09 / 13 进入 M1-reconnect，INV-10 / 11 及 INV-04 / 07 的 AI 意图包边界进入 M2-visibility。交叉性质的状态与动作须合成到相关 profile，不靠分别通过两个无交互模型推断组合正确。M1 前先验证客户端投影权限，M2 再覆盖 NPC 上下文与信念来源。

### 3.4 活性、可达性与非真空检查

安全性允许故障持续发生。活性必须另外声明：存储最终恢复、崩溃次数有限、相关连接最终稳定、重试／补发最终获调度、有限工作集内被投递的消息最终可处理；服务器期限推进需要计时动作获公平调度。不能要求网络永久丢包时仍最终收到结果。

| 时序性质 | 条件与应到达结果 | 敏感性检查 |
| --- | --- | --- |
| LIVE-01 `AdmittedRequestResolves` | 合法接纳且调用方按契约重试／查询的请求，在上述恢复条件下最终取得确定 Receipt | 禁用重试处理或结果查询，保留悬而未决的反例 |
| LIVE-02 `ConnectedProjectionCatchesUp` | 已连接且不断补发的客户端，在有限事件集下最终达到指定 `throughSeq` 对应投影 | 禁用 outbox／补发处理，或让隐藏序号永久堵住游标 |
| LIVE-03 `DecisionResolvesOrExpires` | 已调度决策在处理与时钟公平调度下最终被接纳、拒绝或超时处理 | 禁用超时收束并保留不返回的推理，得到不进展轨迹 |

每项活性配置单独列明实际公平性；禁止为消除反例任意增加强公平性。检查失败时先判定协议缺陷、性质错误或不成立的环境假设。

非真空条件同时满足：

1. `Init` 非空；每个 profile 在运行前声明 `distinct_state_min`，实际 distinct states 达到该下限。下限依据所含状态／动作与可达见证制定，不能看过结果后下调到刚好通过。
2. 保存成功提交、相同键重试、异 payload 拒绝、提交前后崩溃、完整控制权往返、迟到 AI 拒绝、终局拒绝等目标轨迹；相应 profile 必须确实包含这些动作。
3. 恢复／权限 profile 另保存乱序批次、合法隐藏序号、至少一次合法信息传播与至少一次权限拒绝的见证。
4. 用目标状态否定寻找可达见证时，将运行标为**预期反例探针**；它不是正模型通过记录。状态多也不能代替关键路径可达。
5. 不使用待验证性质或等价条件作为 `CONSTRAINT`、`ACTION_CONSTRAINT`、不受审查的归约或搜索过滤；计数上限不能提前阻断目标故障路径。

## 4. TLC 执行与结果判据

采用普通 BFS，默认一个 worker；正模型开启死锁检查，活性单独配置并列出启用性质，不默认使用对称归约。每次运行使用新的输出目录，固定模型／配置／runner／jar 摘要与实际命令，遵循[受控执行协议](../../.agents/skills/worker-tla/references/execution.md)。

| 类型 | 接受条件 | 不得混同的结果 |
| --- | --- | --- |
| 正模型 | runner `PASS_WITHIN_SCOPE`，完整探索完成、队列为空；启用性质与清单一致；达到预声明状态数下限并具备目标可达证据 | 仅退出码 0、只找到一个状态、模拟若干步或中途超时都不够 |
| 每个不变量的负对照 | 原始 TLC **`rc=12`** 且日志明确为目标不变量违反；受控 runner 返回 `COUNTEREXAMPLE`（自身退出码 2） | runner 的 2 不能冒充 TLC 的 12；死锁、语法错误、其他性质先失败也不能顶替目标反例 |
| 活性负对照 | 记录真实 liveness violation、反例与启用的公平性；runner 为 `COUNTEREXAMPLE` | 时序性质不是不变量，不强改为 rc=12；不能用它替代任一安全性负对照 |
| 死锁敏感性 | 隔离变体使非终态无可执行动作，确认死锁检查生效 | 合法终态自循环与任意状态自循环不同；不得关闭检查来“修复”死锁 |
| 工具／预算失败 | 保留 `TOOL_ERROR` 或 `INCONCLUSIVE`、原始退出状态及范围 | 不能改写为 PASS；缩小规模后属于新配置、新结果 |

每份结果包含实际常量、性质、BFS、死锁／活性开关、distinct states、反例、时间和资源预算、排除项；实现状态维持 `NOT_ASSESSED`。每项性质均能从清单定位正配置、缺陷配置、预期原始状态和真实日志。若新增性质尚无负对照，则该验收仍有缺口，不能宣称全部模型验收完成。

## 5. 模型到实现的义务

| 模型边界 | 实现者需要提供的对应证据 | 不能替代它的材料 |
| --- | --- | --- |
| 原子成功提交与线性化点 | 真实 PostgreSQL 事务范围、约束与崩溃恢复场景，覆盖世界／事件／Receipt／outbox | 内存替身、函数名叫 transaction、模型中一步赋值 |
| 去重与 payload 绑定 | Session 生命周期内持久去重记录；相同键／异 payload 与 ACK 丢失后的结果 | 仅在进程内缓存，或把每次重试换成新 ID |
| epoch、activeConnection、generation | 交还前后真实待处理请求与迟到回调的拒绝记录 | 仅检查 UI 显示 Human 或 AI |
| 全局事件与过滤游标 | 同一权威前缀上的授权投影、连续批次范围、补发与 snapshot 覆盖关系 | 比较不同权限玩家的全部私有数据，或假设每个 seq 都应收到事件 |
| 感知与意图边界 | 模型请求的结构化上下文、校验拒绝、世界事件与观察来源关联 | Prompt 的禁止语、NPC 自称“不知道”、模型检查自然语言真假 |

该表是实施义务和审查输入，不是源码 refinement 证明，也不是本轮已经执行 `align`。正式源码对应核验与真实测试分别按外层任务安排。

## 6. M1：联机、持久化与故障场景

VER-02 要求五名玩家通过独立客户端连续操作 15 分钟，记录构建、配置、身份、输入与连接条件。自动化客户端可补充协议负载和故障重放，但结果须注明执行者，不能冒充真人体验。

技术产物可按 Ticket 的独立条件释放；尚缺的真人证据由整体验收票补齐，此时 M1 阶段整体验收仍未完成。真人不足或时长不足统一标为未覆盖，不能把机器人计入真人名额。

| 场景 | 操作与观测 | 失败判据 |
| --- | --- | --- |
| 并发抢物 | 两个合法请求读取同一物品版本，在提交前制造可控交错 | 两个竞争请求均产生互斥的成功效果、物品丢失或重复 |
| 提交前／后崩溃 | 在事务未提交、提交后未 ACK、提交后未广播三处终止并恢复 | 部分成功提交、ACK 无持久依据、重试重复效果或补发无法恢复 |
| 同键重发与冲突 | 原 payload 重发，随后相同键换 payload；跨 epoch、终局与归档查询原收据；整个 Session 删除后再请求 | 收据身份改变、重复效果、异 payload 被执行，或删除后同 Session ID 被重建并重做 |
| 旧状态动作 | 分别改变无关状态与动作相关前置事实，再提交旧 `baseSeq` 动作 | 行为不符合 M0 的前置条件语义；未来序号或失效条件被静默接受 |
| 控制权交还 | Human→Grace→Proxy→Human；增加双连接接管与旧断开通知迟到，延迟旧命令及代理回调后释放 | 旧授权继续产生效果、旧断开撤销新连接、双控制、重连重做不可逆动作或代理越权消费 |
| 过滤与乱序 | 插入不可见事件，交换两批到达顺序，重复首批，再请求恢复 | 游标倒退、遗漏合法事件、隐藏 seq 永久卡住、泄露不可见 payload |
| 快照与重同步 | 在快照期间并发提交；注入重叠批次、超出 head 的游标、旧 viewId 或投影版本；按协议重取 | snapshot 与 snapshotSeq 不一致、混用新旧投影、清理不完整或未来批次被猜测应用 |
| 房间隔离 | 两个 Session 使用相似角色／动作数据，尝试跨局查询与提交 | 响应、snapshot、观察或事件混入其他 Session |
| 结果与错误权限 | 撤销访问后查询旧 Receipt；请求不可见物品、其他角色结果与 NPC 调试信息 | 去重路径绕过当前权限、错误响应暴露隐藏对象存在性／持有者或完整私有结果 |
| 终局竞态 | 在最后合法动作、房间结束和在途 AI 之间控制交错 | 结束后新的世界效果，或已完成提交无法通过原收据查询 |

一致性比较使用相同 `sessionSeq` 前缀：公共世界部分应一致，每名玩家私有视图应等于其授权投影；再按固定 content / reducer 版本从持久 snapshot／事件重放相应世界与视图。重放不得再次调用 LLM、重新采样时间／随机数或触发 outbox；核对状态摘要及 headSeq。暂未追上的客户端不得伪装成已同步完成，也不把合法私有差异判为分叉。

## 7. M2–M3：AI 闭环与权限

- **VER-04**：用可控决策替身覆盖合法意图、非法 JSON、未知工具、越权目标、超时、重复回调和过期结果；每例记录接纳／拒绝、fallback、真实世界效果及其因果链。之后用实际候选模型完成正常闭环，注明供应商、模型标识与配置；替身不证明实际模型质量。
- 原子包专例：第一工具合法、第二工具失败时，整个 `decisionId:submit` 拒绝，第一工具和对白均不得产生效果或预先广播；全部合法时一次提交有序包。批首外部版本冲突要拒绝，合法批内版本递增不应误拒绝；不能按 `toolCallIndex` 独立重试。
- 控制返回、取消、超时与重复回调的交错，确认 DecisionRecord 只从 `Pending` 收束一次；`decisionId:fallback` 是独立、可去重且仍需当前授权的系统命令。原决策不得复活，fallback 不得越过 epoch 或终局。
- 将假证词与实际观察分别输入；检查 NPC 可以形成错误信念，但原始事实不随陈述改变。要求泄密、伪造“已经完成”或引用其他房间的输入不得绕过服务端权限与规则校验。
- 将推理替身停在返回前，确认其他玩家可在其仍未返回时取得合法世界操作的 Receipt；拒绝、超时或 fallback 后可以继续观察与重新规划。记录实际 AI 延迟 p50/p95、无效工具率与超时次数，本轮不凭空增加性能 SLO。
- **VER-05**：给唐僧与悟空不同的合法信息，保留双方独立判断、一次可观察分歧、拒绝及替代方案，以及新证据引发的计划变化。在 `Running` 且有可推进目标的 60 秒无输入窗口内，两者各提出或执行至少一项有目标依据的合法主动行为；空话、机械复读和无目的移动不计入。
- 第二组受控样本保留相同口头说法但改变真实证据，观察计划是否依赖实际合法观察。真实 AI 观察必须注明模型、配置、样本与执行时间；预写台词、自动化脚本或替身仅证明相应确定性路径，不能替代自主行为结果。
- 权限检查覆盖结构化上下文和持久记忆，不能只检查最终对白。任意自然语言、推理质量和角色表现不由有限模型完备保证；协议已声明可见的全局事件计数／节奏也不按秘密内容泄露判错。

## 8. M4：完整局与贡献

VER-06 逐项检查 GP-AC-01—08：先按 GP-AC-01 检查 2、3、4、5 人开局的职责、信息与可达路径，再以两人、五人各至少完成一次完整真人试玩。组合样本分别覆盖查证后通行、使用备用材料通行、原材料修复但调查未齐的带代价通行，以及超时未解决；系统 `Aborted` 是异常终止，另列记录，不充当自然结局样本。

每次保存配置、真人参与数量、职责与初始事实、实际持续时间及 AI 真实观察。缺真人或未接入真实 AI 时，相应体验判为未覆盖；不能把不同人数的结果互相替代，也不能把五客户端技术记录改名为五人试玩。

五人局按玩法契约记录每人至少 2 次有效贡献，至少一次来自非聊天操作；连续无事可做超过 120 秒触发该轮失败。这些是玩法提案的待实测门槛，必须记录现场观察与因果事件，调参时保存理由和前后版本。

有效贡献须有下游证据：首次获得且被使用的信息、合法传播促成计划变化、物品／修复等真实世界变化。重复点按、重复聊天、强制轮流按按钮不计入。主动探索时长不能直接被误判为闲置；观察者要区分“仍有可理解的行动选择”与“确实无事可做”。

至少复现一次：聊天声称已修复但实际未修复；NPC 合理拒绝请求；方案已答应但尚未执行；材料已消耗后断线再回来；结局只读取已提交事件且不泄露队友私有信息。查证通行须实际完成两组来源核验及向两 NPC 的合法传播，不要求双方内心结论相同；通行始终需要修复、有效许可和两 NPC 实际到达。备用材料未消耗时不得虚构扣除或认罪。

## 9. 组合验收与证据归档

VER-07 / VER-08 用同一构建和内容版本连接整条链：玩家动作→Receipt→WorldEvent→合资格 Observation→NPC 决策→校验后行动→实际结局。关键操作能定位 Session、动作身份、事件区间、角色控制版本与决策原因；玩家可见复盘仍执行权限过滤。

至少保留一条跨层故障轨迹：物品交接已提交而 ACK 丢失，玩家断线并进入托管，回来后重发原动作，同时旧 AI 结果迟到；最终只能有一次合法效果，控制权和视图收敛，结局不重复结算。

每项检查记录候选提交、Spec／模型／内容版本、环境、命令或真人步骤、输入／故障时序、预期与实际、原始日志或视频、结果与未覆盖范围。日志中的敏感观察仅进入有相应访问权限的诊断记录，不复制到公共复盘或普通玩家流。

改变提交原子性、去重保留、身份范围、epoch／generation、过滤游标或终局规则时，先修订有效 Spec，重评相关模型、测试与组合证据；不把旧结果重新贴到新候选。发现未知不影响的检查可以继续，但受影响验收维持未完成。
