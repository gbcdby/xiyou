## 1. 两种入口必须显式区分

| 模式 | 建局输入与显示 | 可以承接什么 | 禁止行为 |
| --- | --- | --- | --- |
| 独立选章 | 显示“独立章节，采用本章预设前情”；列出队伍名单、开局事件和必要关系；确认后固定内容版本 | 本章明确的预设事实和按角色授权的起始知识 | 把预设写入此前高老庄会话，声称承接其不入队/不原谅等选择 |
| 连续游历 | 选择真实已结束的前章结果，解析实际队伍与已发生事件；显示保留项、时间跳跃和下一章变体 | 已发生且可追溯的队伍变化、角色亲历/合法获知经历、物件与未履承诺 | 从原著默认名单补人；只按 ending 名称猜加入；把没有发生的中间故事补成玩家经历 |

进入独立章是新 Session，原局历史不变。连续模式也建立新 Session，并以受控导入记录引用前章不可变结果；原 Session 的已结束事件流不追加“后来修正”。原始历史中未决不等于拒绝，未完成不等于从未发生，承诺也不等于履行。

章与章之间可跳过无交互的普通路程，必须在入口说明地点与时间变化；不得借未声明的“赶路摘要”补招徒、盗取、婚约、归还、赔偿、揭示身份或重大和解。章节预设的开局事件在连续模式只允许由该章明确声明的前奏建立，逐项绑定当前真实参与者，标为本章固定开场而非玩家/模型已实玩结果；不套用独立预设中缺席角色的行为。目标章已经存在的历史永不按新名单重算，具体五庄观边界见下节专门变体。

## 2. 前情包的语义与唯一责任

以下是内容合同的必需信息，不是可直接发送给所有客户端的 DTO：

| 信息 | 权威来源与写入者 | 对接收者的约束 |
| --- | --- | --- |
| 来源身份 | 来源 Session、已结束版本/摘要、内容与规则版本、实际结果事件引用，由服务端读取 | 公共视图只露有权知道的说明；内部真实实体/事件引用不旁漏 |
| 队伍与关系 | 实际加入/离开事件、有效参与者、相应本人决定与真实到达 | 收徒意向或队伍列表文本不算加入；不携带旧控制 epoch |
| 关键物 | 原 owner/保管地点、实际归还/借用/授权状态及来源 | 只导入明确允许跨章的物件；不能复制唯一扇子或把公共器具自动归还 |
| 承诺与债务 | 当事人、范围、实际状态、合法获知者 | 未履行保持未履行；新章可显示提示，不能自行兑现或向无权者公开 |
| NPC 经历 | 亲历观察，或合法送达的陈述/证据及来源 | 保留 WORLD FACT / BELIEF / CLAIM；两个核心 NPC 的摘要可以不同 |
| 本地角色 | 新章角色与职责配置、该角色起始知识 | 同一账号换当地人后不继承旧角色秘密；旧私人笔记只在原角色/授权复盘内可见 |
| 未知与缺口 | 断链、缺少事件、版本不兼容的明确原因 | 未知不能用模型补全；界面指出缺哪个入口条件及可用模式 |

章节装载器负责判定适用变体；权限模块只为接收者生成合法观察；摘要生成器只能压缩有来源材料，不创造新事实。LLM 摘要不作为准入判据。导入须幂等绑定来源结果与目标内容版本；同一建局重试不能重复招徒/发物。来源未结束、修订不支持或摘要缺引用时停止连续建局，允许用户仍读取旧结果或另建明示的独立章。

既有 region fixture、旧会话和旧回放保留各自解释器。没有空间事件、同意或入队事实的旧数据不能被猜测迁移成新连续前情；可以明示作为独立章的背景选择，不能声称获得新契约认证。

## 3. 八戒与沙僧：真实名单驱动内容

本批不虚构章间招徒事件。八戒没有在高老庄实际加入，就保持不在队；沙僧同样必须来自真实已记录的加入，或仅存在于明确的独立章预设。后续只有经单独设计且实际发生的加入流程才能改变名单。

| 章节 | 独立预设 | 连续模式已设计行为 |
| --- | --- | --- |
| CH02 | 悟空、八戒、沙僧均参与分果，固定事实唯一来源为原详案 | 按实际名单选择 [CH02-CONT-1](narrative-adventure-wuzhuang-continuity.md) 中明确的四种变体；不在队者没有食用/证言/施治事件 |
| CH03 | 师徒四众到白虎岭 | 唐僧、悟空为必需；八戒/沙僧在队才有相应反应与携物，线索和双人操作不依赖两人 |
| CH04 | 唐僧、八戒误饮，悟空、沙僧协助 | 唐僧为固定误饮者；八戒在队且前奏实际误饮才增加一名请求解困者；缺席不自动误饮，水份按实际请求人数配置 |
| CH05 | 两位核心在驿路发生冒名事件，八戒/沙僧可作在场陪衬 | 观察链、行囊、核验全部由两位核心与当地人完成；没有八戒/沙僧也可解；不强制重演逐走悟空 |
| CH06 | 两位核心与可选在队者来到火焰山 | 所有关键工作由当地人、两位核心、铁扇完成；八戒缺席时不生成“假八戒骗扇”，改用当场已出现人物的冒名请求或省略该尝试 |

共同前置是唐僧与真悟空仍实际同行、能够进入下一章。若上章实际分别，当前连续线路在该结果停止，显示“尚无重新会合的实际事件”；可继续原结果的合法后续（未来内容）或选择独立章，不把核心角色瞬移回来。停止不抹除已救人、已开路等成绩，也不伪装成技术崩溃。支持所有已声明名单变体，不承诺任何任意历史组合都能进入每个章节。

## 4. 各章共用的实施与恢复义务

四章正文里的状态名和操作名均为内容语义标签，复用 #27 的移动、inspect/share/interact、物权、同意、合作与权威事件。具体 schema、资源版本和收据由协议规范规定，正文不创造可绕过 Rules 的剧情 API。

- 各章同时就位最多需要两名真人；多人职责是可交接工作机会，不增加逐人打卡。仅一名在线时沿用主 Spec 暂停推进；不由 NPC 凑第二真人完成核心合作。
- 公共工具、公开记录的领回/重新授权只用预声明清单；当事人的信件、扇子、行囊和身体选择不因离线被转成公共资源。私物须依本人有效许可交接。
- 所有未知、取消、失败与重试遵循原动作身份。已提交准备不被随意回滚，未提交效果不消耗关键物；旧外观/同意/移动版本不能替新计划完成。
- 导航/停止沿用#27的 `movementCommandSeq` 发出顺序围栏。真人、AI、场景策略与fallback都在计划创建时绑定受信序号和epoch；延迟结果不得临到执行再取新号。来源链/护送不能被旧移动请求或旧到达回调复活，章内不另建移动队列语义。
- 对完整自主 NPC 的请求失败有可见原因和替代路径。超时/连续两次没有有效行动只允许受控策略执行已合法获知、已授权的安全移动/明确程序，不代替加入、婚约、放弃使命、借出私物、原谅或赔偿决定。
- 各章完整结局需角色实际抵达声明去向；未完成结束只记录已发生事项。结束请求沿用主 Spec 的当前在线真人共同明确确认，少于2人不伪造剧情成功。终局后旧回调不得继续改变结果。
- 每章需要两人与五人真实 AI 样本和2/3/4/5人规则覆盖；贡献、120秒无事可做、复玩及正式视觉条件沿用主 Spec，不在后续章降低标准。
