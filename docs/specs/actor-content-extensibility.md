## 1. 目标与非目标

**目标：** 将可复用的房间规则与具体内容分开，使同类场景、角色和能力能通过稳定契约组合；真人、AI 和脚本共同使用角色及动作模型，同时保留各自授权与信息范围。

本稿记录四个设计面：

1. 角色模板、每局实例、参与者与控制来源的职责。
2. 场景／关卡、角色、属性组件、动作与表现扩展的最小契约。
3. 控制交接、知识隔离、权威提交、版本与恢复时必须保持的语义。
4. 后续接受方案和拆票之前需要回答的问题及可观察验收。

**范围外：** 插件市场、普通玩家上传执行任意代码、在线热替换运行中房间、通用游戏引擎、账号系统重建、微服务拆分和正式编辑器。它们不是本稿默认启动的工作。

## 3. 拟议领域模型与状态归属

### 3.1 五项职责

| 概念 | 职责与状态 | 权威写入者 |
| --- | --- | --- |
| Account | 真实用户身份及跨局资料；复用现有身份系统 | 身份／账号服务 |
| Participant | 本局参与资格、房主／玩家／旁观角色、玩家任务与房间权限 | 房间成员与授权规则 |
| Actor | 世界人物实例：位置、外观、组件状态、能力、物品关系、知识与经历 | 房间内核经规则提交 |
| Controller | 根据授权观察提出动作；实现可以是真人输入、模型或脚本 | 控制器只维护自身待处理工作，不直接写世界 |
| ControlBinding | 当前 Actor 的控制主体、授权范围、epoch、有效连接或内部句柄 | 房间内核的控制权规则 |

这些是概念边界，不要求五个服务或五张表。控制器可先是接口，绑定可先属于角色状态。Seat 仅在预留席位、补位或换人继承职责确有独立语义时再引入。

- 参与者可以没有 Actor（例如被允许的旁观者）；原生 AI Actor 可以没有真人参与者。
- 一个 Actor 同时至多有一个有效控制绑定；是否允许参与者同时控制多个 Actor，第一阶段不新增此能力。
- 连接是输入与观察通道，不等于参与者。多端观察是否开放沿用现有授权，动作输入归当前有效绑定。
- 角色生命周期（跨章／章内）与控制策略（自主 AI／玩家／受限托管／脚本）分别声明，避免扩展交叉枚举。
- 种族、外观、剧情身份属于角色内容；不以“人类”种族字段判断真人权限。

### 3.2 定义、实例与持续性

ActorDefinition 是带版本的共享模板，包含人格、初始组件、能力引用、表现资源、生命周期和允许的控制策略。ActorInstance 引用固定模板，并在自己的房间中保存独立状态。

同模板的不同房间实例不共享可变属性、关系、记忆或决策缓存。切换控制器不重建 Actor，不复制物品，不清空经历。AI provider 的会话缓存不是角色记忆的权威来源。

跨章时，参与者按剧情绑定新当地角色，并为新角色创建新的 characterId；可延续的参与记录、角色经历与队伍事实分别由既有跨章契约决定。账号相同不自动继承旧角色秘密，也不能按 userId 把新角色认成熟人；独立选章与连续游历不混用历史。

### 3.3 三层条件共同成立

世界动作必须同时满足：**角色具备能力、场景与资源前提成立、控制绑定及此次委托允许执行。**

- 玩家角色具备转交物品能力，不意味着离线代理获准赠送私人道具或代作重大选择。
- 房主操作、真人结束确认和队伍私聊资格属于参与者权限，不因持有 Actor 的控制权自动获得。
- 原生 NPC 对自身意愿的决定，与代理替真人作决定分别校验；统一接口仍须保留 NPC 拒绝和本人同意。
- Controller 自报 human、角色包声明权限或提示词自称获准，都不能生成可信身份与授权。插件不能替代核心授权校验。

## 4. 场景、角色与能力扩展契约草图

### 4.1 扩展单元

| 单元 | 声明内容 |
| --- | --- |
| SceneDefinition | 地图、障碍、出口、锚点、初始布置和空间资源 |
| ScenarioDefinition | 由哪些场景组成一章，固定事实、角色职责、阶段、合法分支与结局 |
| ActorDefinition | 人格、初始属性组件、能力组合、表现和控制策略引用 |
| ComponentDefinition | 名称空间、schema、默认值、范围、归属、读写规则、持久化与迁移版本 |
| ActionDefinition | 参数 schema、可用说明、所需能力、前提、允许效果、结果及可观察范围 |
| PresentationDefinition | 授权事件如何映射到资源、动画、交互组件，以及缺少支持时的行为 |
| ControllerAdapter | 将真人输入、AI 或脚本输出转换为统一动作提议；不授予身份权限 |

场景是空间；关卡是组合空间并定义玩法的内容。能力可由不同人物或道具复用；关卡通过规则响应能力效果。新增的非战斗“识别”“变换外观”可作为接口讨论样例，不据此改变既有关卡内容。

### 4.2 清单、注册与属性

拟议 PackageManifest 包含 id、packageVersion、engineApiVersion、依赖及固定版本／摘要、提供的定义、允许能力范围和客户端要求。使用名称空间隔离标识；保留核心空间，重复定义和不兼容依赖应在开局前拒绝。

注册入口可采用以下职责；名称、语言与最终字段尚未定稿：

~~~ts
registerComponent(componentDefinition);
registerAction(actionDefinition);
registerCharacter(actorDefinition);
registerScene(sceneDefinition);
registerScenario(scenarioDefinition);
registerPresentation(presentationDefinition);
registerController(controllerAdapter);
~~~

注册时校验定义完整性、引用、schema 和能力范围；按房间创建实例时再校验内容组合、角色数量与必要可达路径。声明属性不等于允许任意 JSON 补丁：唯一所有权、控制权、同意、安全事实等核心语义必须经过对应规则。

属性不仅有数值，还要有归属。例如“唐僧对悟空的信任”是有方向的关系；真实身份是世界事实，悟空对身份的怀疑是他的认知。插件版本决定这些字段的解释方式，不能随意把动态字符串当作已注册能力。

### 4.3 动作调用与效果提交

1. 内核依据角色权限及当前合法观察，投影可发现的动作说明和目标引用；可用动作、错误和元数据同样不得泄露隐藏身份。
2. 控制器提出 actionId 与参数。会话、可信主体、控制 epoch 和绑定由内核关联，不相信模型或客户端自填的授权。
3. 内核校验参数、能力、当前控制／委托、实际读依赖和场景前提。长推理在提交边界之外执行，不占用房间等待模型。
4. 动作处理器使用明确授予的规则读取范围，返回受控效果提案及观察结果；模型只能看到角色授权视图，不能获得规则层的隐藏真相读取权。
5. 内核逐项校验效果类型、作用对象、消耗、权限及不变量，在同一权威边界提交状态、事件和收据；失败不得遗留部分效果。
6. 事件按观察者投影到客户端和角色知识，再产生表现。接受移动计划不等于已经到达，承诺不等于执行成功。

处理器不直接持有数据库、跨房间状态或任意世界写入口；日志、计时、随机与异步适配也须受接口约束并保留恢复依据。不得将任意 setState／任意 WorldEvent 当成绕过校验的通用效果。

类型声明与代码约定不足以隔离恶意代码。内部可信扩展先通过审查和受控装载执行；未来若接收外部不受信代码，需另行设计并验证执行隔离、资源预算与权限落实，再宣称支持该开放程度。

## 5. 用户入口、交接与异常语义

| 场景 | 成功与状态变化 | 失败、迟到或未知结果 |
| --- | --- | --- |
| 创建房间 | 解析并固定兼容的包集合，创建角色实例与授权 | 缺依赖、重复标识或客户端不兼容时明确拒绝，不创建半成品运行状态 |
| 角色执行动作 | 经同一规则入口提交，返回可授权读取的收据 | schema 合法不代表执行合法；超时不得宣称失败后另建 ID 重做 |
| 真人断线 | 撤销失效输入，进入既有宽限，随后按受限托管策略绑定同一 Actor | 位置、物品、合法知识保留；不新建替身，不新增代理权限 |
| 真人重连／多端接管 | 服务端核验本人及当前规则，原子更新有效绑定和 epoch | 旧连接、旧 AI 结果及旧到达回调失效；不能因旧连接迟到断开撤销新绑定 |
| 跨章换身份 | 在既有章节阶段获准实施后，延续参与资格并按契约绑定新当地角色 | 不迁移未授权的物品、私人知识和原角色职责；本稿不提前实现 A5 |
| 同关换角／接管原 AI | 仅在 D2 决定并修订产品规则后开放 | 当前继续限制唐僧／悟空与高老庄八戒的既定 AI 身份 |
| 旁观转玩家 | 仅在 D3 确定旁观范围、加入资格后开放 | 不能假设真人会遗忘已见秘密；未明确规则前不新增该入口 |
| 插件出错／缺少表现 | 返回可理解的失败或已声明的通用表现，保留房间已提交事实 | 必需交互缺失不能显示“可玩”；普通动作继续，不自动代做关键选择 |

控制切换时：未提交的旧意图取消，已提交效果保留；当前空间版移动按既有规则取消，不新增默认“继续执行旧计划”的行为。合作准备、随行、到达与终局继续按 ADV-001 的控制／计划版本和本人同意处理。

重发沿用原 clientActionId 及语义摘要；同键异载荷拒绝。结果未知时先按原身份查询收据或重发同一请求；控制权变化不允许重执行旧已提交动作，也不扩大旧结果的读取权限。

人数不足时的场景时钟暂停、全员离线／重启不追赶剧情、原生 NPC 自主决定、公共借用物领回的现有条件全部保留。统一 Actor 不使 AI 计入真人在线人数或结束确认人数。

## 6. 知识、目标与表现边界

| 信息 | 归属与读取约束 |
| --- | --- |
| WORLD FACT | 房间规则维护；隐藏事实不直接进入普通客户端或模型上下文 |
| BELIEF／CLAIM | 分别记录持有者／说话者与来源；听闻或相信不自动变成世界事实 |
| 角色观察、经历与目标 | 归 Actor；控制器仅取得当前获准使用的部分 |
| 玩家任务、房主资格、队伍私聊 | 归 Participant 或对应授权任务；托管与 NPC 不自动获得 |
| 跨章摘要 | 按既有连续性契约，只带亲历或合法获知内容，区分事实、认知与陈述 |

同一真实 Actor 的外观变化不产生新账号、控制权、物权或他人同意；不同观察者的模型工具、UI、动作结果、重连及复盘都使用各自合法引用。

能力包需声明前端表现支持。常见事件可以采用通用渲染；新交互模式需对应适配器。资源选择也遵守授权外观，不能从真实身份挑选图标、动作名或资源路径而泄密。

## 7. 版本、恢复与演进建议

建议先做内部可信包和声明式配置，验证边界后再决定是否开放外部执行；这项顺序尚未获用户接受，不作为当前实施指令。

- 每局锁定实际解析后的包版本、摘要、schema／解释器及必要资源兼容信息；必须能重新取得原包内容，只有摘要不能保证恢复。
- 更新注册表只影响后续创建的房间；运行中房间、历史事件和存档继续使用原解释器。缺失版本时明确不可恢复原因，不静默采用最新版。
- 恢复与回放读取已提交事件及原语义，不重新调用模型、抽随机数或重做外部副作用。
- 迁移必须显式定义输入／输出版本、所有权与知识保留规则、失败恢复和校验；先保留旧路径，不能把旧 region 会话猜测成新空间实例。
- 插件卸载不删除活动房间仍依赖的定义；已固定版本的可用性属于发布和保留策略的一部分。

可按“先抽取定义与注册 → 将高老庄放入内部包 → 用既有 CH02 五庄观检验复用”的方式验证方案；额外小样例只能作为隔离实验。该建议不重排 ADV-001 的章节或 A1–A5 阶段。

优先考察 personaByRole、公共协议中的高老庄专属定义、规则入口的章节分支，以及 human 分类的多重职责。保留已有权威事务、幂等、控制 epoch、授权投影、版本与恢复能力；不为抽象而重写已验证底座。

若新增能力需要核心尚不支持的世界机制，可显式升级内核 API；不承诺所有未来机制都能只改配置。

| EXT-AC-01 | 用同一角色包创建两间房，分别修改属性、物品与记忆 | 实例独立，定义不被修改；跨房间污染即失败 | NOT_RUN |
| EXT-AC-02 | 在允许相应控制策略的测试角色上，分别用真人、原生 AI、脚本和受限代理对同一 Actor 提议同类动作 | 共用规则语义，权限差异有依据；按控制器绕过规则即失败，不据此开放核心 AI 接管 | NOT_RUN |
| EXT-AC-03 | 断线、宽限、代理在途、真人重连、多端接管与旧连接迟到断开交错 | 至多一个有效控制绑定；旧 epoch 不提交、不撤销新绑定 | NOT_RUN |
| EXT-AC-04 | 私人物品赠送、结束确认、队伍私聊与 NPC 自身同意的正反例 | 能力／参与者权限／委托分别检查；代理越权或误封 NPC 自主性即失败 | NOT_RUN |
| EXT-AC-05 | 控制切换、替换计划、随行撤回与到达／合作提交竞争 | 已提交事实保留，旧意图与回调不生效；新同意不被旧计划冒用 | NOT_RUN |
| EXT-AC-06 | 同键重发、异载荷、提交后收据丢失及控制权变化后查询 | 至多一次效果，语义不符拒绝，授权查询不重做；重复效果即失败 | NOT_RUN |
| EXT-AC-07 | 新包登记属性与非战斗动作，包含错误 schema、引用、名称冲突及非法效果 | 合法扩展可发现并执行，非法定义开局前拒绝，效果仍受核心校验 | NOT_RUN |
| EXT-AC-08 | 乔装、秘密证据、私聊、记忆共享与失败反馈组合检查 | WORLD FACT／BELIEF／CLAIM 分离，各端投影无越权；元数据泄密也判失败 | NOT_RUN |
| EXT-AC-09 | 按既有跨章合同更换当地 Actor，核对参与身份与可携带状态 | 获准资料延续，旧角色秘密不自动迁移；模型换代不丢权威记忆 | NOT_RUN |
| EXT-AC-10 | 包升级／卸载、重启和历史回放，含原版本不可用 | 使用原内容与语义，无模型重询和副作用重做；静默升级即失败 | NOT_RUN |
| EXT-AC-11 | 内部包异常、推理超时、效果校验失败及预算耗尽 | 无部分效果，不阻塞普通动作，不代做关键选择；无限等待或越权兜底即失败 | NOT_RUN |
| EXT-AC-12 | 新动作在支持／缺少前端适配、不同授权外观下执行 | 反馈真实，必需交互明确兼容性；隐藏身份资源泄漏或假完成即失败 | NOT_RUN |
| EXT-AC-13 | 将高老庄及既有 CH02 机制映射到同一契约，核对改动面与原验收 | 同类扩展主要位于包中，原产品约束可追踪；不断增加核心章节分支须返回设计 | NOT_RUN |
| EXT-AC-14 | 若未来选择外部代码执行：受限环境越权、跨房间访问及资源耗尽负例 | 隔离与预算可证；未设计／未验证时不能宣称支持，当前门槛仍未满足 | NOT_RUN |

建议交给 worker-tla 的有限模型输入：两个连接、一个托管控制器、至少两个 Actor／房间、一个稀缺物件、控制／资源／计划版本、动作请求与收据、暂停及终局状态。先给出单房间权威排序、可信授权和持久提交假设，再检查唯一控制、隔离、幂等、旧计划无效与效果不被回滚；进展性质另行声明公平性和恢复前提。

本稿没有新增 TLA+ 模型或运行 TLC；历史模型结果不能自动覆盖新注册接口、控制抽象和迁移语义。后续需保留模型性质、代码对应、真实运行和体验检查各自的候选及证据。

## 9. 未决事项与返回设计条件

| ID | 需要决定什么 | 当前建议／现有边界 | 影响范围 |

| D2 | 同关能否换角或接管原 AI 角色 | 当前按原角色定位保持限制；预留结构，不新增入口 | 控制策略、秘密、NPC 自主性及剧情验收 |
| D3 | 旁观范围及旁观转玩家规则 | 未决定；不能假定已见秘密可被遗忘 | 参与资格、投影与加入流程 |
| D4 | 托管允许代做哪些行为、读取哪些知识 | 先保留现有受限托管和私人频道隔离；扩大范围需明确规则 | 委托矩阵、不可逆选择、认知上下文 |
| D5 | 角色人格、关系、记忆的可配置／可演进范围 | 保留稳定人格与来源要求，跨章遵循 A5；数值和更新规则待细化 | 组件 schema、模型上下文与存档迁移 |

角色身份、同意来源、动作原子性、知识可见范围、外部效果、可信代码假设或旧存档兼容承诺发生变化时，修订本 Spec 并重新评估受影响验收。接口字段和存储方式可以由实现者在已接受合同内选择；这些关键语义不能由拆票或实现静默改变。
