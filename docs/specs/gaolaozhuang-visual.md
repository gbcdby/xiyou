## 1. 依据与复用

- 复用[原型 #25](https://github.com/gbcdby/xiyou/issues/25)归档的庭院原图与高才SE站姿。两个原素材包SHA-256均已核对；没有重画或改色这两项输入。高才五原生、三镜像的已接受试玩动作仍是当前试用基准，不因本设计重新要求用户确认或返工E/NE可选艺术问题。
- 视觉遵循[项目美术方向](../design-direction/art-direction.md)：墨线骨架、通透淡彩、冷暖有分工、明亮安静且有细节。本次没有恢复或审阅历史72张图，不以缺失图号证明本轮风格。
- 新生成五人静态造型图和庄外短路概念，均为 `original_team`。五人依次为唐僧、悟空、猪刚鬣、翠兰、木匠帮手；没有复制现代改编的造型、对白或资产。
- 通用画风技能中的他项目竖屏、装备槽等约定不适用。本Spec先验收桌面鼠标操作，触控与手机真机另列。
- 最初两张生成式整屏合成稿因人物体量不符、第一稿错字未被采用。当前基准使用原始背景、精确人物层和独立DOM文字，不从生成截图反推坐标或协议。

`#27`已对齐：坐标为场景整数单位；外观与服务端碰撞独立；对他人的操作使用当前观察者作用域的 `entityRef/targetRef` 和内容 `anchorId`。渲染器不能把角色姓名、贴图路径或像素坐标当作权限或真实身份。点目标先导航，实际到达后重验才交互；停步、换目标、外貌/目标失效时取消旧排队操作。

`#27`复审中的移动顺序补充：新目标与停步共享同一角色/控制epoch下的 `movementCommandSeq`，按客户端发出次序递增，原请求重试不得重编号；停步不必等待未知移动请求返回 `movementId`。本地计数器丢失时重新取得epoch，不能把网络抵达先后当作人的意图先后。正式接入必须绑定#27最终释放合同；本设计样页没有实现这些网络字段。

### 2.2 地图层与交互锚点

空间输入的唯一坐标来源为 [spatial-layout.json](../design-direction/gaolaozhuang-v1/spatial-layout.json)，可见标注为[院落地图](../design-direction/gaolaozhuang-v1/layout-courtyard.svg)与[庄外地图](../design-direction/gaolaozhuang-v1/layout-road.svg)。两图均使用1600×1000逻辑范围，给出主要可走多边形、屋体/桌凳/花圃/门柱等障碍、明确开口、38个锚点、路线、室内外感知分区和场景连接。图是开发用空间输入，不直接把私密地点或真实人物身份全部展示给玩家，也不是已验证的导航网格。

**统一锚点语义：** `anchors[].position` 是角色在相应场景/状态条件下可接近或站立的脚底点；交互时导航到此处，再重验目标引用、权限与动作前提。`visual_object` 仅指门扇、台面等对象的图上位置，不能替代站位或作为导航终点。图中圆点标站位，`◇` 标对象外观位置；编号的排版偏移不改变坐标。样例角色、安置到达点和场景边界也按各自 `role` 使用脚底点，不将图像中心混入导航。

`C01` 已固定为封门前可达的门外检查站位 `(1250,425)`；门图上位置仍为 `visual_object=(1250,365)`。站位位于常态前庭，处于门道南侧，不依赖仅开门后可走的 `rear-door-passage`。门关闭时可以先到 `C01` 检查、满足条件后执行破锁；门内 `C08` 通向 `C01` 的穿门路线仍只在开门后可通行。`rear-to-guest/rear-to-road` 的外侧起点同步使用新站位，原有救援/同意前提不变。这是对 `R-28-REQ-001` 接近点歧义的作者补充修正，状态为 `FIX_REPORTED`，不据此宣称实际运行导航通过。

原型的前庭点 `(450,795)` **仅保留为历史演示点并停用**，不再被称为客房或用于安置确认。本轮把前院客房固定在北侧偏左房屋内：`C11` 为敞开门口、`C12` 为屋内到达/本人确认区、`C13` 为退回前庭的自由出口。原底图没有这扇完整客房门和内室，因此样页只叠加独立门框/目的地设计标记，地图使用剖面；正式门、室内地面与前景拆层仍需制作，不能把墙面或空地假装成已完成的房间。原型旧饭账 `(360,550)` 也仅保留历史说明，现行 `C15` 对准灶房台面前的取阅位置。

当前随行样页的下一段严格对应 `follow-visible-leg`：高才脚底 `(708,640)` 沿庭中通路先到 `C11 (645,350)`，随后进入 `C12 (645,285)` 才可能触发本人到达确认；界面写“先到敞开的门口”，不提前写“安置完成”。茶棚方案的设计路线跨两场景，走 `rear-to-road` 与 `court-to-tea`；两处安置点均保留独立自由退出折线，不能因拒绝会面、借貌或招徒失败被重新锁住。

从底到顶绘制：底图地面及建筑远层 → 交互物与门状态 → 按脚底深度排序的人物 → 前景树冠/墙沿 → 场景内名字与目标反馈 → 固定HUD。地面选择环和路径不能压在人脸或门梁上。脚底阴影贴地，不能随人物站姿上下漂浮。

需要拆出的前景层保留树冠、竹叶、低墙与花丛的压边作用。当它们挡住本地角色或当前目标时，只让该前景局部淡到约35%并保留墨色外缘，或显示局部轮廓；不能把整张底图一起透明。未拆分的原底图不能声称已支持局部遮挡淡化。本轮保留完整原图，前景拆层是正式资产制作义务。

庄外短路以左侧茶棚、右上洞外等待空地、南侧院落连接和北向短路出发点组成紧凑连通空间。茶棚后间已固定为安置选项，不再仅称“候选”；正式内容/空间验收仍需证明画出的出口实际可达，且必须同时满足有效同意、真实到达与本人确认。

## 3. 主视图、文字层与避让

精确主图基准为1600×1000 CSS px、DPR 1。所有HUD、名字、图标、计数与按钮独立于背景图，不烘焙进场景。地图可缩放/跟随，文字按屏幕CSS px布局；不能把整页连字一起缩成小图。

| 区域 | 1600×1000基准 | 使用规则 |
| --- | --- | --- |
| 章名/地点 | 左上30px外边距，章名31px、地点15px | 小朱印只标章节，不作为可点动作 |
| 眼下目标 | 左30px、上132px、宽310px；标题21px，正文15–16px | 一项当前问题、最多两项已知准备；不显示全章谜底或其他角色秘密 |
| 同伴 | 右上30px，头像43px | 只计真人席位；示例2/5不包括自主NPC；多人时优先同一行，窄屏可压缩职责文字 |
| 动作卡 | 宽260px，常态靠右；按钮至少46px高 | 只显示已授权对象及合法下一步；导航受理不写操作完成 |
| 本人/停步 | 左下30px | 高才名字、当前职责、独立停步入口；Esc也可停步 |
| 常用入口 | 右下，四个68×77px入口 | 行囊、手记、队伍、回看；图标与文字共同出现 |
| 随行卡 | 下方居中，690px宽，距底138px | 现场保留，卡片不能覆盖真实翠兰、本地角色或前方路径 |
| 对话面板 | 示例左下560px宽 | 地图和交谈对象保持可见，其他真人继续行动；不使用全屏暗幕暂停房间 |
| 行囊/手记/复盘 | 示例右侧390px宽 | 长文在面板内滚动，关闭后回到原场景；不把保管物品和证据陈述混成一类 |

**浮卡避让合同：** 把当前交互目标、正在随行者、本地角色的图像边界与名字区各外扩16 CSS px作为保护区。候选位置先用场景边缘空域，碰撞时移到另一侧或上方空域；仍无空间则收为一行提示/底部短卡，并让镜头把相关人物保持在未遮挡区域。不能把卡片留在人物身体上，不能为了让卡片腾空而移动权威人物。庄外样例已将右侧卡移到上方145px，人物身体、称呼和道路可见。

底部高频控制保留至少44px命中区；焦点轮廓使用独立深青色，不依赖鼠标悬停。超过当前桌面支持范围时，正式实现应按视口重排，而不是把1600宽设计整页等比缩到手机。本轮未作手机真机或完整小屏交互验收。

阅读面板关闭后恢复**当前场景**的卡片；随行中不能重新显示开门前的门撑准备卡。Esc在面板打开时先关闭面板，无面板时对应停步入口；隔离样页仅给操作提示，不提交移动事实。动态打开的行囊、手记等面板按钮也必须给同一设计样页提示，不能呈现点击无响应的假动作。随行中的手记、队伍和复盘使用该阶段已知内容，不重放开门前的未同意/未开门状态。

## 4. 字体、颜色与信息语义

标题与短叙事使用可读的宋体气质；正文优先系统CJK字体，不能依赖外网字体加载才可读。角色名字与短状态可用简洁黑体。正文保持15–17 CSS px，标题21–31px，来源/辅助文字12–14px；长文换行，不截掉拒绝原因或人物选择。

| 用途 | 前景/背景 | 本次纯色对比计算 |
| --- | --- | --- |
| 正文 | `#332c23 / #f8f2e5` | 12.34:1 |
| 次级文字 | `#665c4b / #f8f2e5` | 5.89:1 |
| 已完成/主要强调 | `#365e52 / #f8f2e5` | 6.54:1 |
| 主按钮 | `#fff8e9 / #365e52` | 6.89:1 |
| 待核验/准备 | `#76572e / #f0e9dc` | 5.48:1 |
| 未决/撤回 | `#66566e / #ede8ee` | 5.57:1 |

色值是本轮设计建议，不是从历史72图精确取样。纯色计算通过项目4.5:1正文工作阈值，只证明声明色对，不等于纹理、透明叠加、实际设备或整页无障碍验收。角色保留高才灰青、唐僧赭朱、悟空赭金、猪刚鬣烟紫、翠兰桃粉/蓝灰、木匠赭杏/靛青的身份分工，场景不统一蒙绿。

状态同时使用短文字和形状：`✓`已提交完成，`◇`准备/陈述，`?`未知结果或未核验，`Ⅱ`暂停，`—`撤回。不能只用红绿区别可操作与失败。

## 5. 关键状态合同

完整可见样例在[状态板源码](../design-direction/gaolaozhuang-v1/state-board.html)，图像交付与对外恢复缺口见[设计说明](../design-direction/gaolaozhuang-v1/README.md)。

| 对象 | 必须区分的状态 | 视觉和行为边界 |
| --- | --- | --- |
| 移动/目标操作 | 已受理、行走中、已到达、阻挡、取消、结果未知 | 路径是导航提示；到达后重验才出现“查看/交接”。未知结果查询原操作，不弹出再次交出物品的默认动作 |
| 门与合作 | 铜封未解、单侧准备、双方就位、已锁定、开放 | 同时显示完成位置与剩余准备；左侧锁定就只画左侧锁定。已锁定支撑不因角色离开消失 |
| 距离/权限拒绝 | 太远、当前不可达、对象已变化、尚未获准 | 保留物品；提示下一步但不暴露隐藏对象存在与真实身份 |
| 本人同意 | 提议、待本人回应、已接受、暂停、撤回、改约、到达、确认安置 | 玩家不看到“替翠兰同意”；改地点/带路者重新提议。到达文案用“到了，再问问她是否安心” |
| 乔装与身份 | 相同外貌、不同合法知识、合法揭示、借貌撤回 | 真实翠兰与悟空借貌共用外观语言但保持不同可操作引用；未识破视角不在标签、提示、物主或复盘泄漏悟空；知情者才见“悟空·借貌” |
| 证据/陈述/承诺 | 亲历观察、角色陈述、待比较、已合法送达、承诺未执行、实际完成 | 每条能回查来源；“有人说过”不换成“世界已证实”，说愿意归还不显示已归还 |
| 公共物领回 | 借用标记、宽限内不可领、符合条件可请求、竞争后需刷新 | 私人物品无公共领回入口；对不可见的持有人不泄露身份 |
| 人数不足/恢复 | 等待同伴、恢复确认、旧安排失效、合法结束入口 | 保留准备状态；不自动继续剧情。符合既定宽限/在线确认条件才开放结束 |
| 招徒与分别 | 未决、明确接受/拒绝、安排已知、实际到达、最终结果 | 不能用一行“已加入”代替真实到达；未响应不写“拒绝”，安全分别保留未解决事项 |
| 复盘 | 当时视角、后来合法获知、未完成事项 | 不全知解密；GZ-E01/E02/E03各按真实事件说明，不用统一失败图覆盖获救事实 |
