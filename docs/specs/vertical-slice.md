## 2. 范围与阶段

| 阶段 | 切片内必须形成的行为 | 释放到下一阶段的条件 |
| --- | --- | --- |
| M0 | 明确协议；形成首批所有权、控制权及相关交错的模型、契约和反例证据 | 对应规格、负对照、非真空见证与实现义务可读取，必需检查通过 |
| M1 | 无 AI 的单房间；2–5 人、角色、移动与物品操作、持久事件、重连恢复 | 五位玩家通过独立客户端连续操作 15 分钟；状态与事件回放一致 |
| M2 | 一个测试 NPC 的感知、信念、目标、决策、工具、校验动作闭环 | 权限与故障路径通过；模型输出不能直接改变世界 |
| M3 | 唐僧与悟空的独立感知、分歧、主动交流与计划调整 | 双 AI 不共享越权知识，玩家行动能改变后续计划 |
| M4 | 第一机制关的完整入场、协作、解决／代价／未解决结果与复盘 | 两人和五人体验验收、真实 AI 观察及整体验收通过 |

自动化五客户端检查可提前发现同步错误，须单独标明执行者，不能替代 M1 的五人操作或 M4 的真人体验；真人尚未参与时只释放已满足条件的技术产物，不宣称阶段整体验收完成。M4 需保留原设计“第五名玩家有实际贡献空间”的检验。

不在本切片内：确定六个正式原著篇章、M5 第二机制关、M6 跨关记忆与角色轮换、生产账号运营、支付、完整美术与骨骼动画、生产多地域扩展、赛事发布。八戒／沙僧的最终参与方式继续按总设计保留，不为本试验场景新增固定常驻位。

## 3. 一局的行为合同

具体场景及参数以[玩法闭环](vertical-slice-gameplay.md)为准；它是可替换的机制 fixture，不是正式关卡剧情的定稿。

1. 房主创建房间，玩家进入并获得本关角色、能力与局部信息；开局固定本局角色分工。
2. 玩家在最少场景中调查物件、检视证据、与队友或 NPC 交流；同一条信息可以被相信或怀疑，但不因此改写世界事实。
3. NPC 可自主提出问题、调查或行动，也可拒绝不满足条件的请求。至少有一条通过实际操作推进局面的路径，不把聊天次数当作任务进度。
4. 调查、权限协调、物品交接与实际修复通过服务端接受的动作产生事件；NPC 口头承诺不等于已经执行。
5. 规则根据已提交事实确定终局，并留下玩家操作与 NPC 决策的因果复盘。超时或未解决也是可观察结果；不存在为凑时长强行追加事故的要求。

断线角色按协议进入宽限或受限托管。进入托管不产生第二位全权拥有者，重连接回后旧连接和迟到 AI 意图不能继续控制该角色。无人在线或模型失败也不能让全局状态机失去结束路径。

## 4. 状态归属与模块职责

| 模块 | 负责什么 | 输出与约束 |
| --- | --- | --- |
| Vue 客户端 | 展示授权投影、提交动作、显示待确认与恢复状态 | 不持有世界事实写权限；收到 Receipt 不代表其他客户端已收到广播 |
| Session / Rules | 身份与角色校验、状态机、动作前置条件、终局、确定性 reducer | 同一 Session 的所有世界写入经过统一事务路径 |
| Event / State Store | 已提交事件、状态、Receipt 与发送待办 | 原子性及恢复语义见 M0；缓存和连接状态不替代持久事实 |
| Perception / Memory | 依据合法观察维护角色可知范围、信念及来源 | WORLD FACT、NPC BELIEF、NPC CLAIM 分开；不按 UserId 继承本关外秘密 |
| NPC Orchestrator / Model Gateway | 触发和预算、异步推理、结构化意图、超时降级 | 输出必须再次校验；决策过期、控制权改变或终局时拒绝旧结果 |
| Content / Ending | 关卡人物、资源、证据、权限、目标与终局配置 | 使用通用动作和规则；fixture 的物品与剧情名称不进入通用协议分支 |

上述是逻辑职责，首版保持简单部署和模块隔离。共享协议不依赖具体 HTTP 框架或模型厂商。后端语言仍允许实现者在既定接口与工程边界内选择，并在对应 Ticket 记录动机；改变事务、权限或一致性语义必须返回设计。

## 5. 本轮收敛的关键决定

| 决定 | 原因与代价 | 详细合同 |
| --- | --- | --- |
| 试验机制先于正式篇章选择 | 验证协作与 AI 行为，避免把工程实现绑定固定对白或六套剧情 | 玩法闭环 |
| 权威事务提交后才形成事实 | 接受、持久化、确认和广播分开；接受后掉线仍能找回结果 | M0 协议 |
| 单 Session 顺序号与实体前置条件分工 | 顺序号用于同步，资源条件决定冲突；无关事件不应导致全部旧操作失败 | M0 协议 |
| 控制权携带 epoch 与连接绑定 | 真人交还或取消后必须能拒绝在途旧意图，代价是显式维护控制版本 | M0 协议 |
| 可见事件通过完整区间游标同步 | 允许区间内部分事件不可见；既能判断真正丢包，也不传隐藏内容 | M0 协议 |
| AI 不持有全世界快照或全权限写入 | 防止提示注入直接越权；人格与文本质量仍需真实 AI 观察 | M0 协议、验证计划 |
| 按相关风险分批建模 | M0 聚焦核心所有权／交还，重连与信息投递模型在相关阶段实现前补齐 | 验证计划 |

运行中不得以“模型说成功”“Socket.IO 已重连”“锁在某个进程内”代替相应协议的完成判据。

## 6. 切片整体验收

下表保留原 `full-real` 完成条件；本轮模拟输入下的对应判据见[修订矩阵](vertical-slice-mock.md#5-本轮同候选验证矩阵)。实际运行状态以绑定候选及profile的Issue/PR记录为准，不从规格表推定已通过。玩法和协议的细项编号分别在其文档中维护。

| 验收 ID | 可观察结果 | 检查入口与失败判据 |
| --- | --- | --- |
| INT-AC-01 | 核心协议的字段、状态转换、幂等和控制权与模型义务一致 | M0-AC 全集 / VER-01；缺模型证据、负对照不触发或实现偏离约束即未通过 |
| INT-AC-02 | 五位玩家通过独立客户端连续操作 15 分钟后，各自状态与同一提交水位的服务端对应角色投影一致；服务端回放还原同一权威状态 | VER-02；不要求不同角色看到相同秘密，重复物品、丢事件、分叉或不可恢复游标均失败 |
| INT-AC-03 | 重试、断线、重连、交还、终局和跨房间访问保持身份及信息边界 | VER-03；重复副作用、双控制、私密载荷或旧结果越权均失败 |
| INT-AC-04 | 单 NPC 仅依据合法观察，经校验工具执行；超时、取消和非法 JSON 不阻塞房间 | VER-04；模型直接写事实、无法追踪来源或失败导致停局均失败 |
| INT-AC-05 | 双 NPC 有不同可知信息与目标，可分歧并主动互动；玩家的实际证据／操作影响计划 | VER-05；只有被动问答、全知共享或固定台词触发通关均失败 |
| INT-AC-06 | 两人和五人均完成 fixture 的入场至终局；不同执行路径产生可观察结果，五人有真实贡献 | GP-AC 全集 / VER-06；只靠聊天、一人包办的结构性限制、空角色硬锁均需修正 |
| INT-AC-07 | 接受动作、NPC 决策、事件和结局能关联复盘；日志访问与玩家视图分开 | VER-07；缺少因果标识，或为调试向普通玩家暴露秘密均失败 |

VER-08 汇总同一候选的上述全部检查，不能用分散版本的局部结果代替整体验收。可调参数、样本规模与观测条件在检查前固定并记录；失败后修改参数需要重评相关证据，不通过删断言改变目标。
